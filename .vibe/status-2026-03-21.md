# BuildMax Current Status Summary

Date: 2026-03-21

## Overview

BuildMax is no longer just a local CLI/TUI agent. The repository now contains a multi-entry system with:

- CLI/TUI agent
- HTTP server backend
- scheduler + worker execution pipeline
- Portal web app
- Wails desktop app
- shared React GUI package

The current repository state is stable enough to resume work from directly:

- `git status --short` is clean
- `go test ./...` passes
- recent main-branch work is focused on removing the old `workspace` product model, renaming `chat` to `task`, and completing the Tier 1 conversation flow

## High-Level System Shape

The system currently has four practical layers:

1. Shared agent runtime
2. Server and worker backend
3. Portal and desktop product surfaces
4. Shared GUI component package

The shared agent runtime lives in `internal/app/agentrun` and is reused by:

- CLI/TUI
- worker task execution
- desktop app local chat

This is an important milestone because agent execution is no longer tightly coupled to one UI entrypoint.

## Architecture Status

### Tier 1 / Tier 2 split

The two-tier architecture is no longer just a design idea; it is reflected in code.

- `internal/app/conversation/service.go` is now the Tier 1 orchestration entrypoint
- `internal/conversation/agent.go` is the lower-level conversation loop
- `internal/app/task/service.go` owns task and task_run creation workflows

This means the project has moved toward the intended boundary:

- Tier 1 handles user-facing conversational routing
- Tier 2 handles background execution through tasks and task runs

This aligns well with:

- `design/007-two-tier-agent.md`
- `design/008-backend-architecture-refactor.md`

### User-scoped ownership refactor

The old workspace-centric ownership model has been substantially removed from the product surface.

The active mental model is now:

- user
- conversation
- task
- task_run

This direction is visible in:

- recent commits
- Portal route structure
- server handlers
- storage usage

This aligns with:

- `design/009-user-scoped-ownership-refactor.md`

## Backend Status

The backend path is substantially complete and wired together.

### Server

The server startup flow in `internal/cmd/server/run.go` now wires together:

- MySQL entity store
- blob storage
- quota checker
- Tier 1 conversation services
- scheduler
- worker configuration

The HTTP server in `internal/server/server.go` registers:

- auth routes
- portal routes
- worker routes
- webhook routes
- OpenAPI and Swagger endpoints

### Scheduler and worker

The execution pipeline is complete in shape:

- scheduler polls pending task runs
- claims one run
- starts worker
- worker materializes user files
- worker prepares run-scoped `AGENTS.md`
- worker runs the shared agent runtime
- worker persists result and artifacts
- worker updates server-side run status

Core files:

- `internal/executor/scheduler.go`
- `internal/executor/executor.go`

This is a major project milestone: the execution system is not a stub anymore.

### Conversation flow

Portal conversation handling is live in the backend.

- conversation creation and message routes exist
- streaming SSE support exists
- Tier 1 can either reply directly or spawn background task work

Key file:

- `internal/server/portal/conversation_handlers.go`
