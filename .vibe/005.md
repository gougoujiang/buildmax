# Task 005 - Add Read File Tool

## Goal

Add the first concrete tool for the agent: **read_file**, which reads a local file and returns its contents as text so the LLM can use it in the conversation.

## Context

- **`internal/agent`** defines the **`Tool`** interface: `Name()`, `Description()`, `Parameters() any` (JSON schema), `Execute(ctx context.Context, args map[string]any) (string, error)`. The agent already wires tools via `NewAgent(caller, tools []Tool)` and passes their definitions to the LLM; tool results are sent back as tool-role messages.
- **`internal/llm`** has `ToolDef` (Name, Description, Parameters) and `ToolCall` (ID, Name, Arguments JSON string). The agent unmarshals `Arguments` into `map[string]any` and calls `tool.Execute(ctx, args)`.
- **`cmd/buildmax/main.go`** currently builds the agent with **no tools**: `agent.NewAgent(client, nil)`. Prompt mode runs `a.Process(ctx, prompt)` and prints the reply.
- AGENTS.md calls out "Tools/plugins: Extensible tool calls (e.g. search, run commands, **read files**); interfaces defined in Go." No `internal/tools` (or similar) package exists yet.
- Task docs live in **`tasks/`**; build/test: `./make build`, `./make test`.

## Read file tool (this task)

For this task, "read file" means:

1. **Single tool**: One tool named **`read_file`** that the LLM can call with a file path and receive the file’s text content.
2. **Parameters**: One required string argument (e.g. **`file_path`** or **`path`**). JSON schema for Parameters follows the same style as existing tools (e.g. `map[string]any` with `type`, `properties`, `required`).
3. **Behavior**: Read the file at the given path; return its contents as a string. On error (file not found, permission denied, path is a directory, etc.), return a clear error message (e.g. via `Execute`’s error, which the agent turns into a tool-role message).
4. **Encoding**: Assume UTF-8 text files. Binary files or non-UTF-8 content are out of scope (e.g. return error or best-effort; implementer may document behavior).
5. **Security**: Path must be constrained so the tool cannot read arbitrary system paths (e.g. path traversal). Resolve the path and allow only paths under a single **root** (e.g. current working directory at agent start, or a configurable base path). Reject with an error if the resolved path is outside that root.

We are **not** in this task:

- Adding other tools (search, run command, etc.).
- TUI changes to display tool calls or tool results.
- Configurable tool list or enabling/disabling tools via config.
- Streaming or chunked file reads; reading the whole file into memory is sufficient.

## Deliverables

1. **`internal/tools` package (or equivalent)**
   - **ReadFile tool**: A type that implements **`agent.Tool`**:
     - **Name()**: returns `"read_file"`.
     - **Description()**: short description so the LLM knows when to use it (e.g. read local files to see source code, config, or text).
     - **Parameters()**: JSON schema with one required string property for the file path (e.g. `file_path`). Format consistent with what the LLM API expects (e.g. OpenAI-style schema: `type`, `properties`, `required`).
     - **Execute(ctx, args)**: read the file at `args["file_path"]` (or the chosen key); resolve path relative to a **root** (see below); ensure resolved path is under root; read and return contents as string; on any error return a clear error.
   - **Root directory**: The root for resolving paths must be explicit (e.g. pass a root dir into the tool constructor, or use `os.Getwd()` at construction time). Resolve the given path to an absolute path; if it is outside the root, return an error. Handle path traversal (e.g. `..`) by resolving and then checking prefix.
   - No TUI or Bubble Tea imports in this package; it only depends on `agent` (for the interface), stdlib, and possibly `internal/config` if root comes from config.

2. **Wire-up in main**
   - In **`cmd/buildmax/main.go`**, when creating the agent (e.g. in `runPromptMode`), construct the read_file tool (e.g. with root = current working directory) and pass it in the tools slice: `agent.NewAgent(client, []agent.Tool{readFileTool})`. Same agent construction can be used for TUI path if the app builds the agent in one place; otherwise wire at least for prompt mode so the LLM can use read_file when user asks to read a file.

3. **Tests**
   - **Unit tests** for the read_file tool:
     - Success: create a temp file with known content; call `Execute` with path under root; assert result equals content.
     - Not found: path to non-existent file returns error.
     - Path outside root: path or `..` escaping root returns error (e.g. root = temp dir, request path outside it).
     - Optional: directory path returns error.
   - Tests may use `os.Chdir` and temp dirs; no dependency on real project files.

4. **Dependencies**
   - No new external dependencies; use only stdlib and existing `internal` packages.

## Out of scope (for later)

- Additional tools (search, run command, etc.).
- TUI display of tool calls or tool results.
- Configurable tool set or root path via config file/env.
- Non-UTF-8 or binary file handling beyond a simple, documented choice.
- Maximum file size limit (can be added in a follow-up if needed).

## Acceptance

- [ ] **ReadFile tool** in `internal/tools` (or agreed package) implements `agent.Tool`: `Name()` = `"read_file"`, `Description()` and `Parameters()` (JSON schema with file path argument) and `Execute(ctx, args)` that reads the file and returns content or error.
- [ ] **Path safety**: Resolved path is restricted to a single root (e.g. CWD or constructor argument); paths outside root or path traversal result in an error.
- [ ] **Wire-up**: `cmd/buildmax/main.go` creates the read_file tool and passes it to `agent.NewAgent(client, tools)` so prompt mode can use it (e.g. user asks "read foo.go" and LLM calls read_file).
- [ ] **Unit tests**: (1) Execute with valid path under root returns file contents; (2) non-existent file returns error; (3) path outside root (or escaping via `..`) returns error.
- [ ] **Build and test**: `./make build` and `./make test` pass; no new dependencies in `go.mod` beyond existing ones.
