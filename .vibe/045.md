# Task 045 - Allow upload directory

## Goal

Allow users to upload an entire directory (with its nested structure preserved) to a workspace, in addition to the existing individual-file upload.

## Context

- The upload endpoint `POST /api/workspaces/{workspace_id}/upload` already accepts `multipart/form-data` with a `files` field and saves files **flat** to the workspace root (`internal/server/upload.go`). It uses `filepath.Base(fh.Filename)` which strips any directory info.
- The portal Explore page (`portal/src/pages/ExplorePage.tsx`) has an "Upload Files" button with `<input type="file" multiple>` — files only, no directory selection.
- The portal API function `uploadFiles()` in `portal/src/lib/api.ts` builds a `FormData` with files under field name `files`.
- The file tree endpoint (`GET /api/workspaces/{workspace_id}/files`) already supports nested directories — `buildTree` in `internal/server/files.go` recursively walks the workspace directory.
- Path safety is available via `util.Workspace.ResolvePath` which rejects path-traversal attempts.

## Directory upload (this task)

For this task, "upload directory" means:

1. The user clicks an "Upload Folder" button in the portal Explore page
2. A folder picker opens (using the HTML `webkitdirectory` attribute on `<input type="file">`)
3. When the user selects a folder (e.g. `sales/`), the browser enumerates all files recursively and exposes their relative paths via `File.webkitRelativePath` (e.g. `sales/2024/sales.2024.csv`)
4. The portal sends these files **with their relative paths** to the upload endpoint
5. The backend creates the necessary subdirectories and saves each file at its relative path within the workspace

**Example**: user selects folder `sales` containing:
```
sales/
  2024/
    sales.2024.csv
  2025/
    sales.2025.csv
```
Result on disk under `{workspace_dir}/`:
```
sales/
  2024/
    sales.2024.csv
  2025/
    sales.2025.csv
```

We are **not** yet implementing:

- Drag-and-drop folder upload
- Upload progress bars or per-file progress
- Server-side file size or count limits beyond the existing 10-file cap (we raise the cap for directory uploads — see below)
- Zip/archive upload and extraction

## Deliverables

1. **`internal/server/upload.go`** — extend existing handler
   - Accept an optional `paths` multipart form field (one value per file, in the same order as `files`)
   - When `paths` is present, use each path as the relative destination within the workspace instead of `filepath.Base(fh.Filename)`
   - Validate each path with `util.Workspace.ResolvePath` to prevent traversal attacks
   - Create intermediate subdirectories (`os.MkdirAll`) as needed
   - Raise the file limit: when `paths` is present (directory upload), allow up to 200 files; keep existing 10-file limit for regular uploads (no `paths` field)
   - Response stays the same: `{ "uploaded": ["sales/2024/sales.2024.csv", ...] }` — paths reflect the relative location

2. **`portal/src/lib/api.ts`** — extend `uploadFiles`
   - Add an optional `paths` parameter: `uploadFiles(workspaceId, files, token, paths?)`
   - When `paths` is provided, append each path as a `paths` field in the FormData (one per file, same order)

3. **`portal/src/pages/ExplorePage.tsx`** — add folder upload button
   - Add an "Upload Folder" button next to the existing "Upload Files" button
   - Use a second hidden `<input type="file">` with the `webkitdirectory` attribute (and `directory` for Firefox)
   - On folder selection, collect all files' `webkitRelativePath` values as the `paths` array
   - Remove the 10-file client-side check for directory uploads (server handles the 200-file limit)
   - Call `uploadFiles(workspaceId, files, token, paths)` and refresh the tree on success
   - Show the same upload status messaging (success count / error)

## Out of scope (for later)

- Drag-and-drop upload (both files and folders)
- Upload progress indicators (per-file or overall)
- Server-side file type or size restrictions
- Zip/archive upload and server-side extraction
- Duplicate/conflict resolution UI (overwrite is acceptable for now)
- Empty folder creation (browsers skip empty folders in `webkitdirectory`)

## Acceptance

- [ ] Selecting a folder via "Upload Folder" uploads all files recursively; files appear in the workspace at the correct nested paths
- [ ] The existing "Upload Files" button continues to work as before (flat upload, 10-file limit)
- [ ] Directory upload with up to 200 files succeeds; 201+ files returns 400
- [ ] Path traversal attempts in `paths` field (e.g. `../../etc/passwd`) are rejected with 400
- [ ] After folder upload, the file tree refreshes and shows the uploaded directory structure
