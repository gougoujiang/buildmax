# Task 106 - Token expiry check and login metadata

## Goal

Add client-side JWT expiry checking so stale tokens are detected before hitting the server, and record `last_login_at` / `last_login_platform` in the user table on each successful login.

## Context

- JWT tokens are already issued with a 24h `exp` claim (`internal/server/auth/login.go`, `jwtExpiry = 24 * time.Hour`).
- Server-side validation already rejects expired tokens via `jwt.ParseWithClaims` in `internal/server/portal/auth.go`.
- Client-side `Credentials.IsValid()` (`internal/auth/credentials.go`) only checks `Token != ""` — no expiry check. CLI, desktop, and portal all rely on this or on 401 responses.
- The `User` model (`internal/storage/entity/models.go`) has no login-tracking fields.
- `UserStore` interface (`internal/storage/entity/interfaces.go`) has `UserByEmail`, `GetUser`, `CreateUser` — no update method.
- Login entry points: server `loginHandler` (POST `/api/login`), CLI `interactiveLogin`, desktop `DoLogin`, portal `AuthContext.login`. All go through the same server endpoint.
- The portal stores the token in `localStorage` and handles 401 via a `buildmax:unauthorized` event.

## Key concepts (this task)

For this task, "token expiry check" means:

1. Parse the JWT `exp` claim from the token on the client side (base64 decode the payload segment — no signature verification needed).
2. `IsValid()` returns false when the token is expired or unparseable.
3. CLI and desktop callers that check `IsValid()` will detect stale tokens before making API calls.

For this task, "login metadata" means:

1. Add `last_login_at` (unix timestamp) and `last_login_platform` (string: `"cli"`, `"desktop"`, `"portal"`) columns to the `user` table.
2. Update these fields on each successful login in the server login handler.
3. The platform is passed by the client as a new `platform` field in the `POST /api/login` request body.

We are **not** yet implementing:

- Token refresh (issuing a new token before the current one expires).
- OS keychain integration for credential storage.
- Multi-server credential support.
- Portal-side proactive expiry detection (portal already handles 401 gracefully).

## Deliverables

1. **`internal/auth/credentials.go` — client-side expiry check**
   - **`IsValid()`**: Parse the JWT payload (base64url decode middle segment), extract `exp`, return false if `exp` is in the past or token is malformed. No external JWT dependency — just `encoding/base64` + `encoding/json`.
   - No signature verification (clients don't have the server secret).

2. **`internal/auth/client.go` — pass platform in login request**
   - **`Login` method**: Add a `platform` parameter (`string`). Include it in the request body as `"platform"`.
   - All callers (CLI, desktop) pass their platform string.

3. **`internal/storage/entity/models.go` — User model update**
   - **`User` struct**: Add `LastLoginAt *int64` (`gorm:"" json:"last_login_at,omitempty"`) and `LastLoginPlatform *string` (`gorm:"type:varchar(32)" json:"last_login_platform,omitempty"`).
   - GORM auto-migration picks up the new columns.

4. **`internal/storage/entity/interfaces.go` + `user.go` — update user on login**
   - **`UserStore` interface**: Add `UpdateLoginMeta(ctx, userID string, loginAt int64, platform string) error`.
   - **`Store.UpdateLoginMeta`**: GORM update of `last_login_at` and `last_login_platform` by `user_id`.

5. **`internal/server/auth/login.go` — record login metadata**
   - **`LoginRequest`**: Add `Platform string` field (`json:"platform"`).
   - **`loginHandler`**: After successful OTP check, call `UserStore.UpdateLoginMeta(userID, now.Unix(), req.Platform)`. If platform is empty, default to `"unknown"`.

6. **CLI and desktop callers — pass platform**
   - **`internal/cmd/cli/login.go`**: Pass `"cli"` to `client.Login(ctx, email, otp, "cli")`.
   - **`internal/cmd/desktop/app.go`**: Pass `"desktop"` to `client.Login(ctx, email, otp, "desktop")`.
   - **Portal** (`portal/src/features/auth/api.ts`): Add `platform: "portal"` to the login request body.

7. **Tests**
   - **`internal/auth/auth_test.go`**: Add tests for `IsValid()` with valid unexpired JWT, expired JWT, malformed token, and empty token.
   - **`internal/storage/entity/store_test.go`**: Add test for `UpdateLoginMeta`.

## Out of scope (for later)

- Token refresh / silent re-authentication
- OS keychain storage (macOS Keychain, Windows Credential Manager)
- Multi-server credential support
- Portal proactive expiry check (already handles 401; could add `setTimeout`-based check later)
- Configurable JWT expiry duration (currently hardcoded 24h)

## Acceptance

- [ ] `Credentials.IsValid()` returns false for an expired JWT (exp in the past)
- [ ] `Credentials.IsValid()` returns true for a valid JWT with exp in the future
- [ ] `Credentials.IsValid()` returns false for empty token or malformed token (non-JWT string)
- [ ] `User` model has `last_login_at` and `last_login_platform` columns
- [ ] `UpdateLoginMeta` updates user row with timestamp and platform string
- [ ] Server login handler calls `UpdateLoginMeta` on successful login
- [ ] CLI login passes `"cli"` as platform
- [ ] Desktop login passes `"desktop"` as platform
- [ ] Portal login passes `"portal"` as platform
- [ ] Existing tests pass; new tests cover expiry logic and `UpdateLoginMeta`
