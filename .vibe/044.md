# Task 044: Workspace file explore

## Goal

Replace the mock data in the portal's Explore page with real workspace files by adding two backend API endpoints (list directory tree, read file content) and wiring the portal to call them.

## Context

- The Explore page (`portal/src/pages/ExplorePage.tsx`) already has a polished three-panel UI: folder tree (left), file list (center), file viewer (right). It currently uses hardcoded mock data from `portal/src/data/mockExplore.ts`.
- Workspace files live on disk at `{WorkspacesDir()}/{workspace_id}/` (default `~/.buildmax/workspaces/{id}/`).
- The `internal/util.Workspace` type already provides `ResolvePath` with path-traversal protection.
- The upload endpoint (`POST /api/workspaces/{workspace_id}/upload`) already writes files into the workspace directory.
- The `ExploreNode` TypeScript type already models folders and files:
  ```
  { id, name, type: "folder", children: ExploreNode[] }
  { id, name, type: "file", content: string }
  ```

## In scope

1. **Backend — directory tree endpoint**
   - `GET /api/workspaces/{workspace_id}/files`
   - Returns the full directory tree of the workspace as a nested JSON structure matching the `ExploreNode` shape (folders with children, files without content).
   - Auth required (JWT); workspace ownership check.
   - Node `id` = relative path from workspace root (e.g. `"docs/readme.md"`); root id = `"."`.
   - Files include `name` and `type: "file"` but **no content** (to keep the tree response lightweight).

2. **Backend — file content endpoint**
   - `GET /api/workspaces/{workspace_id}/files/{path...}`
   - `path...` is the relative file path (e.g. `docs/readme.md`).
   - Returns the file content as plain text (`Content-Type: text/plain`).
   - Auth required; workspace ownership check; path-traversal protection via `util.Workspace.ResolvePath`.
   - Returns 404 if file does not exist or is a directory.

3. **Portal — API client functions**
   - `getFileTree(workspaceId, token)` → calls tree endpoint, returns `ExploreNode`.
   - `getFileContent(workspaceId, filePath, token)` → calls file content endpoint, returns string.

4. **Portal — ExplorePage wiring**
   - On mount (and after upload), fetch the file tree from the API instead of using `MOCK_EXPLORE_TREE`.
   - When a file is selected, fetch its content via the file content endpoint (lazy load, not bundled in the tree).
   - Show loading states while fetching.
   - The `ExploreNode` type for files in the tree will have `content: ""` (empty) until the file is selected and fetched.

5. **Refresh after upload**
   - After a successful upload, re-fetch the file tree so newly uploaded files appear immediately.

## Out of scope

- File creation, deletion, renaming, or editing from the portal (future tasks).
- Subdirectory upload (current upload is flat to workspace root).
- Pagination or streaming for very large directories (simple recursive walk is sufficient for now).
- Binary file handling / download endpoint (future).
- File size limits or truncation for the content endpoint (handle later if needed).

## API design

### `GET /api/workspaces/{workspace_id}/files`

**Response** (`200 OK`, `application/json`):
```json
{
  "id": ".",
  "name": "Workspace",
  "type": "folder",
  "children": [
    {
      "id": "docs",
      "name": "docs",
      "type": "folder",
      "children": [
        { "id": "docs/readme.md", "name": "readme.md", "type": "file" }
      ]
    },
    { "id": "notes.txt", "name": "notes.txt", "type": "file" }
  ]
}
```

- Files in the tree do **not** include `content` (omitted or empty string).
- Sorted: folders first, then files, both alphabetically.

### `GET /api/workspaces/{workspace_id}/files/{path...}`

**Response** (`200 OK`, `text/plain`):
```
Raw file content as plain text.
```

**Errors**:
- `404`: file not found or is a directory.
- `400`: path traversal detected.
- `401` / `403`: auth / ownership failure.

## Acceptance criteria

- [ ] `GET /api/workspaces/{workspace_id}/files` returns the real directory tree for the workspace; empty workspace returns a root folder with no children.
- [ ] `GET /api/workspaces/{workspace_id}/files/{path...}` returns the file content as plain text; returns 404 for missing files or directories.
- [ ] Path traversal attempts (e.g. `../../../etc/passwd`) are rejected with 400.
- [ ] Both endpoints require JWT auth and workspace ownership.
- [ ] Portal Explore page loads the real file tree on mount.
- [ ] Clicking a file in the portal fetches and displays its content.
- [ ] After uploading files, the tree refreshes to show new files.
