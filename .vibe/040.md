# Task 040: Entity id refactor

## Goal

Standardize entity identity across the persistence layer: use internal integer primary keys for DB use only, public ULID columns for API and references, and singular table names. Document table naming as a project rule in AGENTS.md.

## Context

- **Current**: `internal/store` uses GORM with MySQL. User, Workspace, and Project use a single varchar(36) UUID as primary key. Task has an internal `ID` (uint) and public `TaskID` (UUID). Tables are plural: `users`, `workspaces`, `projects`, `tasks`.
- **API**: JWT `sub` and login response use user id; workspace/project/task APIs use path params and response fields `id`, `owner_user_id`, `workspace_id`, `project_id`. API contract (snake_case, field names) remains; only the format of ids changes (UUID → ULID) and table names become singular.
- **Convention**: Persisted data uses snake_case (AGENTS.md §6.1). This task adds a rule: database table names use **singular** (e.g. `user`, `workspace`, `project`, `task`).

## In scope

1. **AGENTS.md**
   - Add a "Database table naming" rule: use singular table names (e.g. `user`, not `users`); one row per entity type.

2. **User**
   - Add column: `id` (integer, auto-increment, primary key, internal only).
   - Add column: `user_id` (ULID, unique, not null). Used in API and JWT.
   - Keep: `email`, `name`, `created_at`.
   - Table name: `user` (singular).
   - Store and server: generate/lookup by `user_id`; JWT `sub` and login response `user.id` are `user_id`.

3. **Workspace**
   - Add column: `id` (integer, auto-increment, primary key, internal only).
   - Rename current `id` to `workspace_id` (ULID, unique, not null). Used in API and paths.
   - `owner_user_id`: keep name; reference `user.user_id` (not the internal `user.id`).
   - Table name: `workspace` (singular).
   - Store and server: create/list/lookup by `workspace_id` and `owner_user_id`; config dirs and API use `workspace_id`.

4. **Project**
   - Add column: `id` (integer, auto-increment, primary key, internal only).
   - Rename current `id` to `project_id` (ULID, unique, not null).
   - `workspace_id`: reference `workspace.workspace_id`.
   - Table name: `project` (singular).
   - Store: GetProject/list/create by `project_id` and `workspace_id`; API continues to use `id` / `project_id` in paths and body.

5. **Task**
   - Change `task_id` from UUID to ULID (column type and generation).
   - Table name: `task` (singular).
   - API response `id` remains the task’s public id (task_id); no change to API shape.

6. **Migrations and compatibility**
   - Prefer GORM AutoMigrate with explicit renames/adds where needed, or document a one-time migration path (e.g. add columns, backfill ULIDs, switch primary/unique, drop old columns) for existing data. If the project has no production DB yet, additive schema changes plus switching to ULID for new rows may be enough; clarify in design.

7. **ULID**
   - Use a single, project-wide ULID dependency (e.g. `github.com/oklog/ulid/v2`). Generate ULIDs in Go when creating User, Workspace, Project, Task; store as string (e.g. varchar(26)).

## Out of scope

- Changing API path or query parameter names (`workspace_id`, `project_id`, etc.).
- Portal or other clients beyond ensuring they still work with ULID strings.
- New endpoints or new entities.
- Changing session or other non-DB id formats.

## Deliverables

- AGENTS.md updated with database table naming rule (§6.3 or under §6).
- Store models and TableName() updated: User, Workspace, Project, Task (ids, ULID, singular table names).
- Store methods and server handlers updated to use `user_id`, `workspace_id`, `project_id`, and `task_id` (ULID) consistently; JWT and responses use public ids.
- Migration path documented or implemented so existing DBs (if any) can be migrated; new installs work with the new schema.
- All existing tests updated and passing; `go build ./...` and `go test ./...` pass.
