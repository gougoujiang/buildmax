# Task 072: Remove project related in backend

## Goal

Remove the project concept from the backend so that tasks and artifacts are owned by workspace only; all project-related APIs, storage, types, and request/response fields are removed.

## Context

- **Current state**: Tasks belong to a workspace and optionally to a project (`task.project_id`). Projects are CRUD via `GET/POST /api/workspaces/{id}/projects`. Task list/create and artifact list accept optional `project_id` filter or body field. The entity layer has `Project` model, `ProjectStore`, and `project` table; `Task` and `ArtifactWithTask` expose `project_id`.
- **Where this fits**: `internal/server` (handlers, routes, OpenAPI), `internal/storage/entity` (store, interfaces, migrations), `internal/model` (domain types), `internal/workerapi` (worker response types), `internal/servercmd` (server config).
- **Conventions**: AGENTS.md (singular table names, snake_case JSON); existing patterns for removing an entity (drop routes, store methods, model, then adjust callers).

## Scope

**In scope**

- Remove project HTTP API: `GET/POST /api/workspaces/{workspace_id}/projects` and handlers.
- Remove project from task and artifact APIs: no `project_id` in query or body for list/create tasks or list artifacts; remove `resolveProjectForWorkspace` and all project validation.
- Remove project from storage: delete `ProjectStore` interface and its implementation (`internal/storage/entity/project.go`), remove `Project` from AutoMigrate and from `internal/model`.
- Remove `project_id` from task and artifact surfaces: `Task.ProjectID` and `ArtifactWithTask.ProjectID` removed from model and from DB usage (task list/create, artifact list, worker API response). Store method signatures updated to drop `projectID *string` where present.
- Server config: stop passing `ProjectStore` into the server (e.g. `servercmd` sets it to nil or the field is removed).
- OpenAPI: remove `/projects` paths and all `project_id` parameters/responses from tasks and artifacts.
- Tests: remove or adjust project-related tests (e.g. `projects_test.go`, project cases in `tasks_test.go` and `artifacts_test.go`, mock project store in `helpers_test.go`).
- Database: no longer use `project` table; no longer read/write `task.project_id`. Migration approach (e.g. drop column/table or leave schema and ignore) is decided in design.

**Out of scope**

- Portal/frontend code changes (see "Portal" section below for what a follow-up task would do).
- Changes to executor, worker binary, or tools beyond removing `project_id` from worker API response types.

### Portal (current state and follow-up)

Rescan (portal code) shows:

- **UI already has no project**: Routes are workspace, newChat, chat, chats, explore, agents (no project route or project selector). `WorkspaceHome` and `createTask` use `{ input }` only; no `project_id` is sent. Sidebar shows workspace + chats + agents. The project page is removed (CSS comment: "Page: Project (removed) — legacy .page-project__* kept for reference").
- **Data layer still references project**: So after the backend stops returning/supporting `project_id`, a **follow-up task** should update the portal for consistency and to avoid passing obsolete params:
  - **portal/src/lib/types.ts** — Remove `Project` interface; remove `projectId?` from `Task` and `Artifact`.
  - **portal/src/lib/api/types.ts** — Remove `ApiProject`; remove `project_id` from `ApiTask` and `ApiArtifact`.
  - **portal/src/lib/api/index.ts** — Remove `projectId` param from `getTasks`; remove `project_id` from `createTask` body; remove `projectId` from `getArtifacts` options. (No `getProjects`/`createProject` calls exist.)
  - **portal/src/lib/api/mappers.ts** — Stop mapping `project_id` to `projectId` in `apiTaskToTask` and `apiArtifactToArtifact`.
  - **portal/src/hooks/useArtifacts.ts** — Remove `projectId` from `UseArtifactsOptions` and from the fetch query.
  - **portal/src/index.css** (optional) — Remove or keep legacy `.page-project__*` and `.sidebar__project-*` as desired.
- This task (072) is backend-only; the portal will continue to work (it does not call `/projects` or send `project_id` from the UI), but types and API layer should be updated in a follow-up so responses and request shapes match the new backend.

## Deliverables

1. **internal/model**
   - Remove `Project` struct and `Project.TableName()`.
   - Remove `ProjectID` from `Task` and from `ArtifactWithTask`.

2. **internal/storage/entity**
   - Remove `ProjectStore` interface and `project.go` (GetProject, ListProjectsByWorkspace, CreateProject).
   - Remove `Project` from `Store` AutoMigrate and from `types.go` if it only re-exports model.Project.
   - Change `TaskStore`: `ListTasksByWorkspace`, `ListTasksByWorkspacePaginated`, and `CreateTask` no longer take `projectID *string`; implementation filters/create logic no longer use project.
   - Change `ArtifactStore.ListArtifactsByWorkspace` to drop `projectID *string`; implementation no longer filters by project_id.
   - Update `Store` so it no longer implements `ProjectStore` (remove methods).

3. **internal/server**
   - Remove `projects.go` and routes `GET/POST /api/workspaces/{workspace_id}/projects`.
   - Remove `ProjectStore` from server `Config` and from all handlers that use it; remove `resolveProjectForWorkspace`.
   - Tasks: list and create handlers no longer accept or return `project_id`; request/response types and OpenAPI updated.
   - Artifacts: list handler no longer accepts `project_id` query param; response type and OpenAPI updated.
   - Worker handler: response type for task no longer includes `project_id`.
   - OpenAPI (`static/openapi.json`): remove projects paths and all `project_id` references for tasks/artifacts.
   - Tests: remove `projects_test.go`; update `tasks_test.go`, `artifacts_test.go` (if any), and `helpers_test.go` to drop project store and project-related cases.

4. **internal/workerapi**
   - Remove `ProjectID` from `TaskRunTask` (worker GET response).

5. **internal/servercmd**
   - Stop setting `ProjectStore` on server config (remove field or set nil).

6. **Database**
   - Design doc will specify how to handle existing `project` table and `task.project_id` column (e.g. migration to drop, or leave and ignore).

## Acceptance

- [ ] `go build ./...` and `go test ./...` pass.
- [ ] No references to `ProjectStore`, `GetProject`, `ListProjectsByWorkspace`, `CreateProject`, or `resolveProjectForWorkspace` in server or entity packages.
- [ ] No `project_id` in task or artifact API request/response or OpenAPI.
- [ ] No `GET/POST .../projects` routes or handlers.
- [ ] Task and artifact list/create use only workspace (and optional task_id for artifacts); store interfaces and implementations match.
- [ ] Worker API task payload no longer includes `project_id`.
