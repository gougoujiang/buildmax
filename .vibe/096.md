# Task 096: Agent loop refactor

## Goal

Use a **single tool type and shared tool-definition/tool-call handling** so the CLI agent (`internal/agent`) and the Tier 1 conversation agent (`internal/conversation`) share the same data structures and helpers. Move the two tools currently defined in `internal/conversation` into `internal/tools` for reuse and consistency.

## Context

- **Two agent loops today:** (1) `internal/agent` — used by CLI/TUI; (2) `internal/conversation` — used by Tier 1 (conversation API). Both call the LLM with tools and execute tool calls, but each defines its own `Tool` interface and its own conversion from tools to `llm.ToolDef` / execution of `llm.ToolCall`.
- **Existing types:** `internal/llm` has `ToolDef` and `ToolCall` (API shape). `internal/agent` has `Tool` (Name, Description, Parameters, Execute) and builds `[]llm.ToolDef` inside `NewAgent`; it executes tool calls in `processOneToolCall`. `internal/conversation` has a duplicate `Tool` interface, local `toolDefs()` and `executeTool()`, and two tools: `GetCurrentDate` and `start_chat` (via `NewStartChatTool`).
- **internal/tools:** Already holds CLI tools (ReadFile, WriteFile, Bash, etc.) that implement `agent.Tool`. Some files (e.g. webfetch, task) import `internal/agent` for `LLMCaller`. No import from `internal/agent` to `internal/tools` today.
- **Dependency constraint:** Putting the shared `Tool` interface in `internal/tools` would introduce a cycle (agent would need `tools.Tool`, and tools already depends on agent for `LLMCaller` in webfetch/task). So the single `Tool` interface remains in `internal/agent`; both loops use `agent.Tool` and shared helpers.

## Scope

### In scope

1. **Single Tool interface** — Keep `agent.Tool` as the one definition; conversation loop will use `agent.Tool` instead of its own `Tool` type.
2. **Shared helpers in agent** — Export from `internal/agent`: (a) `ToolDefs(tools []Tool) []llm.ToolDef` so both loops can build LLM tool definitions the same way; (b) a function to execute one tool call (parse `llm.ToolCall` args, call `tool.Execute`, return result string), e.g. `ExecuteTool(ctx, tool Tool, tc llm.ToolCall) string`, so conversation can reuse it instead of its local `executeTool`.
3. **Conversation loop refactor** — Update `internal/conversation` to use `agent.Tool`, `agent.ToolDefs`, and the new `agent.ExecuteTool` (or equivalent); remove `conversation.Tool`, `toolDefs()`, and the local `executeTool()`.
4. **Move conversation tools to internal/tools** — Move `GetCurrentDate` and the start_chat tool (including `StartChatFunc` and `NewStartChatTool`) from `internal/conversation/tools.go` to `internal/tools`. Both will implement `agent.Tool`. Provide in `internal/tools` the conversation-specific builders, e.g. `DefaultConversationTools() []agent.Tool` and `BuildConversationToolsWithStartChat(workspaceID, userID string, fn StartChatFunc) []agent.Tool`, so the server can keep calling a single place to get the tool list.
5. **Wire server and tests** — Update `internal/server` (e.g. `conversation_tools.go`) to obtain `[]agent.Tool` from `internal/tools` (e.g. `tools.BuildConversationToolsWithStartChat(...)`). Ensure existing conversation and agent tests still pass; add or adjust tests as needed for the new exports and moved tools.

### Out of scope

- Merging the two agent loops into one shared core (we keep two separate loops; only tool types and helpers are shared).
- Adding new tools or changing tool behavior beyond the refactor.
- Moving CLI-specific tools (readfile, bash, etc.) or changing how the CLI agent is wired.

## Deliverables

1. **internal/agent**
  - Export `ToolDefs(tools []Tool) []llm.ToolDef` (logic already in `NewAgent`; extract and call from `NewAgent`).
  - Export `ExecuteTool(ctx context.Context, tool Tool, tc llm.ToolCall) string` (logic from `processOneToolCall`; no session append — just parse args, call `tool.Execute`, return result or error string). `processOneToolCall` should use `ExecuteTool` and then append the result to the session.
  - No change to the `Tool` interface or to `LLMCaller`.
2. **internal/conversation**
  - Remove local `Tool` interface, `toolDefs()`, and `executeTool()`.
  - Use `agent.Tool` for the tools parameter of `RunLoop` (and streaming path if present). Use `agent.ToolDefs(tools)` and `agent.ExecuteTool(ctx, tool, tc)` (or the chosen names) in the loop.
  - Remove the file (or in-file definitions) that define `GetCurrentDate` and `start_chat` / `StartChatFunc` / `NewStartChatTool` / `DefaultTools` / `BuildToolsWithStartChat` once moved to tools.
3. **internal/tools**
  - Add `get_current_date.go`: `GetCurrentDate` struct implementing `agent.Tool` (same behavior as today).
  - Add `start_chat.go` (or same file): `StartChatFunc` type, `startChatTool` (or exported name) implementing `agent.Tool`, `NewStartChatTool(workspaceID, userID string, fn StartChatFunc) agent.Tool`, `DefaultConversationTools() []agent.Tool`, `BuildConversationToolsWithStartChat(workspaceID, userID string, fn StartChatFunc) []agent.Tool`. These replace conversation’s `DefaultTools` and `BuildToolsWithStartChat`.
  - Ensure both new tools only depend on `agent` (for `Tool`) and standard library; `StartChatFunc` stays a function type in tools.
4. **internal/server**
  - Update conversation tool wiring to use `tools.BuildConversationToolsWithStartChat(...)` and pass `[]agent.Tool` into the conversation layer (e.g. `RunLoop`). Adjust types so handlers receive `[]agent.Tool` where they currently use `[]conversation.Tool`.
5. **Tests**
  - Unit tests for `agent.ToolDefs` and `agent.ExecuteTool` (e.g. in `internal/agent`).
  - Move or add tests for `GetCurrentDate` and start_chat in `internal/tools` so behavior is covered there.
  - Conversation and server tests: update imports and tool construction; ensure `go build ./...` and `go test ./...` pass.

## Acceptance

- `agent.ToolDefs(tools []Tool) []llm.ToolDef` is exported and used by both `internal/agent` and `internal/conversation`.
- `agent.ExecuteTool(ctx, tool, tc)` (or equivalent) is exported and used by both agent’s `processOneToolCall` and conversation’s loop.
- `internal/conversation` no longer defines its own `Tool` interface or local `toolDefs`/`executeTool`; it uses `agent.Tool` and the exported helpers.
- `GetCurrentDate` and start_chat (with `StartChatFunc`, `NewStartChatTool`, and the default/builder functions) live in `internal/tools` and implement `agent.Tool`.
- Server obtains conversation tools from `internal/tools` (e.g. `BuildConversationToolsWithStartChat`) and passes `[]agent.Tool` to the conversation layer.
- `go build ./...` and `go test ./...` pass; existing conversation and agent behavior is preserved.
