# Task 083: Agent detail page (edit and delete agent)

## Goal

Enable users to edit and delete existing workspace agents from the Portal: clicking an agent card opens an edit dialog where name, description, and instructions can be updated and saved; users can also delete an agent (from the edit dialog or the list).

## Context

- **Agents today**: Workspace-scoped entities (personas / task templates). Backend: `internal/model` `Agent`, `internal/storage/entity` `AgentStore` (ListAgentsByWorkspace, GetAgent, CreateAgent), HTTP: GET/POST list/create, GET one at `/api/workspaces/{id}/agents` and `.../agents/{agent_id}`. No update API or edit UI.
- **Portal**: `AgentList.tsx` shows a grid of agent cards (name, description, instructions); "Create agent" opens `CreateAgentModal` (name, description, instructions). Cards are not clickable. API: `getAgents`, `createAgent`, `apiAgentToAgent` in `portal/src/lib/api`; no `updateAgent`.
- **Conventions**: AGENTS.md (snake_case for persisted/API JSON, singular table names). OpenAPI in `internal/server/static/openapi.json` documents agent routes.

## "Agent detail" (this task)

For this task, "agent detail" means **edit and delete in place** from the Agents list:

1. User clicks an agent card on the Agents page.
2. An edit dialog opens with the agent’s current name, description, and instructions.
3. User can save changes (backend PATCH); list reflects the update.
4. User can delete the agent (e.g. "Delete" in the edit dialog); backend DELETE removes the agent; list updates and modal closes.

We are **not** implementing:

- A dedicated full-page agent detail route (e.g. `#workspaceId/agents/agentId`).
- Agent usage history or linking chats/tasks to agents in this task.

## Deliverables

1. **Backend – update agent**
   - **AgentStore**: Add `UpdateAgent(ctx, agentID, workspaceID, name, description, instructions) (*Agent, error)` in `internal/storage/entity` (interface in `interfaces.go`, implementation in `agent.go`). Same semantics as create: only name/description/instructions; workspace ownership implied by caller.
   - **HTTP**: Add `PATCH /api/workspaces/{workspace_id}/agents/{agent_id}` with JSON body `{ name?, description?, instructions? }`; require name if present (non-empty). Auth and workspace check same as GET agent. Return updated agent (same shape as GET). Update OpenAPI spec.

2. **Backend – delete agent**
   - **AgentStore**: Add `DeleteAgent(ctx, agentID, workspaceID) error` in `internal/storage/entity` (interface + implementation in agent.go). Only delete if agent exists and belongs to workspace.
   - **HTTP**: Add `DELETE /api/workspaces/{workspace_id}/agents/{agent_id}`; auth and workspace check same as GET agent. Return 204 No Content on success. Update OpenAPI spec.

3. **Portal – API client**
   - **Artifact**: In `portal/src/lib/api`, add `updateAgent(workspaceId, agentId, body, token)` (PATCH) and `deleteAgent(workspaceId, agentId, token)` (DELETE).

4. **Portal – edit dialog and list behavior**
   - **Artifact**: Edit dialog that shows current name, description, instructions; on save call `updateAgent` and refresh the list (or update the single item in state). Reuse the same field set as CreateAgentModal (name, description, instructions); dialog can be a new component (e.g. `EditAgentModal`) or an extended create modal that accepts optional initial values.
   - **Artifact**: In `AgentList.tsx`, make each agent card clickable (or add an explicit "Edit" control) so that clicking opens the edit dialog for that agent.
   - **Artifact**: Edit dialog includes a "Delete" action (e.g. button); on confirm, call `deleteAgent`, remove agent from list, close modal.

5. **Tests**
   - Backend: unit or handler tests for PATCH agent (success, 400, 404) and DELETE agent (success, 404).
   - No new frontend test required unless the task/design explicitly adds it.

## Out of scope (for later)

- Dedicated agent detail page (separate route and full-page view).
- Agent usage history or linking chats/tasks to agents in this task.

## Acceptance

- [ ] `AgentStore.UpdateAgent` and `AgentStore.DeleteAgent` exist and are implemented; PATCH and DELETE `/api/workspaces/{id}/agents/{agent_id}` are implemented with auth and workspace checks; OpenAPI updated.
- [ ] Portal has `updateAgent` and `deleteAgent` in the API client and an edit dialog (prefilled with current agent) that can save via PATCH and delete via DELETE.
- [ ] From the Agents list, user can click an agent card to open the edit dialog, change name/description/instructions and save, or delete the agent; list updates accordingly.
- [ ] Backend test(s) cover PATCH agent (success and at least one error) and DELETE agent (success and 404).
