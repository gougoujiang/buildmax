# Task 022: New tool - Task

## Goal

Implement an agent tool **Task** that lets the LLM spawn a sub-agent to handle complex subtasks autonomously, so the parent agent can delegate multi-step work (exploration, shell commands, general tasks, or specialized user-defined roles) to a focused sub-agent that runs in its own ephemeral session and returns the result. The tool supports both **built-in agent types** (general, explore, shell) defined in code and **user-defined agents** loaded from `<workspace>/.agents/agents/` at startup.

## Context

- **internal/tools**: Existing tools implement `agent.Tool`: `Name()`, `Description()`, `Parameters() any`, `Execute(ctx, args) (string, error)`. Tools are constructed in `cmd/buildmax/root.go` `setupAgentAndSession()` and passed as a slice to `agent.NewAgent()`. Existing tools: Read, WriteFile, WebFetch, TodoWrite, Bash, Glob, EditFile, Grep. Snake_case for parameter keys; return meaningful success/error strings for the LLM (AGENTS.md §6.2).
- **internal/agent**: `Agent` struct holds tools, LLM caller, and runs `processLoop(ctx, sess)`. Public API: `Process(ctx, sess, userMessage) (reply, err)` appends the user message and runs the loop; `ProcessAfterUserAppended(ctx, sess) (reply, err)` for when the caller already appended the message. `LLMCaller` interface: `ChatWithTools(ctx, messages, tools) (content, toolCalls, err)`. `NewAgent(caller, tools, opts...)` constructs an agent. `MaxIterations(n) Option` configures max loop iterations. The system prompt is currently hardcoded as `DefaultSystemPrompt` in `processLoop`.
- **internal/session**: `NewSession(title)` creates a session with a generated UUID. `CtxWithSessionID` / `SessionIDFromContext` carry session identity in context.
- **internal/llm**: `Client` implements `LLMCaller`. `NewClient(cfg)` creates a client. Types: `Message`, `ToolCall`, `ToolDef`.
- **cmd/buildmax/root.go**: `setupAgentAndSession` creates all tools and the agent. `client` is `*llm.Client` (implements `agent.LLMCaller`). The tool slice is passed to `agent.NewAgent(client, []agent.Tool{...})`.
- **Conventions**: All-Go; snake_case for JSON parameters (AGENTS.md §6.1). Tools return clear success/error messages (§6.2).

## Task tool (this task)

For this task, **Task** means:

1. **Sub-agent spawning**: The LLM calls the Task tool with a prompt, short description, and agent type. The tool creates a new `Agent` with the appropriate tool subset and system prompt, runs it on an ephemeral session via `agent.Process()`, and returns the sub-agent's final reply as the tool result string.

2. **Built-in agent types** (defined in code):
   - `general`: All base tools except Task itself (Read, WriteFile, WebFetch, TodoWrite, Bash, Glob, EditFile, Grep). General-purpose agent for multi-step tasks.
   - `explore`: Read-only tools only — Read, Glob, Grep. Fast codebase exploration without modifications.
   - `shell`: Bash tool only. Command execution specialist.

3. **User-defined agent types** (loaded from files):
   - Located under `<workspace>/.agents/agents/`. Each file defines one agent.
   - File format: YAML frontmatter (between `---` delimiters) + markdown body as the system prompt.
   - Frontmatter fields:
     - `name` (string, required): Agent type name. Used as the `subagent_type` value. Must not conflict with built-in names.
     - `description` (string, required): LLM-readable description of what this agent specializes in.
     - `tools` (string, required): Comma-separated list of tool names (e.g. `"Glob, Grep, Read"`). Names must match registered base tool `Name()` values. Unknown tool names are skipped with a log warning.
     - `model` (string, optional): Model hint — parsed and stored but **not used** in this task (future: model selection).
   - Body (everything after the closing `---`): The system prompt for this agent type.
   - Example file (`.agents/agents/code-architect.md`):
     ```
     ---
     name: code-architect
     description: Designs feature architectures by analyzing existing codebase patterns
     tools: Glob, Grep, Read, WebFetch, TodoWrite
     model: sonnet
     ---

     You are a senior software architect who delivers comprehensive blueprints...
     ```

4. **Loading at startup**: On system start, all agent definition files are loaded from `<workspace>/.agents/agents/`. If the directory does not exist, no user-defined agents are loaded (not an error). If a file has parse errors, log a warning and skip it.

5. **Dynamic description**: The Task tool's `Description()` method builds a description string that lists **all** available agent types (built-in + user-defined) with their names and descriptions, so the LLM knows every type it can use.

6. **Dynamic enum**: The `Parameters()` method includes all agent type names (built-in + user-defined) in the `subagent_type` enum.

7. **Ephemeral session**: The sub-agent runs in a new in-memory session created via `session.NewSession(description)`. The session is not persisted — it exists only for the duration of the Execute call and is discarded after the result is returned.

8. **Synchronous execution**: `Execute` blocks until the sub-agent finishes and returns the final reply text. No background or async execution.

9. **Recursion prevention**: Sub-agents do NOT receive the Task tool. Only the parent agent has it. This prevents infinite recursion.

10. **Custom system prompt**: Each agent type (built-in or user-defined) gets its own system prompt. This requires adding a `SystemPrompt(string) Option` to the Agent (currently the system prompt is hardcoded as `DefaultSystemPrompt`). The Task tool passes the type-specific prompt when constructing the sub-agent.

11. **Parameters**: `description` (string, short 3-5 word summary), `prompt` (string, the task for the sub-agent), `subagent_type` (string, one of the available type names). All three required. Snake_case keys.

We are **not** implementing in this task:

- Model selection for sub-agents (the `model` field is parsed and stored but all sub-agents use the parent's LLM client)
- Resume capability (sub-agent sessions are ephemeral, no agent ID returned)
- Background/async execution or output files
- Max turns parameter (sub-agents use `DefaultMaxIterations`)
- Persisting sub-agent sessions to disk
- TUI display of sub-agent activity, progress, or color
- Hot-reloading agent definitions (only loaded once at startup)

## Deliverables

1. **internal/agent/agent.go** (edit)
   - Add **`SystemPrompt(prompt string) Option`**: An `Option` function that sets a custom system prompt on the Agent. Store it as a field `systemPrompt string` on the `Agent` struct (default: `DefaultSystemPrompt`).
   - In `processLoop`, use `a.systemPrompt` instead of the hardcoded `DefaultSystemPrompt` when building the messages slice. This allows sub-agents to have role-specific prompts.
   - No other changes to the Agent loop or Tool interface.

2. **internal/tools/agentdef.go** (new)
   - **AgentDef** struct (exported): Represents one parsed agent definition. Fields:
     - `Name string` — agent type name
     - `Description string` — LLM-readable description
     - `ToolNames []string` — parsed tool names from the `tools` field
     - `SystemPrompt string` — body text (the system prompt)
     - `Model string` — model hint (stored, not used yet)
     - `Color string` — color hint (stored, not used yet)
   - **LoadAgentDefs**(dir string) ([]AgentDef, error): Reads all files from `dir`. For each file:
     - Parse YAML frontmatter (between first `---` and second `---`).
     - Extract `name`, `description`, `tools` (split by comma, trim whitespace), `model`, `color`.
     - Validate: `name` and `description` are required; `tools` must have at least one entry. Skip invalid files with a log warning.
     - Body after the closing `---` is the system prompt (trimmed).
     - If `dir` does not exist, return `(nil, nil)` — not an error.
   - Use `gopkg.in/yaml.v3` (or the standard library if feasible) for YAML frontmatter parsing. If adding a dependency is undesirable, a simple manual parser (split on `---`, parse key-value lines) is acceptable.

3. **internal/tools/agentdef_test.go** (new)
   - Unit tests:
     (1) LoadAgentDefs with a valid definition file returns correct AgentDef.
     (2) LoadAgentDefs with missing `name` skips the file.
     (3) LoadAgentDefs with non-existent directory returns `(nil, nil)`.
     (4) Multiple files in the directory return multiple AgentDefs.
     (5) Tools string is correctly split and trimmed (e.g. `"Glob, Grep, Read"` → `["Glob", "Grep", "Read"]`).
     (6) System prompt (body) is correctly extracted and trimmed.

4. **internal/tools/task.go** (new)
   - **AgentTypeConfig** struct (exported, so wiring code can construct it): `Tools []agent.Tool`, `SystemPrompt string`, `Description string`.
   - **TaskTool** struct: holds `caller agent.LLMCaller` and `agentTypes map[string]AgentTypeConfig`. Implements `agent.Tool`.
   - **NewTask**(caller agent.LLMCaller, agentTypes map[string]AgentTypeConfig) (\*TaskTool, error): Constructor. Validates caller is not nil and agentTypes is non-empty. Returns error on invalid input.
   - **Name**() string: Returns `"Task"`.
   - **Description**() string: Dynamically built. Lists all available agent types with their name and description. Example output:
     ```
     Launch a sub-agent to handle a complex subtask autonomously. Available agent types:
     - general: General-purpose agent with all tools for multi-step tasks.
     - explore: Read-only agent for fast codebase exploration (Read, Glob, Grep).
     - shell: Command execution specialist (Bash only).
     - code-architect: Designs feature architectures by analyzing existing codebase patterns.
     ```
   - **Parameters**() any: JSON schema with `description` (string), `prompt` (string), `subagent_type` (string, enum dynamically built from all agent type names). All required.
   - **Execute**(ctx, args) (string, error):
     - Parse and validate: `description` (non-empty string), `prompt` (non-empty string), `subagent_type` (must be a key in agentTypes).
     - Look up the `AgentTypeConfig` for the requested type.
     - Create an ephemeral session: `session.NewSession(description)`.
     - Create a sub-agent: `agent.NewAgent(t.caller, config.Tools, agent.SystemPrompt(config.SystemPrompt))`.
     - Call `subAgent.Process(ctx, sess, prompt)` to run the sub-agent loop.
     - Return the sub-agent's final reply string.
     - On error (LLM failure, max iterations exceeded, etc.), return a clear error message.
