# Task 042: Change design: tasks belong to workspace

## Goal

Make tasks owned by workspace instead of project. Add `workspace_id` to the task model, make `project_id` optional, expose workspace-scoped task APIs as the single canonical endpoints, remove project-scoped task endpoints, and update the portal to use the new APIs.

## Context

- **Current**: Task has required `project_id`; `TaskStore` has `ListTasksByProject(projectID)` and `CreateTask(projectID, input, createdBy)`. API: `GET/POST /api/projects/{project_id}/tasks`; auth via project → workspace ownership. Portal calls these endpoints.
- **Reason**: Users should be able to start a task in a workspace without choosing a project (e.g. explore workspace, ask ad-hoc questions). Tasks are conceptually owned by the workspace; project is an optional scope.

## In scope

1. **Data model**
   - Add `workspace_id` (required, NOT NULL) to `Task` in `internal/store`; make `project_id` optional (nullable).
   - Migration: GORM AutoMigrate adds `workspace_id` column and makes `project_id` nullable. Existing rows get `workspace_id` backfilled from their project's workspace.

2. **Store**
   - Replace `TaskStore` interface:
     - `ListTasksByWorkspace(ctx, workspaceID string, projectID *string) ([]Task, error)` — list tasks in workspace; when `projectID != nil`, filter by that project.
     - `CreateTask(ctx, workspaceID string, projectID *string, input, createdBy string) (*Task, error)` — create task with required workspace and optional project.
   - Remove `ListTasksByProject` (no longer needed; callers use `ListTasksByWorkspace` with a `projectID` filter).

3. **API (workspace-scoped only)**
   - `GET /api/workspaces/{workspace_id}/tasks` — list tasks in workspace. Optional query `?project_id=X`: filter by project (validate project belongs to workspace). Auth: user must own workspace.
   - `POST /api/workspaces/{workspace_id}/tasks` — create task. Body: `{ "input": "…", "project_id": "optional" }`. If `project_id` provided, validate it belongs to the workspace. Auth: user must own workspace.
   - **Remove** `GET /api/projects/{project_id}/tasks` and `POST /api/projects/{project_id}/tasks` — routes, handlers, and OpenAPI entries all removed.

4. **Response**
   - `TaskResponse` adds `workspace_id` (always present); `project_id` becomes nullable (omitted or null when task has no project).

5. **OpenAPI**
   - Remove `/api/projects/{project_id}/tasks` paths.
   - Add `GET/POST /api/workspaces/{workspace_id}/tasks` with `project_id` as optional query param (GET) and optional body field (POST). Task schema: `workspace_id` required, `project_id` nullable.

6. **Portal**
   - Update `api.ts`: `getTasks(workspaceId, projectId?, token)` calls `GET /api/workspaces/${wid}/tasks?project_id=${pid}`. `createTask(workspaceId, body, token)` calls `POST /api/workspaces/${wid}/tasks`.
   - Update `App.tsx` and `ProjectDashboard.tsx` call sites to pass `workspaceId` and `projectId` to the new API functions.

## Out of scope

- Portal: workspace-level task list UI or "create task without project" form (follow-up).
- Task execution or run semantics.
- Get/update/delete single task endpoints (follow-up; will use `GET/PATCH/DELETE /api/workspaces/{wid}/tasks/{tid}`).

## Deliverables

- **internal/store**: Task struct: `workspace_id` NOT NULL, `project_id` nullable; updated `TaskStore` interface (`ListTasksByWorkspace`, `CreateTask` with new signature); `ListTasksByProject` removed; AutoMigrate handles schema change.
- **internal/server**: Remove project-scoped task routes and handlers; add workspace-scoped list/create handlers; `TaskResponse` includes `workspace_id`, `project_id` nullable; OpenAPI updated.
- **portal**: `api.ts` functions updated to workspace-scoped URLs; call sites in `App.tsx` and `ProjectDashboard.tsx` updated.

## Acceptance criteria

- [ ] Task table has `workspace_id` (NOT NULL) and `project_id` (nullable). Existing tasks backfilled with `workspace_id` from their project.
- [ ] `GET /api/workspaces/{workspace_id}/tasks` returns 200 with tasks in that workspace; with `?project_id=X` returns only tasks for that project; 401/403 when not owned.
- [ ] `POST /api/workspaces/{workspace_id}/tasks` with body `{ "input": "…" }` creates a task with no project (201, `project_id` null); with `{ "input": "…", "project_id": "…" }` creates a task linked to that project (400 if project not in workspace). 201 response includes `workspace_id`.
- [ ] Project-scoped task endpoints (`/api/projects/{project_id}/tasks`) are removed — return 404 (no route).
- [ ] OpenAPI describes only workspace-scoped task endpoints; task schema has `workspace_id` required, `project_id` nullable.
- [ ] Portal `getTasks` and `createTask` use workspace-scoped URLs; project dashboard works as before.
- [ ] `go build ./...` and `go test ./...` pass.
