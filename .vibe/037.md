# Task 037: Workspace management

Manage workspaces (create, list, switch, delete) so users can organize projects and agent context by workspace. This task delivers **backend persistence and API** for workspaces and wires the portal to use them; for MVP only the **Default** workspace per user is supported.

---

## Goal

**One sentence:** Add a workspace table and directory layout on the server, ensure every user has exactly one "Default" workspace (created on first use), expose `GET /api/workspaces` for the authenticated user, and have the portal load the workspace list from the API instead of mock data.

---

## Context

- **Server:** `internal/server` — HTTP server with `/healthz`, `/openapi.json`, `/swagger/`, `POST /api/login`. JWT returned on login; no protected routes yet beyond what this task adds.
- **Store:** `internal/store` — MySQL via GORM; `User` model (id, email, name, created_at); `UserStore` with `UserByEmail`. AutoMigrate runs for User.
- **Config:** `config.DataDir()` — default `~/.buildmax`, override via `BUILDMAX_HOME`. No workspace root yet.
- **Portal:** Workspaces are mock-only in `portal/src/data/mockData.ts` (`listWorkspaces`, `getWorkspaceById`, `createWorkspace`); App and TopBar already show workspace selector and route by `workspaceId`. No workspace API client.
- **Conventions:** AGENTS.md — persisted data uses snake_case in JSON; backend in Go; portal calls Go API.

---

## In scope

- **Workspace table (MySQL, same store)**
  - Columns: `id` (primary key, auto-increment or unique id), `owner_user_id` (FK to users), `name` (e.g. `"Default"`), `created_at`.
  - JSON/API: snake_case (`owner_user_id`, `created_at`).
  - One row per user for MVP: the single "Default" workspace.

- **Workspace root (filesystem)**
  - Root directory: configurable; **default** `DataDir()/workspaces` (i.e. `BUILDMAX_HOME/workspaces` when `BUILDMAX_HOME` is set).
  - Layout: under root, one directory per workspace: `<workspace_root>/<workspace_id>`. Directory created when the workspace row is created (or on first use). No file upload or storage inside these dirs in this task.

- **Backend API**
  - **`GET /api/workspaces`** — requires valid JWT. Returns list of workspaces for the authenticated user. If the user has no workspace, create one named `"Default"` and return it (so response always has at least one workspace). Response JSON: array of `{ "id", "name", "owner_user_id", "created_at" }` (or minimal set needed by portal). 401 when no/invalid token.

- **Store layer**
  - Add `Workspace` model and persistence (e.g. `WorkspaceStore` or methods on existing Store). At least: ensure default workspace for user (create if not exists), list workspaces by owner. Use same DB and GORM; AutoMigrate for `Workspace`.

- **Portal**
  - When authenticated, load workspaces via `GET /api/workspaces` (with `Authorization: Bearer <token>`). Use returned list for TopBar selector and routing; no mock workspace list when user is logged in. If API fails, show error or fallback behavior as designed.

- **OpenAPI**
  - Document `GET /api/workspaces` (auth: Bearer JWT; response: list of workspace objects).

---

## Out of scope

- **Create/delete/rename workspace APIs** — MVP is Default-only; multi-workspace CRUD is a follow-up.
- **File upload or storage** inside workspace directories — future task.
- **Protected routes middleware** — only `/api/workspaces` needs to require JWT in this task; general auth middleware can be a follow-up.
- **CLI/TUI workspace** — no change to CLI or TUI in this task.

---

## Technical notes

- **Workspace id:** Use a stable id (e.g. integer auto-increment or UUID) for the row; directory name = that id (string form). Prefer consistent type (e.g. string in API so portal keeps using string `workspaceId`).
- **Default workspace creation:** On first `GET /api/workspaces` for a user with no workspaces, insert one row (name `"Default"`, owner = user id) and create `<workspace_root>/<id>` directory; then return the list.
- **Config:** Add `WorkspacesDir()` (or `WorkspaceRoot()`) in `internal/config` returning `filepath.Join(DataDir(), "workspaces")`; optional env override (e.g. `BUILDMAX_WORKSPACES_DIR`) if desired.

## Deliverables

1. **internal/store**
   - `Workspace` struct: id, owner_user_id, name, created_at; GORM tags and `json:"snake_case"`.
   - Interface or methods: ensure default workspace for user (create if not exists); list workspaces by owner_user_id. AutoMigrate `Workspace`.

2. **internal/config**
   - `WorkspacesDir()` (or `WorkspaceRoot()`) returning default `DataDir()/workspaces`.

3. **internal/server**
   - Register `GET /api/workspaces`. Extract user id from JWT (reuse or add small helper); call store to ensure default workspace and list; create workspace directory on disk when creating default; return JSON array. Return 401 when no/invalid token.
   - Update OpenAPI spec with `GET /api/workspaces`.

4. **Portal**
   - API client: e.g. `getWorkspaces(): Promise<Workspace[]>` in `api.ts`, calling `GET /api/workspaces` with `Authorization: Bearer <token>`.
   - App/context: when authenticated, fetch workspaces from API; pass list to AppShell/TopBar; use first workspace as default route when needed. Remove or bypass mock workspace list for logged-in users.

5. **Tests**
   - Backend: test that listing workspaces creates Default when none exist; test 401 without token. No real external API in tests.
