# Task 053: Add artifact concept

## Goal

Introduce a first-class **artifact** concept: a dedicated storage location and DB model for task-run outputs. Each successful task run produces one recorded artifact (one result file in this task); artifacts are stored under a new `artifact` workspace directory and tracked in new `artifact` and `artifact_item` tables, with a per-task `artifact_seq` column to order runs and `last_artifact_id` for easy lookup of the latest artifact. This prepares for flexible artifact management (listing, multiple files, etc.) while keeping current behavior of also copying the result into the persistent workspace so the file tree still shows it.

## Context

- **Current behavior** (from task 052): Workspace has two roots — **persist** (`DataDir()/workspace/persist/<workspace_id>`) for user uploads and displayed files, and **task** (`DataDir()/workspace/task/<task_id>`) for the ephemeral run. After the agent runs, the executor writes `result-<task_id>.md` in the runtime dir and copies it to the persist dir. There is no DB record of "this file is the output of run N" or a stable artifact id.
- **Your intention**: Reintroduce artifact as a concept that was removed earlier for simplicity. You want: (1) a **reorganized path layout** so all three dir types live under one workspace root; (2) new DB tables to record generated artifacts and their items (paths); (3) an **artifact_seq** column on task that increments on each run (and **last_artifact_id** to point to the latest artifact for easy lookup); (4) when saving an artifact, generate a new base62 **artifact_id**, persist the result file under the artifact store, and insert artifact + artifact_item rows. For this task, keep the same single-file output (one result file per run) and leave multiple artifact files per run for a later task.
- **Conventions**: AGENTS.md — config in `internal/config`, store in `internal/store`, executor in `internal/executor`; table names singular; JSON/snake_case for persisted data; IDs use `internal/id` base62 (`id.New()`).

## Workspace path layout (reorg)

All workspace-related directories live under a single **workspace root** per workspace:

```
<data dir>/workspaces/<workspace id>/
  - persist/                              # 用户上传/长期资料 (user uploads, long-term)
  - tasks/<task id>/                      # runtime/scratch (ephemeral, can be cleaned)
  - artifacts/<task id>/<artifact id>/    # 每次会话继续后的快照产物 (snapshot output per run)
```

- **Workspace root** = `DataDir()/workspaces/<workspace_id>/`. One env override: `BUILDMAX_WORKSPACES_DIR` (if set) is the parent of workspace roots, i.e. `WorkspacesDir()` returns that path so workspace root = `WorkspacesDir()/<workspace_id>/`.
- **persist**: user uploads and long-term files; result file is also copied here so the file tree shows it.
- **tasks/<task_id>/**: ephemeral runtime directory for each task run (can be cleaned later).
- **artifacts/<task_id>/<artifact_id>/**: one directory per artifact (snapshot output after each run).

## In scope

1. **Config — reorganized workspace paths**
   - **WorkspacesDir()**: return the **parent** of all workspace roots: `DataDir()/workspaces` (or `BUILDMAX_WORKSPACES_DIR` if set). So workspace root = `filepath.Join(WorkspacesDir(), workspaceID)`.
   - **PersistentWorkspaceDir(workspaceID)**: return `filepath.Join(WorkspacesDir(), workspaceID, "persist")`.
   - **RuntimeWorkspaceDir(workspaceID, taskID)**: return `filepath.Join(WorkspacesDir(), workspaceID, "tasks", taskID)`. Signature gains `workspaceID` (current code has only `taskID`; callers must pass both).
   - **ArtifactDir(workspaceID, taskID, artifactID)**: return `filepath.Join(WorkspacesDir(), workspaceID, "artifacts", taskID, artifactID)`. Used by executor to create one dir per artifact and write the result file there.
   - No other env overrides for the three subdir names (persist, tasks, artifacts).

2. **DB — task.artifact_seq and task.last_artifact_id**
   - Add to **task** table: `artifact_seq` (int, default 0). Represents the run sequence: before saving an artifact we increment it (e.g. 0 → 1 for first run, 1 → 2 for second run) and use the new value for the artifact row.
   - Add to **task** table: `last_artifact_id` (varchar(64), nullable). After creating an artifact, set to that artifact’s id so the latest artifact can be read without querying the artifact table.
   - **TaskStore**: Add a method to atomically increment and return the new artifact_seq for a task, e.g. `IncrementTaskSeq(ctx, taskID string) (newSeq int, err error)`. When creating an artifact, also update task.last_artifact_id = artifact_id (e.g. inside CreateArtifactWithItem transaction).

3. **DB — artifact and artifact_item tables**
   - **artifact** table (singular): one row per “artifact set” (one per task run that produces output).
     - `id`: integer, primary key, auto-increment (internal only).
     - `task_id`: varchar(64), not null, index (references task.task_id).
     - `artifact_id`: varchar(64), unique, not null (base62 id, same style as task_id).
     - `created_at`: int64, set on insert.
     - `seq`: int, not null (run sequence for this task; matches task.artifact_seq at creation time).
   - **artifact_item** table (singular): one row per file in an artifact. In this task we have exactly one item per artifact.
     - `id`: integer, primary key, auto-increment (internal only).
     - `artifact_id`: varchar(64), not null, index (references artifact.artifact_id).
     - `relative_path`: varchar(512), not null — path of the file **relative to the task (runtime) workspace** (e.g. `result-<task_id>.md`).
   - GORM models with `TableName()` singular (`artifact`, `artifact_item`). Add to `Store`’s AutoMigrate. New store methods: e.g. `CreateArtifact(ctx, taskID, artifactID string, seq int) (*Artifact, error)` and `CreateArtifactItem(ctx, artifactID, relativePath string) error`, or a single transactional “create artifact with items” API as needed.

4. **Executor — create artifact on successful run**
   - After writing `result-<task_id>.md` to the runtime dir and copying it to the persist dir (unchanged behavior):
     1. Call `IncrementTaskSeq(ctx, task.TaskID)` to get `newSeq`.
     2. Generate `artifactID := id.New()`.
     3. Create artifact directory: `ArtifactDir(task.WorkspaceID, task.TaskID, artifactID)`; write the result file there (e.g. as `result.md` — single file per artifact).
     4. Insert **artifact** row: task_id, artifact_id, created_at, seq = newSeq. Update task.last_artifact_id = artifact_id (e.g. in same transaction as CreateArtifactWithItem).
     5. Insert **artifact_item** row: artifact_id, relative_path = `result-<task_id>.md`.
   - On any step failure (e.g. mkdir, copy, DB insert): log and continue; do not fail the task run (artifact creation is best-effort in this task if you prefer), or define strict semantics (e.g. fail task if artifact creation fails). Spec: best-effort — log errors, do not mark task as failed solely due to artifact save failure.
   - Do **not** create artifact rows for failed runs; only for runs that reach “success” and copy result to persist.

5. **Persistence naming**
   - All new struct fields and JSON/DB columns use snake_case per AGENTS.md (e.g. `task_id`, `artifact_id`, `created_at`, `relative_path`, `seq`, `artifact_seq`, `last_artifact_id`).

## Out of scope

- **API**: No new HTTP or CLI endpoints to list or get artifacts; DB and storage only.
- **Multiple files per artifact**: Still one result file per run; multiple artifact_item rows per artifact deferred.
- **Deleting or renaming artifacts**: No delete/update artifact API.
- **Changing runtime result filename**: Keep `result-<task_id>.md` in the runtime workspace; artifact_item.relative_path matches that.
- **Runtime workspace cleanup**: Unchanged; no change to when/if task dirs are removed.
- **Migration of existing data**: No backfill of artifacts for past runs; artifact_seq starts at 0 for existing tasks and increments only on new runs. No automatic migration of existing files from the old layout (`DataDir()/workspace/persist`, `DataDir()/workspace/task`) to the new layout (`DataDir()/workspaces/<workspace_id>/persist`, etc.); document or handle in a follow-up.

## Deliverables

- Config: **Path reorg** — `WorkspacesDir()` returns `DataDir()/workspaces` (or env override); `PersistentWorkspaceDir(workspaceID)` = workspace root + `persist/`; `RuntimeWorkspaceDir(workspaceID, taskID)` = workspace root + `tasks/<task_id>/`; `ArtifactDir(workspaceID, taskID, artifactID)` = workspace root + `artifacts/<task_id>/<artifact_id>/`. All call sites updated (executor, server).
- Task model: `artifact_seq` and `last_artifact_id` columns; TaskStore `IncrementTaskSeq(ctx, taskID string) (int, error)`; CreateArtifactWithItem also sets task.last_artifact_id.
- Artifact and ArtifactItem models; new tables in AutoMigrate; store methods to create artifact + one item in a transaction.
- Executor: after successful run, increment artifact_seq, generate artifact_id, write result file to artifact dir, insert artifact + artifact_item and set task.last_artifact_id (best-effort, log on failure).

## Acceptance criteria

- [ ] Workspace path layout is `<data dir>/workspaces/<workspace_id>/persist`, `.../tasks/<task_id>/`, `.../artifacts/<task_id>/<artifact_id>/`. `WorkspacesDir()` returns the parent of workspace roots.
- [ ] `PersistentWorkspaceDir(workspaceID)` returns `WorkspacesDir()/<workspace_id>/persist`; `RuntimeWorkspaceDir(workspaceID, taskID)` returns `WorkspacesDir()/<workspace_id>/tasks/<task_id>`; `ArtifactDir(workspaceID, taskID, artifactID)` returns the full artifact path.
- [ ] Task table has `artifact_seq` (int, default 0) and `last_artifact_id` (varchar, nullable); existing tasks have artifact_seq 0, last_artifact_id null.
- [ ] `TaskStore.IncrementTaskSeq(ctx, taskID)` increments artifact_seq and returns new seq; safe to call from executor.
- [ ] Tables `artifact` and `artifact_item` exist with the specified columns and singular names.
- [ ] On a successful task run, a new artifact_id is generated, the result file is written under `ArtifactDir(workspaceID, taskID, artifactID)/`, and one artifact row and one artifact_item row are created; task.artifact_seq is incremented and task.last_artifact_id is set to the new artifact_id.
- [ ] Failed runs do not create artifact rows and do not increment artifact_seq.
- [ ] Result file is still copied to the persistent workspace as today (unchanged behavior for file tree).
- [ ] All new persisted fields use snake_case. All call sites (executor, server upload/files/workspaces) use the new config APIs and paths.
