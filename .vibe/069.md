# Task 069: Generate a title given user input for task

## Goal

Store a short, human-friendly task title (3–5 words) generated from the user's task input via LLM, and display it on the Portal instead of the truncated input.

## Context

- **Current state**: The Task model has no `Title` field; only `Input` (the full prompt). The Portal derives a display label by truncating `input` to 80 characters in `apiTaskToTask` (portal `lib/api/mappers.ts`). This is unfriendly for long prompts.
- **Existing pattern**: Session title generation already exists in `internal/session/title.go`: `GenerateTitle(ctx, client TitleChatClient, messages []llm.Message)` uses an LLM with a system prompt ("3–8 words") and `cleanTitle()`. Callers use `llm.Client.ChatWithTools(ctx, msgs, nil)` wrapped in `session.TitleChatFunc`. The server does not currently use the LLM.
- **Relevant code**: Task model in `internal/model/models.go`; task creation in `internal/storage/entity/task.go` (`CreateTask`); API in `internal/server/tasks.go` (`TaskResponse`, `taskToResponse`, create handler); portal types in `portal/src/lib/types.ts` and mappers in `portal/src/lib/api/mappers.ts`; session title in `internal/session/title.go`.

## Scope

### In scope

- Add an optional `Title` field to the Task model (and DB migration). Existing tasks remain with empty title.
- When creating a task (POST create task): generate a short title from `input` using the LLM (3–5 words, same style as session). If LLM is unavailable or fails, fall back to truncated input (e.g. first 50 runes + "…").
- Server: accept optional LLM config for title generation; call title generation during create; persist and return `title` in task responses.
- API: extend task list/get responses with `title` (snake_case). Portal uses API `title` when present; otherwise keeps current truncation fallback.

### Out of scope

- Backfilling titles for existing tasks.
- Changing session title generation or wiring.
- Updating task title on rerun or subsequent edits.
- Adding a separate API or UI to edit task title.

## Deliverables

1. **Model & storage**
   - Add `Title` to `model.Task` (e.g. `string`, optional, stored in DB).
   - DB migration for new column (nullable or default "").
   - `entity.CreateTask` (and any call sites) accept and persist title; create flow computes title before insert.

2. **Title generation**
   - Reuse the same LLM pattern as session: simple chat completion (no tools), system prompt asking for 3–5 word title from the given user input, return only the title. Reuse or mirror `cleanTitle` behavior (trim, strip quotes, cap length).
   - Place: either extend `internal/session/title.go` with a single-input helper (e.g. `GenerateTitleFromInput(ctx, client, input string) (string, error)`) or add a small package (e.g. `internal/tasktitle`) used only by the server. Decision: prefer minimal new surface; if the helper fits in `session` without pulling server into session, use that; otherwise a thin server-side helper that uses the same interface is acceptable.

3. **Server**
   - Load LLM config (optional) in server startup; if present, inject a title-generation client into task creation flow.
   - In the create-task handler: compute title (LLM if available, else truncate); pass title to store; include in response.
   - Extend `TaskResponse` and `taskToResponse` with `title`.

4. **Portal**
   - API type for task includes `title` (optional). Mapper: use `api.title` when present and non-empty; otherwise fallback to current truncated `input` for `task.title`.

## Acceptance criteria

- [ ] Task has a `Title` field in the model and DB; migration runs cleanly.
- [ ] New tasks created via the API get a title: when LLM is configured and succeeds, it is a short (3–5 word) title; when LLM is unavailable or fails, title is a truncated version of input.
- [ ] GET task and list tasks responses include `title`; portal displays it in Activity and TaskDetail when present.
- [ ] Existing tasks without title still work: API returns empty or omitted title; portal fallback (truncated input) still applies.
- [ ] No regression in session title or other flows; LLM usage for task title is optional (server runs without LLM config and still creates tasks with truncated fallback).
