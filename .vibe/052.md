# Task 052: Separate runtime workspace from persistence workspace

## Goal

Introduce two distinct workspace roots: **persistent workspace** (where user uploads and stored files live) and **runtime workspace** (ephemeral per-task directory where the agent runs). When a task runs, the executor initializes the runtime workspace by copying from the persistent workspace, runs the agent in the runtime directory, then persists the result file back to the persistent workspace.

## Context

- **Current behavior**: A single `config.WorkspacesDir()` returns `DataDir()/workspaces` (or `BUILDMAX_WORKSPACES_DIR`). All uses share it: upload and file tree use `WorkspacesDir()/<workspace_id>/`; the executor uses the same path as the task’s working directory and writes `result-<task_id>.md` there. So user files and agent run state live in the same place.
- **Conventions**: AGENTS.md — config in `internal/config`, executor in `internal/executor`, server in `internal/server`; persistence paths use snake_case where applicable; single place per responsibility.
- **Relevant code**: `internal/config/config.go` (WorkspacesDir); `internal/executor/executor.go` (workspacesDir, wsDir = join(workspacesDir, task.WorkspaceID), cmd.Dir = wsDir, result written to wsDir); `internal/server/upload.go`, `files.go`, `workspaces.go` (all use config.WorkspacesDir() with workspace_id).

## In scope

1. **Config — two roots**
   - **Persistent workspace root**: directory for user-owned workspace files (uploads, file tree). Default: `DataDir()/workspace/persist`. Expose e.g. `PersistentWorkspaceDir(workspaceID string) string` returning `filepath.Join(root, workspaceID)`, with root = `DataDir()/workspace/persist` (no new env override in this task).
   - **Runtime workspace root**: directory for ephemeral per-task run directories. Default: `DataDir()/workspace/task`. Expose e.g. `RuntimeWorkspaceDir(taskID string) string` returning `filepath.Join(root, taskID)`.
   - Keep or deprecate `WorkspacesDir()`: callers that mean “persistent workspace root” should switch to the new API; design may keep `WorkspacesDir()` returning the same path as the persistent root for compatibility, or rename. Prefer introducing the two new functions and migrating call sites; remove or alias `WorkspacesDir()` so that upload/files/workspace creation use the persistent root only, and executor uses the runtime root + persistent root as needed.

2. **Executor — task run flow**
   - Resolve **persistent** dir: `persistDir := config.PersistentWorkspaceDir(task.WorkspaceID)` (or equivalent).
   - Resolve **runtime** dir: `runtimeDir := config.RuntimeWorkspaceDir(task.TaskID)`.
   - **Before run**: create `runtimeDir`; copy contents from `persistDir` into `runtimeDir` (e.g. recursive copy of files; treat missing persistDir as empty so first run without uploads still works).
   - **Run**: execute buildmax with `cmd.Dir = runtimeDir` (unchanged behavior from agent’s perspective).
   - **After run**: write `result-<task_id>.md` as today (in runtimeDir), then **copy that result file** from runtimeDir to persistDir so the user sees it in their workspace (file tree / GET file). Do not remove the runtime dir; runtime workspace cleanup will be handled in a separate task.
   - No change to DB or task status updates; only the directory layout and copy steps change.

3. **Server — use persistent root only**
   - **Upload**: destination directory = `config.PersistentWorkspaceDir(workspaceID)` (or equivalent). Ensure that directory exists before writing.
   - **Files (tree + content)**: resolve workspace root as `config.PersistentWorkspaceDir(workspaceID)`.
   - **Create workspace / ensure dirs**: when creating a workspace or ensuring dirs for listed workspaces, create `config.PersistentWorkspaceDir(workspaceID)` only (no runtime dirs here).

4. **Backward compatibility / migration**
   - If existing deployments have files under `DataDir()/workspaces/<id>/`, decide whether to migrate: either document one-time move to `workspace/persist/<id>/` or, in code, check both locations and prefer the new path. Prefer **new layout only** for this task: new installs use `workspace/persist` and `workspace/task`; document that existing `workspaces/` is legacy and not used by executor for new runs (or add a one-time migration helper that copies `workspaces/<id>/*` → `workspace/persist/<id>/` if persist dir is empty). Clarification: keep scope to “new layout”; migration of existing data can be a follow-up or doc-only.

## Out of scope

- Syncing back **all** modified or new files from runtime to persistent (only the explicit result file `result-<task_id>.md` is required to be copied back).
- Env overrides for the two new roots (e.g. `BUILDMAX_PERSIST_WORKSPACES_DIR`); can be added later.
- Runtime workspace cleanup (per-run or scheduled removal of runtime task dirs) — out of scope; will be handled in a separate task.
- Changing the portal or API contract (paths are server-internal; API still refers to workspace_id and task_id).

## Deliverables

- **internal/config**: Add `PersistentWorkspaceDir(workspaceID string) string` and `RuntimeWorkspaceDir(taskID string) string` with roots `DataDir()/workspace/persist` and `DataDir()/workspace/task`. Update or replace `WorkspacesDir()` so all current callers that mean “persistent” use the new API; remove or alias `WorkspacesDir()` to avoid duplicate concepts.
- **internal/executor**: Use runtime dir for execution: before run, create runtime dir and copy from persistent workspace dir into it; run buildmax with cwd = runtime dir; after run, copy `result-<task_id>.md` to persistent workspace dir (do not delete runtime dir; cleanup separately). Use config’s PersistentWorkspaceDir and RuntimeWorkspaceDir.
- **internal/server**: Use persistent workspace dir only for upload, file tree, file content, and ensureWorkspaceDirs (create workspace / list workspaces). Replace any `WorkspacesDir()` usage with the new persistent API.
- **Tests**: Executor test(s) that verify copy-from-persist and copy-result-back (e.g. create persist dir with a file, run task, assert result appears in persist dir). Config tests for the two new path functions. Server tests remain valid (still write/read under persistent root).

## Acceptance criteria

- [ ] Persistent workspace root is `DataDir()/workspace/persist/<workspace_id>`; runtime workspace root is `DataDir()/workspace/task/<task_id>`.
- [ ] Upload and file tree / file content use the persistent workspace path only; new files and result file are visible under the same workspace for the user.
- [ ] When a task runs, the executor copies the persistent workspace contents into the task’s runtime dir, runs the agent there, then copies `result-<task_id>.md` back to the persistent workspace dir.
- [ ] Agent runs in an ephemeral runtime directory; persistent workspace is not used as cwd during execution.
- [ ] Config exposes PersistentWorkspaceDir and RuntimeWorkspaceDir; executor and server use them; no remaining single “workspaces” dir used for both upload and run.
- [ ] Tests cover: config path helpers; executor copy-in and copy-out behavior; server still serves uploads and files from persistent root.
