# Task 099: Add desktop app

## Goal

Add a **Wails-based desktop application** that provides a first-hand agent experience similar to the CLI, without requiring a backend server. This task covers only the **first step**: add the basics of the desktop app (scaffold, build, run, minimal window).

## Context

- **Existing entry points**: CLI/TUI (`cmd/buildmax`, `internal/cmd/cli`, `internal/tui`), server (`cmd/buildmax-server`), worker (`cmd/buildmax-worker`). CLI uses `internal/app/agentrun.Open()` and `internal/tui` for the agent chat loop; config via `internal/config` (e.g. `DataDir()`, `LoadLLM()`).
- **Choice of stack**: Wails (Go + frontend) aligns with the project’s all-Go backend and allows reusing `internal/app/agentrun`, `internal/session`, and `internal/config` from the same module.
- **Constraint**: Desktop app does not connect to the backend server in this task; it is a local, CLI-like experience.

## In scope

1. **New desktop app target**
   - Add a Wails application with **entrypoint** under **`cmd/buildmax-desktop/`** (consistent with `cmd/buildmax`, `cmd/buildmax-server`, `cmd/buildmax-worker`) and **implementation** under **`internal/cmd/desktop`** (same pattern as CLI → `internal/cmd/cli`, server → `internal/cmd/server`, worker → `internal/cmd/worker`). Same Go module (`buildmax`).
2. **Build and run**
  - The desktop app builds with Wails (e.g. `wails build`) and runs with `wails dev` or equivalent, producing a native window on macOS (primary; Windows/Linux can be best-effort in this task).
3. **Minimal UI**
  - A single window with a minimal frontend: e.g. app title “BuildMax” and a placeholder area for the future chat/agent UI (no full chat implementation in this task).
4. **Config and data path**
  - Desktop app uses the same application data semantics as the CLI: `BUILDMAX_HOME` / `config.DataDir()` for sessions and logs, so future agent integration uses the same paths.
5. **Make / docs / setup**
   - Document how to build and run the desktop app (e.g. in `README.md` or `cmd/buildmax-desktop/README.md`); optionally add `./make run desktop`. **Ensure `./make setup` installs Wails CLI** (e.g. in `setup/setup.sh`) so new developers get desktop tooling from one-click setup.

## Out of scope

- **Full chat/agent UI**: Implementing the actual agent conversation UI (message list, input, tool calls) in the desktop window. That will be a follow-up.
- **Backend server connection**: Sign-in, workspaces, or any portal/API integration.
- **Packaging and installers**: DMG, MSI, or distribution artifacts.
- **Cross-platform parity**: Ensuring identical behavior on Windows/Linux is not required for this task; macOS is enough for “basics.”

## Deliverables


| #   | Deliverable                               | Notes                                                                                                                          |
| --- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 1   | Wails app entrypoint + implementation    | `cmd/buildmax-desktop/main.go` (thin), `cmd/buildmax-desktop/wails.json`, `internal/cmd/desktop` (App, Run, Startup/Shutdown). |
| 2   | Frontend assets                           | Minimal HTML/JS (or Vue/React/Svelte if Wails template uses it) that show a window with “BuildMax” and a placeholder for chat. |

## Acceptance criteria

- Wails app builds successfully (`wails build` or project’s chosen command) from the repo root or a documented directory.
- Running the app in dev mode opens a native window with a minimal UI (title “BuildMax” and a visible placeholder for future chat).
- Desktop app code or startup uses `buildmax/internal/config` for application data directory (e.g. `config.DataDir()`) so BUILDMAX_HOME is respected.
- README or dedicated desktop doc describes how to build and run the desktop app; `./make setup` installs Wails CLI so new developers are ready; optional: `./make run desktop` works.
- No regression to existing CLI/server/worker builds or tests (`go build ./...` and `go test ./...` still pass; Wails-specific build can be separate).
