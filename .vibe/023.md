# Task 023 - Add Skill Tool

## Goal

Add a `Skill` tool that discovers skill files on disk and, when invoked, returns the skill's content so the LLM can follow its instructions — enabling the agent to use specialized workflows and domain knowledge during a session.

## Context

- **Existing tool pattern**: All tools implement `agent.Tool` (Name, Description, Parameters, Execute) in `internal/tools/`. They are constructed in `cmd/buildmax/root.go` → `setupAgentAndSession()` and passed to `agent.NewAgent`.
- **Similar precedent**: `TaskTool` dynamically builds its Description and Parameters from a map of agent types. The Skill tool will follow the same pattern — dynamically listing discovered skills in its Description.
- **Skill files already exist** in the project (e.g. `.cursor/skills/vibe/SKILL.md`). The tool needs a general discovery mechanism that scans known directories.
- **Convention**: Tools use `snake_case` for JSON parameter keys. Constructor returns `(*SkillTool, error)`.

## Skill (this task)

For this task, a "skill" is:

1. A directory containing a `SKILL.md` file.
2. The directory name is the skill's identifier (e.g. `vibe/SKILL.md` → skill name `vibe`).
3. The SKILL.md content is the skill's instructions, returned verbatim to the LLM when invoked.
4. A short description is extracted from the SKILL.md for listing purposes (first non-empty, non-heading line).

Skills are discovered from **search paths** — a list of directories to scan. Each search path is scanned one level deep for subdirectories containing `SKILL.md`.

We are **not** yet implementing:

- Namespaced / fully-qualified skill names (e.g. `ms-office-suite:pdf`)
- Skill creation, editing, or management commands
- Nested skill invocation detection or guards
- Skill caching or hot-reload (skills are scanned once at startup)

## Deliverables

1. **`internal/tools/skill.go`** — Skill tool implementation
   - **`SkillEntry`** struct: `Name string`, `Description string`, `Path string` (absolute path to SKILL.md).
   - **`SkillTool`** struct: holds discovered `[]SkillEntry` and a `map[string]SkillEntry` for lookup.
   - **`NewSkill(searchPaths []string) (*SkillTool, error)`**: Scans each search path for subdirectories containing `SKILL.md`. Builds the skill list. Returns error only for unexpected I/O issues (missing directories are silently skipped). If multiple search paths contain a skill with the same name, the first one found wins (search paths are priority-ordered).
   - **`Name() string`**: Returns `"Skill"`.
   - **`Description() string`**: Returns a static preamble explaining the tool, followed by a dynamic "Available skills:" list built from discovered entries (name + description).
   - **`Parameters() any`**: JSON schema with `skill` (string, required) and `args` (string, optional).
   - **`Execute(ctx, args) (string, error)`**: Looks up the skill by name, reads the SKILL.md file, and returns its content. If `args` is provided, prepends it as context (e.g. `"Arguments: <args>\n\n<content>"`). Returns an error if the skill is not found.

2. **`internal/tools/skill_test.go`** — Unit tests
   - Test skill discovery from a temp directory with valid and invalid skill dirs.
   - Test Execute with a known skill name returns file content.
   - Test Execute with unknown skill name returns an error.
   - Test search path priority (first path wins on name conflict).
   - Test that directories without SKILL.md are silently skipped.
   - Test description extraction (first non-empty, non-heading line).

3. **`cmd/buildmax/root.go`** — Wire the Skill tool
   - In `setupAgentAndSession()`, construct `SkillTool` with search paths: `[<cwd>/.buildmax/skills, <cwd>/.cursor/skills, ~/.buildmax/skills]`.
   - Add to `baseTools` slice so it's available to the main agent and sub-agents.

## Out of scope (for later)

- Namespaced skills (e.g. `package:skill` syntax)
- Skill management (create, edit, delete via CLI or TUI)
- Dynamic reload of skills mid-session
- Skill argument validation or structured argument schemas
- TUI skill picker or slash-command integration
- Recursive skill directory scanning (only one level deep)

## Acceptance

- [ ] `SkillTool` implements `agent.Tool` interface.
- [ ] Skills are discovered from configurable search paths at construction time.
- [ ] `Description()` dynamically lists all discovered skills with their descriptions.
- [ ] `Execute()` returns the full SKILL.md content for a valid skill name.
- [ ] `Execute()` returns a clear error for unknown skill names (listing available ones).
- [ ] `args` parameter is prepended to the returned content when provided.
- [ ] Search path priority: first path wins on name conflict.
- [ ] Missing search path directories are silently skipped (no error).
- [ ] Unit tests pass: `go test ./internal/tools/...`
- [ ] Build succeeds: `go build ./...`
- [ ] Tool is wired in `setupAgentAndSession` and available to the agent.
