# Task 043 - Upload file to workspace

## Goal

Add an API endpoint for uploading files to a workspace directory on disk, and wire it into the portal's Explore page with a simple upload button — making Explore the first sidebar item.

## Context

- Workspaces already have on-disk directories at `config.WorkspacesDir()/<workspace_id>/` (created in `internal/server/workspaces.go` via `ensureWorkspaceDirs`).
- The server (`internal/server/`) uses `net/http` + `http.ServeMux`, JWT auth via `userIDFromRequest()`, and workspace ownership checks via `store.WorkspaceBelongsToUser()`.
- Existing route pattern: `POST /api/workspaces/{workspace_id}/...` (e.g. projects, tasks).
- The portal Explore page (`portal/src/pages/ExplorePage.tsx`) exists with mock data and a folder/file tree. The sidebar (`portal/src/components/LeftSidebar.tsx`) lists Explore as the third item.
- Portal API client: `portal/src/lib/api.ts` — all functions follow the same pattern: `fetch(url, { headers: { Authorization: Bearer token } })`.

## Upload (this task)

For this task, "upload file to workspace" means:

1. A new `POST /api/workspaces/{workspace_id}/upload` endpoint accepting `multipart/form-data` with a `files` field
2. The endpoint saves uploaded files to the workspace directory on disk
3. The portal Explore page gets an "Upload" button that calls this endpoint
4. The Explore sidebar item moves to the first position

We are **not** yet implementing:

- Browsing or viewing workspace files from the API (the Explore page keeps its mock tree as-is for now)
- File deletion, renaming, or directory creation via API
- File size limits enforcement (beyond Go's default `multipart.MaxBytesReader` — can add later)
- Subdirectory targeting (files go to the workspace root)

## Deliverables

1. **`internal/server/upload.go`** — new file
   - Handler for `POST /api/workspaces/{workspace_id}/upload`
   - Accepts `multipart/form-data`; field name `files` (multiple files)
   - Validates: JWT auth, workspace belongs to user, at most 10 files per request
   - Saves each file to `config.WorkspacesDir()/<workspace_id>/<original_filename>`
   - Returns JSON: `{ "uploaded": ["file1.txt", "file2.png"] }` on success
   - Returns JSON error on failure (401, 403, 400 for >10 files or missing field, 500 for I/O)

2. **`internal/server/server.go`** — register route
   - Add `POST /api/workspaces/{workspace_id}/upload` to the mux, wired to the upload handler

3. **`portal/src/lib/api.ts`** — new function
   - `uploadFiles(workspaceId: string, files: File[], token: string): Promise<{ uploaded: string[] }>`
   - Builds `FormData`, attaches files under field name `files`, sends as `multipart/form-data`
   - Note: do **not** set `Content-Type` header manually — let the browser set it with the boundary

4. **`portal/src/pages/ExplorePage.tsx`** — add upload button
   - Add an "Upload Files" button (or area) that opens a file picker (`<input type="file" multiple>`)
   - On selection, calls `uploadFiles()` and shows a brief success/error message
   - Keep the existing mock tree/viewer untouched

5. **`portal/src/components/LeftSidebar.tsx`** — reorder sidebar
   - Move the Explore item to the first position in `SIDEBAR_NAV`

## Out of scope (for later)

- Listing workspace files via API (GET endpoint)
- File viewing/download API
- Upload progress indicators
- Drag-and-drop upload
- Subdirectory targeting or nested folder uploads
- Duplicate filename handling (overwrite is acceptable for now)
- File size or type restrictions

- [ ] Request with >10 files returns 400 with an error message
- [ ] Unauthenticated request returns 401; wrong workspace owner returns 403
- [ ] Portal Explore page has an upload button; selecting files triggers the upload API call
