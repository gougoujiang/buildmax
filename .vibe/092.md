# Task 092: Two-tier agent — Phase 2 — Portal as ChannelAdapter and pass-through engine

Wire the portal chat flow through Tier 1: portal becomes the first `ChannelAdapter`; the conversation engine is pass-through (every message spawns one Tier 2 run). No Tier 1 LLM call.

**Design:** [design/007-two-tier-agent.md](../design/007-two-tier-agent.md) §8 Phase 2. Depends on Phase 1 (091).

**Deliverables:**
- Portal adapter: implements `ChannelAdapter`; `Receive` builds `ConversationTurn` from HTTP request (channel=portal, workspace/chat/user from auth/path); `Send` streams or returns reply to client (reuse existing stream/response behavior).
- Pass-through conversation engine: implements `ConversationEngine`; `Process` always creates one chat run with `turn.Message` as input and returns its `chat_run_id` in `ConversationResult.TaskIDs`; no conversation history, no LLM.
- Server: create-chat or create-run flow (as appropriate) goes through adapter + engine instead of directly creating runs. Existing API contract (create chat, create run, stream) preserved; only the internal path uses Tier 1.
- Tests: handler or integration test that a portal request results in one Tier 2 run with correct input.

**Out of scope:** Tier 1 LLM conversation or multi-turn history (Phase 3).
