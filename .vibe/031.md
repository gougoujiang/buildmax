# Task 031: Portal landing page

## Goal

Implement the **wireframe landing page** from `design/001-about-portal.md` (§7) in the existing Portal app: a single-screen entry with header, prompt area (“What would you like to accomplish?”), and a Recent Activity section, using static/mock data and no backend.

## Context

- **Portal today**: `portal/` is a React + Vite + TypeScript app with a minimal “BuildMax Portal” title and one line of text (`portal/src/App.tsx`). No layout or wireframe structure.
- **Design reference**: `design/001-about-portal.md` describes an AI-native workspace (intent-first, agent-mediated). Section 7 defines the **Landing Page** wireframe:
  - **Header**: App name/branding (design uses “Nexus”; we use “BuildMax Portal” to match the product), workspace label (e.g. “Workspace: Sales Team”), and a Profile/settings entry.
  - **Main**: Centered prompt area — heading “What would you like to accomplish?”, one text input, and a “Run” button.
  - **Bottom**: “Recent Activity” section with a list of items (e.g. “Generated sales report (Today 10:42 AM)”).
- **Convention**: Portal is independent of the Go binary; no API or backend in this task.

## In scope

- **Layout**: One landing view that matches the wireframe structure (header, prompt block, recent activity).
- **Header**: App title (“BuildMax Portal” or “Portal”), workspace label (static text, e.g. “Workspace: Default” or “Workspace: Sales Team”), and a visible Profile/settings entry (text or icon; no navigation or modal required).
- **Prompt area**: Heading “What would you like to accomplish?”, a single text input, and a “Run” button. Input and button can be controlled in React state; Run may be a no-op (e.g. log or placeholder) — no API call.
- **Recent Activity**: Section heading “Recent Activity” and a list of **mock** items (e.g. 3–5 items), each with a short title and a timestamp or relative time. No backend or real data.
- **Styling**: Clear separation of sections, readable typography, and layout that fits the wireframe (e.g. max-width container, spacing). Reuse or extend existing `portal` CSS (e.g. `index.css`, `App` class); no new design system or dependencies required.
- **Scope of code**: Changes only under `portal/` (e.g. `App.tsx`, possibly new components or `index.css`). No changes to Go code or `portal/README.md` unless needed for accuracy (e.g. one-line note that the landing is the wireframe).

## Out of scope

- Backend, API, or Go HTTP server; real workspace or real recent activity data.
- Profile/settings functionality (modal, page, or persistence).
- Submitting the prompt to the agent or any chat/run flow.
- Chat UI, session list, or API integration with the BuildMax backend.
- Production deployment, embedding assets in the Go binary, or Docker.

## Acceptance criteria

- [ ] Landing page has a **header** with app name, workspace label (static), and Profile/settings entry (visible, non-functional).
- [ ] **Prompt area** is present with the heading “What would you like to accomplish?”, one text input, and a “Run” button; Run may be no-op.
- [ ] **Recent Activity** section shows a list of mock items (each with title and timestamp/relative time).
- [ ] Layout and sections match the wireframe in `design/001-about-portal.md` (§7); styling is consistent and readable.
- [ ] `npm run build` and `npm run dev` in `portal/` still work; app renders the new landing without errors.
- [ ] No backend or API; all data is static/mock. Go build and tests unchanged.
