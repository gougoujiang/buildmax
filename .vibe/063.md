# Task 063: Add ingress controller to kind

## Goal

Enable Ingress-based access to services in the kind cluster used by `./make setup`, so local dev and future in-cluster testing resemble production (single entry point via Ingress).

## Context

- **Existing setup**: `setup/setup.sh` is the one-click entry (idempotent). It creates a kind cluster from `setup/kind-config.yaml`, adds MinIO, MySQL, port-forwards, and a test job. `./make setup` / `./make unsetup` invoke it.
- **Kind config**: `setup/kind-config.yaml` currently defines one control-plane and one worker; no Ingress-related port mapping yet.
- **Convention**: Setup steps are idempotent (skip if already present). New developers run `./make setup` to get a working environment.

## Ingress controller (this task)

For this task we add:

1. **ingress-nginx** as the Ingress controller, using the official kind-specific manifest: `kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/main/deploy/static/provider/kind/deploy.yaml`.
2. **Kind cluster configuration** so host ports 80 and 443 are mapped from the node (control-plane) to the host, and the control-plane node is labeled `ingress-ready=true` so the kind deploy.yaml can target it.
3. **Local DNS**: Document that users should add `127.0.0.1 <host>.kind.local` to `/etc/hosts` for each Ingress host they use (e.g. `buildmax.kind.local`). Standard `/etc/hosts` does not support wildcards; we provide at least one example and mention it in setup output or README.

We are **not** yet implementing:

- Ingress resources for Portal or buildmax-server (only the controller).
- TLS/certificates or production Ingress configuration.
- Automatically modifying the user’s `/etc/hosts` file (documentation only).

## Deliverables

1. **Kind cluster config**
   - **File**: `setup/kind-config.yaml`
   - Add to the control-plane node: `extraPortMappings` for containerPort/hostPort 80 and 443 (TCP), and a `kubeadmConfigPatches` block so the node has label `ingress-ready=true`.
   - Document in setup or in a short comment that an **existing** cluster created before this change will not have these ports; users should run `./make unsetup` then `./make setup` to recreate the cluster with Ingress support.

2. **Setup script**
   - **File**: `setup/setup.sh`
   - New idempotent step (e.g. `ensure_ingress`) that:
     - Applies the ingress-nginx kind manifest from the official URL above.
     - Waits for the ingress-nginx controller to be ready (e.g. `kubectl wait` for the relevant deployment in the `ingress-nginx` namespace).
   - Call this step from `main` after `ensure_kind_cluster` (and before or after other steps as appropriate).
   - In the final “Setup done” log, add a line that tells the user to add a line like `127.0.0.1 buildmax.kind.local` to `/etc/hosts` for Ingress hostnames.

3. **Documentation**
   - Either in `setup/README.md` (if it exists) or in the setup script’s log output: state that for Ingress hostnames under `*.kind.local`, the user should add one line per host in `/etc/hosts`, e.g. `127.0.0.1 buildmax.kind.local`. No automated edit of `/etc/hosts`.

## Out of scope (for later)

- Creating Ingress resources for Portal or buildmax-server.
- TLS or certificate provisioning for Ingress.
- Changing unsetup to remove only the ingress controller (unsetup continues to tear down the whole cluster).
- Wildcard DNS or dnsmasq for `*.kind.local`.

## Acceptance

- [ ] `setup/kind-config.yaml` includes control-plane `extraPortMappings` for 80 and 443 and node label `ingress-ready=true`.
- [ ] `setup/setup.sh` has an idempotent step that applies the ingress-nginx kind manifest and waits for the controller to be ready.
- [ ] After `./make setup`, `kubectl get pods -n ingress-nginx` shows the controller running; no manual steps required beyond running setup.
- [ ] Setup output or README instructs the user to add at least one `/etc/hosts` line (e.g. `127.0.0.1 buildmax.kind.local`) for Ingress hostnames.
- [ ] Documented that existing clusters created before this change need `./make unsetup` then `./make setup` to get Ingress port mapping.
