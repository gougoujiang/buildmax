# Task 025 - Refactor root.go — smell proposals

## Goal

Refactor `cmd/buildmax/root.go` to eliminate code smells identified in `.vibe/smell-20260214.md`: extract tool construction and agent-type wiring into dedicated functions, introduce a result struct, remove duplicate config load, and fix inconsistent error handling.

## Context

- `cmd/buildmax/root.go` is the CLI wiring file (297 lines). Its central function `setupAgentAndSession` (143 lines) handles config loading, tool construction, agent-type configuration, session directory creation, and session loading — too many responsibilities.
- Nine tool constructors follow an identical 5-line error-handling pattern (~50 lines of boilerplate).
- `config.LoadLLM()` is called twice: once inside `setupAgentAndSession` and again in `runTUI`.
- `runRoot` uses `os.Exit(1)` for prompt-mode errors while the TUI path returns errors normally.
- The function returns a 5-value tuple `(agent, session, sessionsDir, cwd, error)`.

## Refactoring (this task)

For this task, "refactoring" means restructuring `root.go` without changing external behavior:

1. Extract tool construction into `buildBaseTools`
2. Extract agent-type wiring into `buildAgentTypes`
3. Introduce `setupResult` struct replacing the 5-value return tuple, carrying `ModelName` to eliminate the duplicate `config.LoadLLM()` call
4. Remove `os.Exit(1)` in `runRoot`, return the error instead
5. Update callers (`runTUI`, `runPromptMode`) to use `setupResult`

We are **not** implementing:

- Moving code out of `cmd/` into `internal/`
- Changing tool constructor signatures in `internal/tools/`
- Adding new tests (existing tests cover behavior; this is a pure refactor)

## Deliverables

1. **`cmd/buildmax/root.go`**
   - **`setupResult` struct**: Fields `Agent`, `Session`, `SessionsDir`, `CWD`, `ModelName`.
   - **`buildBaseTools` function**: Constructs all 9 base tools, returns `([]agent.Tool, map[string]agent.Tool, error)`.
   - **`buildAgentTypes` function**: Defines built-in types, loads and merges user-defined agents, returns `(map[string]tools.AgentTypeConfig, error)`.
   - **`setupAgentAndSession`**: Slimmed to orchestrate `buildBaseTools` → `buildAgentTypes` → `NewTask` → `NewAgent` → session setup, returning `setupResult`.
   - **`runRoot`**: `os.Exit(1)` removed; prompt-mode error returned normally.
   - **`runTUI` / `runPromptMode`**: Use `setupResult` fields; no second `config.LoadLLM()` call.

2. **Verification**
   - `go build ./...` passes.
   - `make.bat test` passes (behavior unchanged).

## Out of scope (for later)

- Table-driven tool construction with closures (constructors have heterogeneous signatures; not worth the abstraction cost for 9 items)
- Moving setup logic into an `internal/` package
- Adding unit tests for the new helper functions (they are wiring code, not logic)
