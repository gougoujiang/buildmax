# Task 054: Display artifacts

## Goal

Display artifacts (task-run outputs) in the portal so users can see and access them. Add backend APIs to list artifacts and to serve artifact file content; add UI sections on the Projects page, Project page, and Activity page that list recent artifacts, with optional columns (workspace_id, task_id, project_id, artifact_id) for quick reference.

## Context

- **Task 053** introduced the artifact concept: each successful task run produces one artifact stored under `ArtifactDir(workspaceID, taskID, artifactID)` (e.g. `result.md`). The `artifact` and `artifact_item` tables record them; `task.last_artifact_id` points to the latest. No HTTP API exists yet to list or read artifacts.
- **Portal today**: Projects page shows projects and a prompt; Project page shows one project and its tasks under "Activity"; Activity page lists workspace tasks (with project name and time). Tasks come from `GET /api/workspaces/{id}/tasks`; `TaskResponse` does not include artifact info.
- **Store**: `ArtifactStore` only has `CreateArtifactWithItem`. `Task` has `LastArtifactID`. Listing artifacts requires joining `artifact` with `task` (task has `workspace_id`, `project_id`).
- **Conventions**: AGENTS.md — snake_case for JSON and persisted data; singular table names; server in `internal/server`, store in `internal/store`, portal under `portal/`.

## In scope

1. **Backend — store**
   - Add a way to list artifacts in a workspace with optional filters. Options: extend `ArtifactStore` with `ListArtifactsByWorkspace(ctx, workspaceID string, taskID *string, projectID *string) ([]ArtifactRow, error)` where `ArtifactRow` (or similar) includes artifact_id, task_id, workspace_id, project_id, created_at, seq, and a short task input snippet (e.g. first 200 chars of task.input) for display. Implement by querying artifact joined with task on task_id, filtering by task.workspace_id and optionally task_id/project_id, ordering by created_at desc.

2. **Backend — server**
   - `GET /api/workspaces/{workspace_id}/artifacts`: optional query params `task_id`, `project_id`. Require workspace auth. Return JSON array of artifact summaries (snake_case): artifact_id, task_id, workspace_id, project_id, created_at, seq, task_input_snippet (or task_input).
   - `GET /api/workspaces/{workspace_id}/artifacts/{artifact_id}/content`: require workspace auth; resolve artifact by artifact_id, verify task belongs to workspace; stream or return the artifact’s result file (e.g. `result.md` from `ArtifactDir(workspaceID, taskID, artifactID)`) as text/plain or text/markdown. Return 404 if artifact not found or not in workspace.

3. **Portal — API and types**
   - Add `getArtifacts(workspaceId, token, options?: { projectId?, taskId? })` and `getArtifactContent(workspaceId, artifactId, token)` in `portal/src/lib/api.ts`. Add `ApiArtifact` (or similar) type with artifact_id, task_id, workspace_id, project_id, created_at, seq, task_input_snippet. Map to a UI-facing `Artifact` type if needed (id, taskId, projectId, workspaceId, timeLabel, title/snippet).

4. **Portal — UI**
   - **Projects page**: Add an "Artifacts" (or "Recent artifacts") section that lists recent artifacts for the workspace. Include columns or metadata for quick query: workspace_id, task_id, project_id, artifact_id (e.g. in a table or card footer). Link each artifact to the task detail and/or to a way to view artifact content.
   - **Project page**: List artifacts for that project (filter by project_id). Same idea: show artifact rows with key ids and link to view content or task.
   - **Activity page**: List artifacts in addition to (or integrated with) tasks. User requested "list all activities and artifacts" — e.g. a subsection "Artifacts" or a combined list with type (task vs artifact) and columns workspace_id, task_id, project_id, artifact_id where useful.
   - **Viewing content**: Allow the user to open an artifact and see its content (e.g. fetch via `getArtifactContent` and show in a modal or inline; or navigate to task detail and show latest artifact there). Minimal: link to task detail (task already has output/summary); better: dedicated "View artifact" that loads and renders artifact content (markdown).

5. **Task list response (optional enhancement)**
   - Optionally include `last_artifact_id` (and maybe artifact count) in task list response so the UI can show "has artifact" without a separate artifacts call. In scope only if simple (add field to `TaskResponse` and taskToResponse).

## Out of scope

- Deleting or editing artifacts.
- Multiple files per artifact in the UI (artifact_item list); single result file per artifact is enough.
- Changing executor or store artifact creation (task 053).
- Migration of existing data.

## Deliverables

- **Store**: `ListArtifactsByWorkspace(ctx, workspaceID string, taskID, projectID *string) ([]ArtifactWithTask, error)` (or equivalent name) returning rows with artifact_id, task_id, workspace_id, project_id, created_at, seq, task_input snippet. Implementation: join artifact + task, filter by workspace and optional task_id/project_id.
- **Server**: `GET /api/workspaces/{workspace_id}/artifacts` (query task_id, project_id); `GET /api/workspaces/{workspace_id}/artifacts/{artifact_id}/content` returning artifact file content with auth. New handler file or add to existing (e.g. artifacts.go).
- **Portal**: API client `getArtifacts`, `getArtifactContent`; types for artifact; Projects page "Artifacts" section; Project page artifacts list; Activity page artifacts (or combined activities). Tables/cards show workspace_id, task_id, project_id, artifact_id for quick query. User can view artifact content (modal or inline).
- **Optional**: Task API response includes `last_artifact_id` for convenience.

## Acceptance criteria

- [ ] Backend: `ListArtifactsByWorkspace` returns artifacts in the workspace, filterable by task_id and project_id; each row includes artifact_id, task_id, workspace_id, project_id, created_at, seq, and a task input snippet.
- [ ] Backend: `GET /api/workspaces/{id}/artifacts` returns a JSON list of artifact summaries with correct auth and optional filters.
- [ ] Backend: `GET /api/workspaces/{id}/artifacts/{artifact_id}/content` returns the artifact result file content (e.g. result.md) with workspace auth; 404 when artifact not found or not in workspace.
- [ ] Portal: Projects page has an Artifacts section listing recent workspace artifacts with key ids (workspace_id, task_id, project_id, artifact_id) visible for quick query.
- [ ] Portal: Project page lists artifacts for that project with key ids.
- [ ] Portal: Activity page lists artifacts (e.g. in a subsection or combined list) with key ids.
- [ ] User can open an artifact and view its content (e.g. modal or inline markdown).
