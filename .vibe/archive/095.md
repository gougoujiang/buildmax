# Task 095: Tier 1 agent — chat management tools and system prompt

Enrich the Tier 1 (conversation) agent with tools to list and inspect chats, continue an existing chat with a follow-up, and optimize its system prompt. Tier 1 / Tier 2 architecture is already implemented; this task adds ListChats (recent 10), GetChat (detail), ContinueChat (follow-up on existing chat), and improves the Tier 1 system prompt. Tool names use camel case to align with existing ones (e.g. StartChat).

---

## Goal

Give the Tier 1 agent the ability to list recent chats, get chat details, and continue an existing chat with a follow-up message, so it can answer user questions and act on follow-ups (e.g. "what chats did I start?", "what's the status of chat c_xyz?", "add this to that chat"). Improve the Tier 1 system prompt so the agent acts as a coordinator, prefers continuing an existing chat when appropriate, and has recent chat context injected into the prompt.

## Context

- **Tier 1 loop** lives in `internal/conversation`: `RunLoop` / `RunLoopStream` use `systemPrompt` and tools built via `buildConversationTools(workspaceID, userID, startChatRunner)`.
- **Existing Tier 1 tool**: `StartChat` in `internal/tools/start_chat.go`, wired via `StartChatRunner`; app layer provides the runner from `internal/app/conversation` (e.g. `startChatRunner(workspaceID, userID, conversationID)`).
- **Chat data**: `entity.ChatStore` has `ListChatsByWorkspacePaginated(ctx, workspaceID, executedOnly, limit, offset)` and `GetChat(ctx, chatID)`. Chats are workspace-scoped; Tier 1 tools must only expose data for the current workspace.
- **Tool pattern**: New tools will follow the same pattern as StartChat: interface + runner in `internal/tools`, built when constructing conversation tools; server/app layer injects runners that use `ChatStore` (or app/chat service).

## In scope

1. **ListChats tool** (camel case, aligned with StartChat)
   - Lists recent chats in the current workspace. At most 10, ordered by created_at DESC (most recent first).
   - No parameters (or optional `limit` capped at 10). Returns a short summary per chat: chat_id, title (or input snippet), created_at, status, last_run_id (if any) — enough for the LLM to answer "what are my recent chats?".
   - Implemented via a runner interface (e.g. `ListChatsRunner`); app/server provides the implementation using `ChatStore.ListChatsByWorkspacePaginated(workspaceID, false, 10, 0)`.

2. **GetChat tool**
   - Returns detail for one chat by chat_id. Parameters: `chat_id` (required).
   - Workspace-scoped: if the chat does not belong to the current workspace, return a clear error (e.g. "chat not found or not in this workspace").
   - Returns: chat_id, title, input (possibly truncated for token safety), status, created_at, last_run_id, and optionally a brief run status or output snippet so the agent can say "this chat succeeded" or "still running", etc.

3. **ContinueChat tool**
   - Continues an existing chat with a follow-up message. Use case: user is not satisfied with a chat result and wants to send a follow-up (e.g. "add this to chat c_xyz", "run again with different input").
   - Parameters: `chat_id` (required), `input` (required — the follow-up message/instruction).
   - Creates a new run for that chat (same as "add message" / CreateRun flow). Workspace-scoped: return clear error if chat not in workspace. Returns run_id and a short confirmation so the agent can tell the user the follow-up was scheduled.

4. **Tier 1 system prompt optimization**
   - Replace or extend the current `systemPrompt` in `internal/conversation` so that:
     - **Role**: Tier 1 agent is a **coordinator** between the user and background chat tasks (not just an assistant that can start chats).
     - **Decision order**: First evaluate whether the user’s request should **continue an existing chat** rather than creating a new one (e.g. follow-up, "try again", "add to that chat"). Prefer ContinueChat when the user refers to an existing chat.
     - **Tool usage**: GetCurrentDate, StartChat, ListChats, GetChat, ContinueChat — when to use each. Guidelines: reply concisely; when starting a background task, always tell the user the chat id and where to check progress; when the user asks about recent or specific chats, use ListChats or GetChat and summarize.
     - **Recent context**: Inject the **latest 5 chats** (simplified info: chat_id, title/snippet, status, created_at) into the system prompt so the Tier 1 agent knows the situation without calling ListChats first when making decisions. The prompt is built per turn (or per conversation) and includes a short "Recent chats in this workspace" block when available.

## Out of scope

- Phase 5 task decomposition (multiple ChatRuns per turn); that was the original 095 scope and is explicitly out of scope.
- Pagination beyond "recent 10" for ListChats (no offset/limit in tool params for now).
- Exposing run artifacts or full run history from GetChat (only chat-level and last-run summary).
- Changes to the portal UI or API for chats (backend/tools only).

## Deliverables

1. **internal/tools**
   - New tool implementations with **camel-case names**: ListChats, GetChat, ContinueChat (e.g. `list_chats.go`, `get_chat.go`, `continue_chat.go` or a combined conversation_tools file), with runner interfaces and `NewListChatsTool(workspaceID, runner)`, `NewGetChatTool(workspaceID, runner)`, `NewContinueChatTool(workspaceID, userID, runner)`.
   - Tool names in `internal/tools/names.go`: `ToolNameListChats`, `ToolNameGetChat`, `ToolNameContinueChat`.
   - Tool builder extended so callers can pass list/get/continue runners and get the full set (GetCurrentDate, StartChat, ListChats, GetChat, ContinueChat).

2. **internal/conversation**
   - Tool builder extended to accept optional ListChats, GetChat, and ContinueChat runners and add the new tools when provided.
   - **System prompt**: Updated with coordinator role, decision order (prefer continue existing chat when appropriate), and tool usage (GetCurrentDate, StartChat, ListChats, GetChat, ContinueChat).
   - **Recent chats injection**: RunLoop/RunLoopStream (or their call site) accept an optional "recent chats" snippet (e.g. a string or a function `func(ctx, workspaceID) string`). When provided, append a short "Recent chats in this workspace (latest 5): ..." block to the system prompt so the agent has context without calling ListChats first.

3. **internal/app/conversation**
   - Service creates ListChats, GetChat, and ContinueChat runners (using `ChatService`/`ChatStore` for list/get; `ChatService.CreateRun` for ContinueChat), and passes them into the conversation layer.
   - When building the turn, fetch latest 5 chats for the workspace, format as simplified lines (chat_id, title/snippet, status, created_at), and pass into the conversation layer so the system prompt includes the recent chats block.

4. **Tests**
   - Unit tests for the new tools (nil runner, missing args, success, workspace-scoped GetChat/ContinueChat rejection) in `internal/tools`.
   - No new API or HTTP tests required unless we add a dedicated integration test; existing conversation flow can be tested manually.

## Acceptance criteria

- [ ] Tier 1 agent has **ListChats** tool (camel case) that returns at most 10 recent chats in the current workspace (chat_id, title/snippet, created_at, status, last_run_id).
- [ ] Tier 1 agent has **GetChat** tool that returns one chat’s detail by chat_id; returns a clear error if chat is not in the current workspace.
- [ ] Tier 1 agent has **ContinueChat** tool (chat_id, input) that creates a new run for an existing chat; workspace-scoped with clear error when chat not in workspace.
- [ ] Tier 1 system prompt states the agent is a **coordinator** between user and background chats; instructs to **evaluate continue vs new first** (prefer ContinueChat when user refers to an existing chat); describes GetCurrentDate, StartChat, ListChats, GetChat, ContinueChat.
- [ ] Latest **5 chats** simplified info is injected into the system prompt each turn so the agent has recent context without calling ListChats first.
- [ ] Conversation turn (portal or test) can call ListChats, GetChat, and ContinueChat and receive LLM-friendly results; build and tests pass.
