# Task 006 - Default system prompt

## Goal

When the agent runs (`Process`), prepend a default system message so the LLM receives a clear role declaration for the assistant (e.g. "You are a helpful AI assistant.") and behaves consistently.

## Context

- **`internal/agent`**: `Process(ctx, userMessage)` builds `messages` with only the user message, then calls `caller.ChatWithTools(ctx, messages, a.toolDefs)`. No system message is sent today.
- **`internal/llm`**: `Message` already supports `Role: "system"` (see `types.go`). `Client.ChatWithTools` forwards all messages to the API; OpenAI-compatible APIs accept a system role.
- **`internal/config`**: No system-prompt or role config today; this task uses an in-code default only.
- Task docs live in **`tasks/`**; build/test: `./make build`, `./make test`.

## Default system prompt (this task)

For this task:

1. **Default system prompt** = a single system message prepended to every `Process` run. Its content is one short sentence that declares the assistant’s role (e.g. "You are a helpful AI assistant." or "You are BuildMax, a helpful AI assistant."). Exact wording is left to the implementer; it must be non-empty and role-oriented.
2. **Placement**: The first element of `messages` passed to `ChatWithTools` must be this system message; then the user message; then any assistant/tool messages from the loop.
3. **Source**: The text is a constant (or package-level variable) in `internal/agent`. No config file or env override in this task.

We are **not** in this task:

- Adding a configurable system prompt (config file, env var, or CLI flag).
- Multiple system messages or dynamic system content.
- TUI display of the system prompt.

## Deliverables

1. **`internal/agent`**
   - **Default system prompt constant**: Define a package-level constant (e.g. `DefaultSystemPrompt`) holding the default role text (one short sentence). Export it so tests can assert on it.
   - **Process change**: When building `messages` at the start of `Process`, set `messages` to `[]llm.Message{ {Role: "system", Content: DefaultSystemPrompt}, {Role: "user", Content: userMessage} }` (or equivalent), so the first message sent to the LLM is always the system message, then the user message. The rest of the loop (appending assistant/tool messages) is unchanged.

2. **Tests**
   - **Unit test**: Add a test that verifies the first message passed to the LLM in a `Process` run has `Role == "system"` and `Content == DefaultSystemPrompt`. This can be done by a mock that records the `messages` slice on the first `ChatWithTools` call and asserting on `messages[0]`. Reuse or extend the existing `mockLLMCaller` pattern in `agent_test.go` (e.g. a wrapper or a new test that checks the recorded messages).

3. **Dependencies**
   - No new external dependencies; no changes to `internal/llm` or `internal/config` required beyond using existing `Message` and `Role` semantics.

## Out of scope (for later)

- Configurable system prompt (config file, env, or CLI).
- Multiple or conditional system messages.
- TUI display of system prompt or role.

## Acceptance

- [ ] **Constant**: `internal/agent` defines an exported default system prompt constant (e.g. `DefaultSystemPrompt`) with a short, role-declaring sentence.
- [ ] **Process**: The first message in every `ChatWithTools` call from `Process` is a system message with that default content; the second is the user message.
- [ ] **Unit test**: A test in `agent_test.go` verifies that on the first LLM call, `messages[0].Role == "system"` and `messages[0].Content == DefaultSystemPrompt`.
- [ ] **Build and test**: `./make build` and `./make test` pass.
