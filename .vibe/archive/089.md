# Task 089: Misc UX improvement

## Goal

Improve portal UX in two areas: the "See all" chats page (simplify and show agent context) and the "new chat from agent" flow (show the initial task message immediately so it feels like user-started chat).

## Context

- **Chats page** (`route.name === "chats"`): Rendered by `Chats.tsx`; reached via sidebar "See all". Currently shows "All chats and artifacts in this workspace" with a chat list and a separate artifacts section. Chats come from `useWorkspaceData` → `useWorkspaceChats` → `getChats`; API already returns `agent_id` on chat when set (task 088).
- **New chat from agent**: In `AgentList.tsx`, "New chat" opens a modal; on confirm, `createChat(workspaceId, { agent_id, input }, token)` is called, then `setPendingChat({ chat: apiChatToChat(chat), initialInput: "" })` and navigate to the chat. Backend stores the composed task (agent name, description, instructions) in `chat.input`. Because `initialInput` is `""`, the chat detail view shows blank content until the session loads after the run completes; the desired behavior is to show the first user message (the composed input) immediately and stream the agent response, like the regular "New chat" flow which passes the user's input as `initialInput`.
- **Types**: `ApiChat` has `agent_id?: string | null`; `Chat` in `lib/types.ts` has no agent field; `apiChatToChat` in `lib/api/mappers.ts` does not map `agent_id`.

## In scope

1. **Chats page ("See all")**
   - Remove the artifacts section from the Chats page so the page shows only the chat list (and empty state when no chats). Artifacts remain available from workspace home, New Chat tabs, and artifact modal where already present.
   - In the chat list, show which agent a chat is from when the chat has an agent (i.e. was started from an agent). This requires: (a) adding `agentId` (and optionally `agentName`) to the `Chat` type and mapping it in `apiChatToChat` from `ApiChat.agent_id`; (b) on the Chats page, resolving agent id to name (e.g. by fetching workspace agents with existing `getAgents`) and displaying it (e.g. in the meta line or subtitle for each chat row).

2. **New chat from agent — immediate first message**
   - When starting a new chat from an agent, pass the created chat’s `input` (from the create-chat API response) as `initialInput` in `setPendingChat`, so the chat detail view shows the first user message (the task context) immediately instead of blank content. Agent response continues to stream in as today. Change in `AgentList.tsx` (and any other place that creates a chat with `agent_id` and navigates to it): use `chat.input` (or a display-safe snippet if needed) for `initialInput` instead of `""`.

## Out of scope (for later)

- Backend changes to include `agent_name` in chat list responses (frontend can resolve via `getAgents`).
- Changing artifact access or removal from other pages (workspace home, New Chat).
- CLI/TUI UX improvements.

## Deliverables

1. **Portal — Chats page**
   - Remove artifacts section from `Chats.tsx` (no artifact list, no artifact-related props needed for this page from the router). Subtitle can be updated to "All chats in this workspace" (or similar).
   - Extend `Chat` type in `lib/types.ts` with optional `agentId?: string`. Map `agent_id` in `apiChatToChat` to `agentId`.
   - In `Chats.tsx`, fetch workspace agents (e.g. `getAgents(workspaceId, token)`) when showing the list; for each chat with `agentId`, resolve to agent name and display it (e.g. under the title or in the meta line: "Agent: …").

2. **Portal — New chat from agent**
   - In `AgentList.tsx`, when calling `setPendingChat` after creating a chat with an agent, set `initialInput` to the created chat’s `input` from the API response (e.g. `chat.input ?? ""`) so the first message appears immediately in `ChatDetail`.

3. **Consistency**
   - If an agent detail page or any other component creates a chat with `agent_id` and navigates to the chat view, it should also pass the created chat’s `input` as `initialInput` (same pattern as above).

## Acceptance

- [ ] Chats page ("See all") no longer shows an artifacts section; page shows only the chat list and empty state when there are no chats.
- [ ] Chats page chat list shows agent context (e.g. agent name) for chats that have an agent (agent_id set); chats without an agent display unchanged.
- [ ] Starting a new chat from an agent (AgentList "New chat") navigates to the chat and shows the first user message (composed task) immediately; agent response streams in afterward, matching the behavior of starting a chat with a direct query from New Chat.
- [ ] `Chat` type and `apiChatToChat` include `agentId` when the API returns `agent_id`; no regression for chats without an agent.
