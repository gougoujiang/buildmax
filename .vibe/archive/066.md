# Task 066: Separate log file for worker and server

## Goal

Use distinct log file names for the server and worker binaries so operators can inspect server and worker logs separately; the CLI binary continues to use the existing single log file. Additionally, server and worker send logs to stdout for easier collection in containers/orchestrators; the CLI stays file-only because stdout is captured as the agent response. When uploading the runtime workspace after a task, also upload the worker’s log file so both agent and worker logs are available in storage.

## Context

- **Current behavior**: All three entry points (CLI `buildmax`, `buildmax-server`, `buildmax-worker`) call `log.Init()`, which always writes to `config.LogsDir()/buildmax.log`. Same file is used regardless of binary.
- **Relevant code**: `internal/log` has a constant `logFilename = "buildmax.log"` and `Init()` uses it with `config.LogsDir()`. No way to pass a different name today. All three `cmd/*/main.go` call `log.Init()` with no arguments.
- **Conventions**: Logging is currently file-only for all binaries; level from `BUILDMAX_LOG_LEVEL`; Lumberjack rotation (10MB, 3 backups, 7 days, compress). See AGENTS.md and `.vibe/kb/log.md`. This task adds optional stdout for server/worker only.

## Scope

### In scope

- **`internal/log`**: Allow the log file name and output targets to be chosen per process.
  - Change the API so the caller can specify the filename (e.g. `Init(filename string)` where empty means default `"buildmax.log"`).
  - Support an option to also write logs to stdout (e.g. `Init(filename string, alsoStdout bool)` or a separate init variant). CLI uses file-only; server and worker use file + stdout so logs can be collected by orchestrators/containers. CLI must remain file-only because stdout is captured as the agent response.
  - Keep Lumberjack and level behavior; `DisableConsole` / `SetOutput` behavior consistent with the chosen output.
- **`cmd/buildmax-server/main.go`**: Call log init with filename `buildmax-server.log` and alsoStdout true.
- **`cmd/buildmax-worker/main.go`**: Call log init with filename `buildmax-worker.log` and alsoStdout true.
- **`cmd/buildmax/main.go`**: Keep using the default log file name and file-only (no stdout).
- **Runtime workspace log upload**: When the executor uploads the task’s buildmax dir to persist storage after a task run (existing flow from 064), also upload the **worker** process log file. The worker writes to `LogsDir()/buildmax-worker.log` (worker’s own DataDir). Upload that file to the same task buildmax prefix under e.g. `logs/buildmax-worker.log` so both the agent run log (`logs/buildmax.log`) and the worker log are available in MinIO for that task.
- **Tests**: Update or add tests that rely on log filename or stdout (if any); ensure `go build ./...` and `go test ./...` pass.

### Out of scope

- Adding an env var (e.g. `BUILDMAX_LOG_FILE`) to override the log file name; can be a follow-up.
- Different log level or rotation settings per binary.
- Changes to deployment or docs beyond what is needed for the code change.

## Deliverables

1. **`internal/log`**: `Init(filename string, alsoStdout bool)` (or equivalent) so that:
   - Empty `filename` → use `"buildmax.log"` (backward-compatible default).
   - Non-empty → use that name under `config.LogsDir()`.
   - When `alsoStdout` is true, logs go to both the file and stdout; when false, file-only (current behavior).
   - Lumberjack and level behavior unchanged.
2. **Entry points**: Server and worker call init with their filename and `alsoStdout true`; CLI calls with default filename and `alsoStdout false`.
3. **On-disk result**: `LogsDir()` contains `buildmax.log` (CLI), `buildmax-server.log` (server), `buildmax-worker.log` (worker).
4. **Executor**: When uploading task buildmax after a run, also upload the worker’s log file from the worker’s `LogsDir()/buildmax-worker.log` to the task buildmax prefix as `logs/buildmax-worker.log` (same key layout as 064). If the file is missing, skip (best-effort). Use the same `uploadTaskBuildmax`-style flow (e.g. extend the list of relPaths or add an explicit “worker log” path and source file).

## Acceptance criteria

- [ ] When running `buildmax` (CLI), logs are written only to `DataDir()/logs/buildmax.log` (no stdout).
- [ ] When running `buildmax-server`, logs are written to `DataDir()/logs/buildmax-server.log` and to stdout.
- [ ] When running `buildmax-worker`, logs are written to `DataDir()/logs/buildmax-worker.log` and to stdout.
- [ ] After a task run, when persist is MinIO, the task buildmax upload includes `logs/buildmax.log` (agent), `logs/buildmax-worker.log` (worker), plus existing sessions/settings.
- [ ] Existing tests pass; no new failing tests from this change.
- [ ] `go build ./...` and `go test ./...` succeed.
