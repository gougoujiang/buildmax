# Task 094: Two-tier agent — Phase 4 — Cron and webhook adapters

Add Tier 1 channel adapters and a rule-based conversation engine for cron and webhook. No LLM at Tier 1 for these channels; structured trigger/payload maps to task input and optional callback.

**Design:** [design/007-two-tier-agent.md](../design/007-two-tier-agent.md) §2.2 (Tier 1 not always LLM), §8 Phase 4.

**Deliverables:**
- Cron adapter: implements `ChannelAdapter`. Receive: config or env (schedule id, workspace_id, template message or fixed message). Sends `ConversationTurn` with channel=cron. Optional Send: on run complete, post summary to a URL or log.
- Webhook adapter: implements `ChannelAdapter`. Receive: HTTP request body (JSON); map to workspace (e.g. header or path), extract message from payload (configurable path or template). Send: optional callback URL with run result.
- Rule-based engine (or extend existing engine): when channel is cron or webhook, no LLM; resolve workspace/chat from turn, create one ChatRun with turn.Message, return task_id(s). No conversation history.
- Server: register HTTP endpoint(s) for webhook (e.g. POST /api/webhook or workspace-scoped); cron runs in-process or via external scheduler calling internal API or adapter.
- Documentation: how to configure cron and webhook (env, payload shape, callback).
- Tests: unit tests for adapters and rule-based path; optional integration test for webhook → one run.

**Out of scope:** Telegram/IM (use Phase 3 LLM engine with different adapter); task decomposition (Phase 5).
