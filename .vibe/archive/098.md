# Task 098: TUI chat history optimization

## Goal

Fix chat history in the BuildMax TUI so that lines wrap at the correct visible width and add horizontal margins for readability.

## Context

- **Current behavior**: In `internal/tui/format.go`, viewport content is built by prefixing each message line with a styled bar (`"• "` or `"> "`) via lipgloss, then calling `wrapLine(prefix, width)` where `width` is the full terminal width. `wrapLine` breaks by rune count. Because the prefix includes ANSI escape codes from `Render()`, the rune count is much larger than the visible width, so lines break too early (e.g. only ~60 visible characters per line when the terminal is 80 columns).
- **Where it lives**: `buildViewportContent` in `internal/tui/format.go`; `wrapLine` in the same file; `ViewportContentOpts.Width` is set from `m.width` (terminal width) in `internal/tui/model.go`.
- **Conventions**: AGENTS.md — all-Go TUI with Bubble Tea; persistence/key style snake_case (not needed for this change).

## In scope

1. **Wrap by visible width**
  When building viewport content, wrap message and streaming-tail text by *content* width, not by the rune length of styled strings. Use a content width = `width - leftMargin - rightMargin - prefixWidth` (prefix is 2 runes: `"• "` or `"> "`). Wrap *plain* content (no ANSI) to that width; then for each wrapped segment output: left margin (spaces) + styled prefix (only on first segment of a logical line) + styled or plain segment. Do not pass lipgloss-rendered strings into `wrapLine`.
2. **Horizontal margins**
  Add a small left margin and right margin so chat text does not touch the terminal edges. Use a single constant (e.g. 2 columns each side) for both margins. Apply to: banner, all message lines, streaming tail, and carousel. Each line of viewport content should start with `leftMargin` spaces and use at most `contentWidth` runes for the rest (so the right side has unused columns).
3. **Banner and consistency**
  Banner and any other viewport lines (e.g. top blank lines) should respect the same left margin so the whole scrollable area is aligned.

## Out of scope

- Changing viewport or scroll behavior (e.g. scroll speed, focus).
- Configurable margin (env or settings); a constant is enough for this task.
- Portal or server; CLI TUI only.

## Deliverables

- `**internal/tui/format.go`**
  - Introduce constants for left and right margin (e.g. `viewportLeftMargin`, `viewportRightMargin`).
  - Refactor `buildViewportContent` so that:
    - Content width = `opts.Width - viewportLeftMargin - viewportRightMargin - 2` (2 = prefix "• " or "> ").
    - For each message line (and streaming tail / carousel): wrap the *plain* content (no ANSI) with `wrapLine(plainContent, contentWidth)`; for each wrapped segment, output `leftMargin` spaces, then for the first segment the styled prefix + segment, for continuation segments either a matching-width “continuation” prefix (e.g. spaces) + segment, or prefix only on first line (per-message) and spaces for continuation.
  - Ensure user messages: wrap plain `line`, then prepend styled `"> "` only on the first segment of each logical line; continuation lines use the same left margin + optional indent so wrapped user content is aligned.
  - Assistant and streaming/carousel: wrap plain content, prepend styled `"• "` on first segment; continuation segments use left margin + 2 spaces (to align with text after the bullet) + segment.
- **Tests**
  - Extend or add tests in `internal/tui/model_test.go` (or `format_test.go` if added) so that: (1) wrapped content width respects margin (e.g. with a fixed width, wrapped lines have length ≤ content width + prefix + margin); (2) no ANSI in the string passed to wrap (optional assertion); (3) at least one test with a long line verifies more visible characters per line than before (e.g. with width 80 and margin 2, expect lines of ~74 visible chars for content, or equivalent).

## Acceptance criteria

- With a terminal width of 80, long assistant messages wrap so that each line shows roughly 80 − leftMargin − rightMargin − 2 ≈ 74 visible characters of content (no early break due to ANSI).
- Chat content (user, assistant, streaming tail, carousel) has visible left and right margins and does not touch the terminal edges.
- Banner and all viewport content use the same left margin.
- Existing tests in `internal/tui` pass; new or updated tests cover wrap-by-content-width and margins.
- `go build ./...` and `go test ./...` pass.
