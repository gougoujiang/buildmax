# Task 062: Id solution refine

## Goal

Use **ULID** for task and artifact IDs (time-ordered, lexicographically sortable) and **uppercase base36** for user, workspace, and project IDs (unchanged semantics, prettier URLs). All IDs remain string-based; no API contract change.

## Context

- **Current**: `internal/util/id.go` provides `NewID()`: UUID v4 → base36 encoding (25 chars, alphabet `0-9a-z`). Used for User, Workspace, Project, Task, and Artifact IDs. Entity create paths: `entity` package (User, Workspace, Project, Task) and `executor` (artifact ID passed into `CreateArtifactWithItem`).
- **Relevance**: Task and artifact are timeline entities; ordering by ID is useful (lists, logs). ULID is 26 chars, Crockford base32, time-ordered. User/workspace/project are not timeline-critical; keeping a short opaque ID is enough; uppercase avoids “zig-zag” look in URLs.
- **Constraints**: DB columns are `varchar(64)`; no schema change. Existing rows keep existing IDs; no data migration in this task.

## In scope

1. **ULID for task and artifact**
   - Add dependency (e.g. `github.com/oklog/ulid/v2`).
   - Add `util.NewULID() string` in `internal/util` (or equivalent), returning a new ULID string.
   - **Task ID**: In `entity.CreateTask`, set `TaskID` using `util.NewULID()` instead of `util.NewID()`.
   - **Artifact ID**: In `internal/executor` where `artifactID := util.NewID()` is used, use `util.NewULID()` instead.

2. **Uppercase base36 for user, workspace, project**
   - In `internal/util/id.go`, change the base36 alphabet from `0-9a-z` to `0-9A-Z` (uppercase letters).
   - Keep `NewID()` for User, Workspace, and Project creation only; document that `NewID()` is for non–time-ordered entities and `NewULID()` for time-ordered (task, artifact).
   - No change to ID length (25 chars) or to call sites for user/workspace/project beyond the new alphabet in the generated value.

3. **Tests**
   - Adjust or add tests that assert ID format (e.g. ULID length/character set for task and artifact; base36 uppercase for new user/workspace/project IDs) where appropriate.
   - Existing entity and executor tests must still pass; any hardcoded or golden IDs in tests should be updated if they assume lowercase base36.

## Out of scope

- **Data migration**: Existing task/artifact/user/workspace/project rows are not backfilled; old IDs remain valid.
- **API or route changes**: IDs stay string; no change to path/query names or response shapes.
- **Session ID**: Session IDs (e.g. `session_id` on Task) are unchanged; no requirement to switch them to ULID or base36 in this task.
- **Portal or CLI**: No change beyond continuing to accept and display the new ID formats as strings.

## Deliverables

- `internal/util/id.go`: uppercase base36 alphabet for `NewID()`; add `NewULID()` (or new file under `util` for ULID) using the chosen ULID library.
- `internal/storage/entity/task.go`: `CreateTask` uses `util.NewULID()` for `TaskID`.
- `internal/executor/executor.go`: artifact ID generated with `util.NewULID()`.
- `go.mod` / `go.sum`: ULID dependency added.
- Tests updated or added so that build and `go test ./...` pass and ID format expectations are met where asserted.

## Acceptance criteria

- [ ] `util.NewULID()` exists and returns a 26-character ULID string; task and artifact creation use it for `task_id` and `artifact_id`.
- [ ] `util.NewID()` uses uppercase base36 (`0-9A-Z`); user, workspace, and project creation still use `NewID()` and produce uppercase IDs.
- [ ] `go build ./...` and `go test ./...` pass (including `internal/storage/entity` and `internal/executor`).
- [ ] No API or DB schema contract change; existing ID columns and JSON fields remain; only the format of newly generated IDs changes.
