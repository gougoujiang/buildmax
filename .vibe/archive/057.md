# Task 057: Decouple workspace dir from buildmax home

## Goal

Make the workspace directory independent of BuildMax's application data directory. **Workspace dir is only used when running the server.** Do not set a default; require the user to set `BUILDMAX_WORKSPACES_DIR` when starting the server (required env var for server mode).

## Context

- **Current behaviour**: `config.WorkspacesDir()` returns `os.Getenv(BUILDMAX_WORKSPACES_DIR)` when set; otherwise it returns `filepath.Join(DataDir(), "workspaces")`. So the default couples workspace location to DataDir.
- **Usage**: Workspace dir is only used in server mode: `internal/cmd/server.go` passes it to `server.Config.WorkspacesDir`; `internal/server/paths.go` and executor use it for workspace roots, persist, runtime, and artifact paths.
- **Relevant code**: `internal/config/config.go` (WorkspacesDir, PersistentWorkspaceDir, RuntimeWorkspaceDir, ArtifactDir), `internal/config/env_spec.go`, `internal/cmd/server.go` (runServer).

## In scope

1. **No default for workspace dir**  
   When `BUILDMAX_WORKSPACES_DIR` is unset, `WorkspacesDir()` returns the empty string (no fallback to DataDir or any other path).
2. **Required in server mode**  
   In `runServer` (internal/cmd/server.go), before building server config and starting the server, check that `config.WorkspacesDir()` is non-empty. If it is empty, return a clear error (e.g. `BUILDMAX_WORKSPACES_DIR is required for server mode`) so the server does not start.
3. **Config and docs**  
   Update `WorkspacesDir()` implementation and comments; update `env_spec.go` so BUILDMAX_WORKSPACES_DIR is documented as required for server mode with no default.
4. **Tests**  
   Update config tests: when unset, `WorkspacesDir()` returns `""`; when set, returns that path (cleaned). Remove or change `TestWorkspacesDir_WithBuildmaxHome` (no default under DataDir). Ensure tests that need a workspace dir set the env var.
5. **.env.example**  
   Update BUILDMAX_WORKSPACES_DIR to state it is required for server mode and has no default.

## Out of scope

- Changing DataDir() or BUILDMAX_HOME semantics.
- Migrating or moving existing workspace data on disk.
- CLI flags or config file for workspace dir (env-only remains).
- Requiring BUILDMAX_WORKSPACES_DIR for CLI/TUI (only server uses it; CLI/TUI do not need it).

## Deliverables

- `internal/config/config.go`: `WorkspacesDir()` returns `""` when BUILDMAX_WORKSPACES_DIR is unset; returns cleaned path when set. Comments updated.
- `internal/config/env_spec.go`: EnvVar description for BUILDMAX_WORKSPACES_DIR updated (required for server, no default).
- `internal/cmd/server.go`: In `runServer`, validate that `config.WorkspacesDir()` is non-empty and return a clear error if not.
- `internal/config/config_test.go`: Tests updated (default = `""`, override returns set path; adjust or remove WithBuildmaxHome test).
- `.env.example`: Comment for BUILDMAX_WORKSPACES_DIR updated (required for server, no default).

## Acceptance criteria

- [ ] When BUILDMAX_WORKSPACES_DIR is unset, `WorkspacesDir()` returns `""`.
- [ ] When BUILDMAX_WORKSPACES_DIR is set, `WorkspacesDir()` returns that path (cleaned).
- [ ] Running `buildmax server` without BUILDMAX_WORKSPACES_DIR set fails at startup with a clear error stating BUILDMAX_WORKSPACES_DIR is required.
- [ ] Running `buildmax server` with BUILDMAX_WORKSPACES_DIR set starts and works as today.
- [ ] PersistentWorkspaceDir, RuntimeWorkspaceDir, ArtifactDir behaviour unchanged when WorkspacesDir() is non-empty (they still derive from WorkspacesDir()).
- [ ] env_spec.go and .env.example state that BUILDMAX_WORKSPACES_DIR is required for server mode and has no default.
- [ ] Config tests updated and passing.
