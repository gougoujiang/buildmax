# Task 039: Add task

Add support for creating and managing tasks (e.g. within workspace or agent flow). A task is the user-submitted work request; it must belong to a project. This task covers task persistence and list/create APIs only — execution is out of scope.

---

## Goal

**One sentence:** Add a task table (internal id, task_id UUID, project_id, status, input, output, created_by, timestamps, error_message), expose `GET /api/projects/{project_id}/tasks` and `POST /api/projects/{project_id}/tasks` with JWT and project ownership checks (user must own the project’s workspace), and have the portal load and create tasks via the API instead of mock data.

---

## Context

- **Server:** `internal/server` — HTTP server with login, workspaces, and project list/create. Projects live under `/api/workspaces/{workspace_id}/projects`. JWT required; workspace ownership enforced via `userOwnsWorkspace`.
- **Store:** `internal/store` — MySQL via GORM; `User`, `Workspace`, `Project`; `ProjectStore` with `ListProjectsByWorkspace`, `CreateProject`. No `GetProject` yet — task handlers will resolve project by id and then check user owns the project’s workspace.
- **Design (001):** Workspace → Project → Tasks/Artifacts. Task = single agent execution.
- **Portal:** `portal/src/lib/types.ts` defines `Task`: id, projectId, title, status (running/success/failed/canceled), timeLabel, summary. Task data is currently mock; project view will need to load tasks from the API and support creating a task.
- **Conventions:** AGENTS.md — persisted data uses snake_case in JSON; backend in Go; portal calls Go API.

---

## In scope

- **Task table (MySQL, same store)**
  - Columns: `id` (internal primary key, auto-increment integer), `task_id` (UUID, unique, not null — used in API as task identifier), `project_id` (FK to projects), `status` (e.g. PENDING, RUNNING, SUCCEEDED, FAILED, CANCELED), `input` (text — user requirement), `output` (text — agent response, nullable), `created_by` (user id), `created_at`, `started_at` (nullable), `ended_at` (nullable), `error_message` (nullable).
  - JSON/API: snake_case (`task_id` as `id` in response, `project_id`, `created_by`, `created_at`, `started_at`, `ended_at`, `error_message`, etc.).
  - Table name: `tasks`.

- **Backend API**
  - **`GET /api/projects/{project_id}/tasks`** — requires valid JWT. Resolve project by id; caller must own the project’s workspace; otherwise 403 (or 404 if project not found). Returns list of tasks for the project. Response: array of task objects (id = task_id, project_id, status, input, output, created_by, created_at, started_at, ended_at, error_message). 401 when no/invalid token.
  - **`POST /api/projects/{project_id}/tasks`** — requires valid JWT. Body: `{ "input" }` (input required). Resolve project by id; caller must own the project’s workspace; otherwise 403 (or 404). Creates a task under the project with status PENDING, created_by = JWT user id. Returns 201 and the created task object. 400 if input missing. 401 when no/invalid token.

- **Store layer**
  - Add `Task` model and `TaskStore`: list tasks by project_id, create task. Add `GetProject(ctx, projectID)` to `ProjectStore` so handlers can resolve project by id and then check user owns `project.WorkspaceID`. Use same DB and GORM; AutoMigrate for `Task`.

- **Portal**
  - When authenticated and viewing a project, load tasks via `GET /api/projects/{projectId}/tasks`. Replace mock task data with API-backed list. Support creating a new task (e.g. "New task" with input) via `POST /api/projects/{projectId}/tasks` and refresh list or navigate to the new task.
  - Map API task shape to existing `Task` type (task_id → id, project_id → projectId, input → title or summary as needed, status mapping PENDING/RUNNING/SUCCEEDED/FAILED/CANCELED to running/success/failed/canceled, created_at/ended_at → timeLabel).

- **OpenAPI**
  - Document `GET` and `POST /api/projects/{project_id}/tasks` (auth: Bearer JWT; request/response schemas).

## Out of scope

- **Task execution** — Running the agent, updating status to RUNNING/SUCCEEDED/FAILED, writing output, started_at/ended_at, error_message. Future work.
- **Update/delete task** — not in this task.
- **GET single task by id** — not required for this task; list and create only.

## Technical notes

- **Task identifier:** API and portal use `task_id` (UUID) as the task id; internal `id` is for DB only.
- **Project resolution:** Project id is globally unique. For task endpoints, resolve project by path `project_id` via `GetProject(ctx, projectID)`; then ensure user owns `project.WorkspaceID` (same `userOwnsWorkspace` as elsewhere). 403 if not owned; 404 if project not found.
- **Path parameters:** Use Go 1.22+ ServeMux: `GET/POST /api/projects/{project_id}/tasks`; parse project_id; validate via GetProject + userOwnsWorkspace(project.WorkspaceID).
- **Status values:** Store and API use PENDING, RUNNING, SUCCEEDED, FAILED, CANCELED. Portal `Task.status` uses running/success/failed/canceled — map accordingly (e.g. PENDING → running or a separate "pending" if UI supports it).

## Deliverables

1. **internal/store**
   - `Task` struct: id (uint, auto-increment PK), task_id (UUID), project_id, status, input, output, created_by, created_at, started_at, ended_at, error_message; GORM and `json:"snake_case"` tags. Table name `tasks`.
   - `ProjectStore`: add `GetProject(ctx, projectID) (*Project, error)`.
   - `TaskStore` interface and implementation: `ListTasksByProject(ctx, projectID) ([]Task, error)`, `CreateTask(ctx, projectID, input, createdBy string) (*Task, error)`. CreateTask sets status PENDING, task_id = new UUID, created_at = now; started_at, ended_at, output, error_message null. AutoMigrate `Task`.

2. **internal/server**
   - Register `GET /api/projects/{project_id}/tasks` and `POST /api/projects/{project_id}/tasks`. Extract user id from JWT; resolve project by id (GetProject); ensure user owns project’s workspace; list or create task; return JSON. Return 401/403/404/400/201/503 as specified.
   - Update OpenAPI spec with both task endpoints.

3. **Portal**
   - API client: `getTasks(projectId, token)` and `createTask(projectId, body, token)` in `api.ts`, calling the new endpoints with Bearer token.
   - Project view: when authenticated, fetch tasks for the current project from the API; use that list instead of mock. Add "New task" (or equivalent) that sends input via create API and refreshes or navigates.
   - Map API response to existing `Task` type (id, projectId, title/summary from input, status, timeLabel from created_at/ended_at).

4. **Tests**
   - Backend: test list tasks (empty when none; 403 when user does not own project’s workspace; 404 when project not found); test create task (201 and body; 403/404 when not allowed; 400 when input missing). No real external API in tests.

- [ ] Portal, when logged in and in a project, loads tasks from the API and displays them; user can create a new task and see it in the list or navigate to it.
