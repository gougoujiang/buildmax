# Task 074: New id solution

## Goal

Introduce a single, consistent ID format (`<prefix>_<body>`) for all public entity IDs so they are recognizable by type, URL- and log-friendly, and collision-safe at scale.

## Context

- **Current state**: `internal/util/id.go` provides `NewID()` and `NewULID()`. User, Workspace, Agent use `NewID()`; Chat, ChatRun, and Artifact use `NewULID()`. Session ID in CLI is UUID. ArtifactItem has no string ID (only `artifact_id` + `relative_path`). **No backward compatibility**: ULID and the old `NewID()` format are removed; all IDs use the new prefixed format only.
- **Where this fits**: ID generation is centralized in `internal/util`; call sites are in `internal/storage/entity` (User, Workspace, Chat, ChatRun, Agent, Artifact creation) and `internal/executor` (artifact ID). API and Portal consume these IDs as strings; ordering uses `created_at`, not ID.
- **Conventions**: AGENTS.md §6.1 uses snake_case for persisted/JSON keys; DB table names are singular. Entity IDs are string columns (e.g. `user_id`, `workspace_id`); no change to column names, only to the *value* format.

## ID format (this task)

For this task, the **new ID format** means:

1. **Form**: `<prefix>_<body>`
   - **prefix**: 1–3 character type abbreviation (lowercase). Fixed set per entity type.
   - **body**: 20-character random string, base36 alphabet `[a-z0-9]` (lowercase). Optional future: exclude ambiguous chars (0/O, 1/l/I); not required for this task.

2. **Prefix set in scope**:  
   `u_` user, `w_` workspace, `a_` agent, `c_` chat, `r_` chat run, `ar_` artifact, `f_` artifact item.

3. **Ordering**: List/sort by `created_at`; IDs are not required to be time-ordered.

4. **Scope**: All *new* IDs generated by the application use this format. We are **not** implementing:
   - Data migration or backfill of existing rows (existing IDs remain valid).
   - Prefixes for trigger (`t_`), connector (`x_`), or policy/permission set (`p_`).
   - Session ID format change (CLI/session can remain UUID for this task, or be switched to `c_` if we treat session as chat; clarify in design).

## Deliverables

1. **`internal/util` (ID generation)**
   - Replace ID generation with a single function (e.g. `NewPrefixedID(prefix string) string`) that returns `prefix + "_" + body`, with body = 20 chars from `[a-z0-9]` (crypto-random, base36). Encode in lowercase base36 (e.g. UUID→bits→big.Int→base36 lowercase, then truncate/pad to 20 chars).
   - Remove `NewULID()` and `NewID()`; remove the ULID dependency from the module. All call sites use `NewPrefixedID(prefix)` with the appropriate prefix. Document prefix semantics in the package.

2. **Entity layer (`internal/storage/entity` + `internal/model`)**
   - User: generate `user_id` with prefix `u_`.
   - Workspace: generate `workspace_id` with prefix `w_`.
   - Agent: generate `agent_id` with prefix `a_`.
   - Chat: generate `chat_id` with prefix `c_`, and in `CreateChat` the first run’s `chat_run_id` with prefix `r_`.
   - ChatRun: generate `chat_run_id` with prefix `r_` in `CreateChatRun`.
   - Artifact: artifact ID is generated in `internal/executor`; use prefixed `ar_` (and pass through to store/artifact storage).
   - Artifact item: add a stable `artifact_item_id` (e.g. `f_` prefix) to the `ArtifactItem` model and to creation paths (`CreateArtifactWithItem`, `OnRunComplete`); generate when creating an item. DB: add column `artifact_item_id` (varchar, unique or unique per artifact); API can expose it for future use.

3. **Executor**
   - Use prefixed ID `ar_` for artifact ID so artifact paths and payloads use the new format.

4. **Tests**
   - Unit tests for the new ID function: correct prefix, body length 20, body charset `[a-z0-9]`, uniqueness over many calls (no collisions in reasonable samples).
   - Existing entity and executor tests that assert ID format or length should be updated to accept the new format (prefix + 20-char body).

5. **Session / CLI (optional in this task)**
   - Either leave session ID as UUID, or align session with chat and use `c_`-prefixed ID when creating a new chat-backed session; document the decision in design.

## Out of scope (for later)

- Migration or backfill of existing DB rows to the new ID format.
- Prefixes for trigger, connector, policy/permission set.
- Changing API URL shapes or route parameter names (only the *value* of IDs changes).

## Acceptance

- [ ] New prefixed ID function exists; body is 20 chars, `[a-z0-9]`, and prefixed output matches `<prefix>_<body>`.
- [ ] User, Workspace, Agent, Chat, ChatRun, Artifact (and ArtifactItem when added) are created with the correct prefix for their type.
- [ ] Artifact ID in executor uses `ar_` and is stored and used in artifact storage paths unchanged.
- [ ] ArtifactItem has `artifact_item_id` column and it is set to `f_`-prefixed ID on create.
- [ ] `go build ./...` and `go test ./...` pass; existing tests updated as needed for new ID format/length.
- [ ] No new external dependencies unless justified (reuse crypto/rand). ULID is removed from the codebase; only the new prefixed ID is used.
