# Task 079: Worker prepare AGENTS.md for remote task

## Goal

Have the worker write an AGENTS.md file into the chat run directory before invoking `buildmax -p`, so the agent receives run context (directory layout and, when present, workspace-provided instructions) via the existing CLI AGENTS.md path (task 078).

## Context

- **Task 075**: Per-run layout is `chats/<workspaceID>/<chatID>/<chatRunID>/` with `home/` (materialized workspace files), `artifacts/` (run output), `global/` (BUILDMAX_HOME). The worker runs `buildmax -p` with `cmd.Dir = runDir`, so the process cwd is the run directory.
- **Task 078**: CLI composes system prompt as `DefaultSystemPrompt` + optional contents of `AGENTS.md` at workspace root (`os.Getwd()`). `agent.ReadAgentsMd(dir)` reads `AGENTS.md` from a given directory. So when the worker sets `cmd.Dir = runDir`, any `AGENTS.md` in `runDir` is picked up by the CLI with no change to CLI or agent code.
- **Executor**: `internal/executor.RunTask` ensures run dirs, materializes workspace home into `runHome`, then calls `runBuildmaxCmd(ctx, run, runDir, runGlobal, sessionID)`. The new step must run after materialize and before `runBuildmaxCmd`.
- **Conventions**: All-Go; executor lives in `internal/executor`; no new runtime deps. Persisted/serialized data uses snake_case (N/A for generated file content).

## Run directory and AGENTS.md (this task)

1. **Run directory** = `paths.RuntimeChatRunDir(...)` — the directory that becomes cwd for `buildmax -p`. It contains `home/`, `artifacts/`, and `global/`.
2. **AGENTS.md** = a file written at `runDir/AGENTS.md` before the worker runs buildmax. The CLI already reads AGENTS.md from cwd, so writing it here is sufficient for the agent to receive it.
3. **Content of AGENTS.md**:
   - **Required**: A generated section that documents the run directory structure so the agent can reference it (e.g. that `home/` is the working copy of workspace files, `artifacts/` is where to write results such as `result.md`, `global/` is BUILDMAX_HOME). Plain Markdown; wording should be agent-oriented.
   - **Optional**: If after materialize the file `runHome/AGENTS.md` exists (user uploaded it to the workspace), include its contents in the written AGENTS.md (e.g. append after the structure section, or a clear order specified in design). This gives remote tasks the same “project AGENTS.md” experience when the workspace has one.

We are **not** implementing:

- Reading AGENTS.md from the server or from a path outside the run directory.
- Nested or multiple AGENTS.md resolution.
- Changing the CLI or `agent.ReadAgentsMd` behavior.

## Deliverables

1. **Generate and write AGENTS.md in RunTask**
   - After `persist.MaterializeToDir(..., runHome)` and before `runBuildmaxCmd`, write a file `runDir/AGENTS.md`.
   - Content: (a) a generated “run directory structure” section; (b) if `runHome/AGENTS.md` exists, include its contents (order: structure first, then workspace AGENTS.md, or as design specifies).
   - Prefer a small helper (e.g. in `internal/executor`) that takes `runDir`, `runHome` and returns or writes the content, so RunTask stays readable and the content is testable.
   - Use `agent.AgentsMdFilename` for the filename so the name stays consistent.

2. **Structure section content**
   - Document at least: `home/` = working copy of workspace files; `artifacts/` = run output (e.g. `result.md`); `global/` = BUILDMAX_HOME for this run. Keep it short and suitable for the system prompt.

3. **Tests**
   - Unit test(s) for the “build AGENTS.md content” logic: with and without existing `runHome/AGENTS.md`; generated content includes the directory structure and (when present) workspace AGENTS.md content. Prefer table-driven tests; no real blob or process execution required.

4. **Documentation**
   - Brief note in project AGENTS.md that the worker prepares AGENTS.md in the run directory (directory structure + optional workspace AGENTS.md) so remote runs get the same convention as the CLI.

## Out of scope (for later)

- Server-side or blob-stored AGENTS.md outside the run.
- Nested / multiple AGENTS.md resolution.
- Modifying the CLI or agent package for where/how AGENTS.md is read.

## Acceptance

- [ ] Before `runBuildmaxCmd`, `runDir/AGENTS.md` exists and contains a generated run directory structure section.
- [ ] When the workspace has an AGENTS.md in home (materialized to `runHome/AGENTS.md`), the written `runDir/AGENTS.md` includes that content (in a defined order with the structure section).
- [ ] When `runHome/AGENTS.md` is missing, the written file contains only the generated structure section (no error).
- [ ] Unit test(s) cover: no workspace AGENTS.md; workspace AGENTS.md present; content includes structure and optional workspace text.
- [ ] `go build ./...` and `go test ./...` pass.
- [ ] Project AGENTS.md documents that the worker prepares run-directory AGENTS.md for remote tasks.
