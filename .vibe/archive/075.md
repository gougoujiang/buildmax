# Task 075: Workspace structure redesign

Redesign the workspace directory layout so that each chat run has a standard, self-contained structure (home, artifacts, global) and the workspace uses a clearer top-level name for uploaded files.

## Goal

One sentence: **Adopt a standard per-run directory layout under `home` / `chats/<chatID>/<chatRunID>/` (with `home`, `artifacts`, `global`) and rename workspace-level `persist` to `home` so the layout is easier to maintain and trace.**

## Context

### Current layout (workspace root = `<workspace root>/<workspaceID>/`)

```
<workspace_root>/<workspace_id>/
├── persist/                          # Uploaded files (Explore, uploads)
│   └── (user files)
├── chats/
│   └── <chat_id>/
│       ├── ws/                       # Materialized persist (shared by all runs in this chat); cmd.Dir for buildmax
│       │   └── (user files copy)
│       ├── <chat_run_id_1>/
│       │   ├── buildmax/              # BUILDMAX_HOME for this run (sessions, logs, settings)
│       │   │   ├── sessions/
│       │   │   ├── logs/
│       │   │   └── ...
│       │   └── result-<chat_run_id_1>.md
│       └── <chat_run_id_2>/
│           ├── buildmax/
│           └── result-<chat_run_id_2>.md
└── artifacts/
    └── <chat_id>/
        └── <chat_run_id>/
            └── <artifact_id>/
                └── result.md         # Archived artifact
```

- **persist** — Uploaded files from user (Explore, uploads). Backend: `PersistentWorkspaceDir(workspaceID)` → `.../persist`. Blob keys: `.../persist/<relPath>`.
- **chats/<chatID>/** — One dir per chat.
  - **chats/<chatID>/ws** — Materialized persist files for the agent (shared by all runs in the chat). Worker materializes here; `buildmax -p` runs with `cmd.Dir = ws`.
  - **chats/<chatID>/<chatRunID>/buildmax** — BUILDMAX_HOME for that run (sessions, logs, settings). Uploaded to blob as `chats/<chatID>/<chatRunID>/buildmax/...`.
  - **chats/<chatID>/<chatRunID>/result-<chatRunID>.md** — Result of the run (also uploaded to artifact storage).
- **artifacts/<chatID>/<chatRunID>/<artifactID>/** — Archived artifact files (e.g. result.md).

Relevant code: `internal/config` (path helpers), `internal/executor` (RunTask, paths, materialize, run buildmax, persist result, upload buildmax), `internal/executor/paths.go` (WorkspacePaths), `internal/storage/blob/keys.go` (persist/artifact/chat buildmax keys), `internal/server` (persistentWorkspaceDir, ensureWorkspaceDirs, loadChatConversationData), `internal/storage/blob` (local FS and S3 persist).

### Target layout (after redesign)

```
<workspace_root>/<workspace_id>/
├── home/                             # Uploaded files (same role as current persist); backend/blob use "home"
│   └── (user files)
├── chats/
│   └── <chat_id>/
│       └── <chat_run_id>/
│           ├── .buildmax/            # (Optional) Agents/skills; out of scope for this task
│           ├── home/                 # Copy of workspace home for this run; agent working copy
│           │   └── (materialized user files)
│           ├── artifacts/           # Run output dir; contents archived to workspace artifacts
│           │   ├── result.md        # Final result of this run
│           │   └── (other generated files)
│           └── global/              # BUILDMAX_HOME for this run (sessions, logs, settings)
│               ├── sessions/
│               ├── logs/
│               └── ...
└── artifacts/                        # Workspace-level archive (unchanged)
    └── <chat_id>/
        └── <chat_run_id>/
            └── <artifact_id>/
                ├── result.md
                └── (other generated files)
```

- **home** — Same role as current `persist`: uploaded files. Backend and blob use `home` instead of `persist`.
- **chats/<chatID>/<chatRunID>/** — One dir per **run** (under chat). Standard run layout:
  - **.buildmax** — (Optional) Standard dir for agents/skills; **out of scope** for this task (no implementation of contents).
  - **home** — Copy of workspace `home` for this run. Materialize target at run setup. Agent’s working copy of user files.
  - **artifacts** — Run output directory. All generated files under this dir are archived to workspace artifacts. Includes `result.md` (final result) and any other files produced during the run.
  - **global** — Same semantics as current `buildmax`: BUILDMAX_HOME for this run (sessions, logs, settings). Renamed for clarity.
- **artifacts/** — Unchanged at workspace level: archived artifact blobs (e.g. `artifacts/<chatID>/<chatRunID>/<artifactID>/` or equivalent; design may keep chatID for listing).

Worker flow (conceptual): create `chats/<chatID>/<chatRunID>/home`, `chats/<chatID>/<chatRunID>/artifacts`, `chats/<chatID>/<chatRunID>/global`; materialize workspace `home` → run `home`; restore session into `global`; run buildmax with `BUILDMAX_HOME=.../global` and cwd run dir (or run `home`); write result to run `artifacts/result.md`; archive run `artifacts/` to artifact storage; upload `global` to blob (key `chats/<chatID>/<chatRunID>/global/...` or keep `.../buildmax/...`).

## In scope

1. **Rename persist → home at workspace level**
   - Config: `PersistentWorkspaceDir` → `.../home`. Keep same function name or rename to something like `WorkspaceHomeDir` for clarity; callers and blob keys must use the new path segment `home`.
   - Blob keys: `.../persist/...` → `.../home/...` (PersistObjectKey, PersistPrefix).
   - Server: `ensureWorkspaceDirs`, `persistentWorkspaceDir` (or equivalent), upload/list file handlers that use the workspace “persist” root.
   - Local FS and S3 persist implementations: use the same root function; no change to interface, only the path segment passed by config/setup.

2. **Per-run directory layout**
   - Paths: Run dir remains under chat: `chats/<chatID>/<chatRunID>/`. New run layout: `chats/<chatID>/<chatRunID>/home`, `.../artifacts`, `.../global`. Replace or repurpose `RuntimeWorkspaceDir`, `RuntimeChatBuildmaxDir`, `RuntimeChatWSDir` with run-scoped: run dir, run home, run artifacts dir, run global dir (current buildmax role).
   - Executor: Create run dir and subdirs (home, artifacts, global). Materialize workspace home → run home. Set BUILDMAX_HOME to run global. Run `buildmax -p` with cwd = run dir (so agent sees home/, artifacts/, global/). Write result to run `artifacts/result.md`. Archive run artifacts to artifact storage (one artifact per run containing result.md; other files under run artifacts if any). Upload run `global` to blob (PutChatBuildmax); blob key layout can stay `chats/<chatID>/<chatRunID>/buildmax/...` for compatibility or become `chats/<chatID>/<chatRunID>/global/...` (design choice).
   - Session restore: Read from previous run’s blob (GetChatBuildmax) and write into current run’s `global` (sessions subdir).

3. **Blob storage key alignment**
   - Persist (workspace uploads): key segment `persist` → `home`.
   - Chat run “buildmax” data: either keep `chats/<chatID>/<chatRunID>/buildmax/` or switch to `chats/<chatID>/<chatRunID>/global/`; GetChatBuildmax/PutChatBuildmax and all callers (executor, server conversation loader) must use the chosen key layout consistently.

4. **Tests and config tests**
   - Update tests that assert on path segments (`persist`, `chats/<chatID>/ws`, `.../buildmax`) and executor tests that mock WorkspacePaths. Add or adjust tests for run-scoped layout and materialize-to-run-home.

## Out of scope

- **.buildmax contents** — Populating `.buildmax` with skills/agents or making the CLI “scan” it is not in this task. The directory may be created empty or omitted for now.
- **Migration of existing workspaces** — No automatic migration of existing `persist` or old `chats/<chatID>/<chatRunID>` layout on disk or in blob. New runs use the new layout; existing data may require a separate migration task or manual move.
- **Portal UI changes** — No requirement to change frontend copy or labels; only backend/worker layout and paths.
- **Artifact API or DB schema** — Listing and storing artifacts by chat/run/artifactID remain; only the on-disk and blob layout for run outputs and archive target are in scope.

## Deliverables

- Config path helpers and WorkspacePaths updated to: workspace `home` (no `persist`), run-scoped `chats/<chatID>/<chatRunID>/home|artifacts|global`.
- Executor RunTask: create run dirs, materialize to run home, run buildmax with run global as BUILDMAX_HOME and cwd run dir, write result to run artifacts, archive run artifacts, upload run global.
- Blob keys: workspace segment `home`; run buildmax/global key layout decided and consistent (local + S3).
- Server: workspace dir creation and file/upload handlers use `home`; conversation loader reads from run-scoped blob path (chatID + chatRunID or chatRunID-only as per key layout).
- Tests updated; `go build ./...` and `go test ./...` pass.

## Acceptance criteria

- [ ] Workspace root uses `home` (not `persist`) for uploaded files; upload and file list work against `home`.
- [ ] Each chat run uses a single run dir `chats/<chatID>/<chatRunID>/` with subdirs `home`, `artifacts`, `global`.
- [ ] Worker materializes workspace `home` into run `home`; buildmax runs with BUILDMAX_HOME set to run `global` and cwd such that agent sees run `home` and `artifacts`.
- [ ] Run result is written under run `artifacts/` (e.g. `result.md`) and archived to artifact storage; run `global` is uploaded to blob and can be read back (e.g. for conversation).
- [ ] Session restore from previous run populates current run’s `global` (or equivalent) from blob.
- [ ] All path and blob key changes are consistent across config, executor, server, and blob (local + S3); no remaining references to `persist` in the new layout; run dir is `chats/<chatID>/<chatRunID>/` with home/artifacts/global.
- [ ] `go build ./...` and `go test ./...` pass; existing executor and config path tests updated or added as needed.
