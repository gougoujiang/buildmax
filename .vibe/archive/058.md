# Task 058: Runtime task dir re-org

## Goal

Reorganize the runtime task directory so each task run has a **sandboxed layout**: a dedicated `buildmax/` subdir for agent runtime data (sessions, logs, settings) and a `ws/` subdir for workspace files materialized from persist. The executor runs `buildmax -p` with `BUILDMAX_HOME=<taskDir>/buildmax` and working directory `<taskDir>/ws`, so agent and workspace data are clearly separated under a single task path.

## Context

- **Current behaviour**: `RuntimeWorkspaceDir(workspaceID, taskID)` returns `WorkspacesDir()/<workspaceID>/tasks/<taskID>`. The executor creates that dir, materializes persist files directly into it, runs `buildmax -p` with `cmd.Dir = runtimeDir`, and writes `result-<taskID>.md` there. Agent process uses global `BUILDMAX_HOME` (or default `~/.buildmax`) for sessions/logs/settings and sees the flat task dir as CWD and tool root.
- **Relevant code**: `internal/config` (`RuntimeWorkspaceDir`), `internal/executor` (creates dir, materializes, runs buildmax, writes result), `internal/cmd/setup.go` (agent uses `os.Getwd()` for workspace root and `config.DataDir()` / `config.SessionsDir()` etc. for app data — all respect `BUILDMAX_HOME`).
- **Convention**: Env-based config; single source of truth for paths in `internal/config`; executor uses `WorkspacePaths` interface for testability.
- **Session file lookup**: With `BUILDMAX_HOME=<taskDir>/buildmax`, the agent writes the session to `<taskDir>/buildmax/sessions/<session_id>.json`. The server’s `GET /api/sessions/{session_id}` currently reads from a single `SessionsDir` (global BUILDMAX_HOME/sessions). After the re-org, executor-created sessions live under the task’s buildmax dir, so session resolution must be updated: given the task (already looked up via `GetTaskBySessionID`), read the session file from `<RuntimeTaskBuildmaxDir(workspaceID, taskID)>/sessions/<session_id>.json`; optionally fall back to global `SessionsDir` for backward compatibility with sessions created before this change.

## Scope

**In scope**

- Define under the existing runtime task path two subdirs: `buildmax/` and `ws/`.
- Executor: create `buildmax` and `ws` under the task dir; materialize persist into `ws` (not the task dir root); run `buildmax -p` with `BUILDMAX_HOME=<taskDir>/buildmax` and `cmd.Dir=<taskDir>/ws`; keep writing `result-<taskID>.md` at task dir root (not inside `ws`).
- Config: add path helpers so executor (and tests) can resolve task dir, buildmax subdir, and ws subdir without string concatenation (e.g. `RuntimeTaskBuildmaxDir`, `RuntimeTaskWSDir` or equivalent).
- Update executor tests and any config tests that assert on runtime layout.
- **Session API**: Update `GET /api/sessions/{session_id}` so that when a task is found for the session_id, the session file is read from that task’s buildmax dir (`<taskDir>/buildmax/sessions/<session_id>.json`); optionally fall back to global `SessionsDir` for older sessions.

**Out of scope**

- Cleanup or retention policy for old runtime task dirs.
- Changing `ArtifactDir`, `PersistentWorkspaceDir`, or blob storage layout.
- Portal or API changes.
- Changing how non-server (interactive) runs use `BUILDMAX_HOME` or CWD.

## Deliverables

1. **Config** (`internal/config`): Add functions that return, for a given `(workspaceID, taskID)`:
   - Task dir: keep existing `RuntimeWorkspaceDir(workspaceID, taskID)` as the task root (no semantic change).
   - Buildmax subdir: e.g. `RuntimeTaskBuildmaxDir(workspaceID, taskID)` = `filepath.Join(RuntimeWorkspaceDir(workspaceID, taskID), "buildmax")`.
   - WS subdir: e.g. `RuntimeTaskWSDir(workspaceID, taskID)` = `filepath.Join(RuntimeWorkspaceDir(workspaceID, taskID), "ws")`.
2. **WorkspacePaths** (`internal/executor/paths.go`): Extend interface with `RuntimeTaskBuildmaxDir(workspaceID, taskID string) string` and `RuntimeTaskWSDir(workspaceID, taskID string) string`. Implementations in `internal/cmd` (server) and executor tests must be updated.
3. **Executor** (`internal/executor/executor.go`): In `executeTask`:
   - Create task dir, then `buildmax` and `ws` subdirs (e.g. via the new path helpers).
   - Call `persist.MaterializeToDir(ctx, task.WorkspaceID, wsDir)` instead of `runtimeDir`.
   - Build `exec.Cmd` with `cmd.Dir = wsDir` and `cmd.Env` including `BUILDMAX_HOME=<buildmaxDir>` (preserve existing env for other vars).
   - Write result file to task dir: `resultPath = filepath.Join(taskDir, resultFilename)` (taskDir = current runtimeDir from paths).
4. **Tests**: Update executor tests (and any config path tests) to create/assert the new layout and env; ensure no real API calls.
5. **Server session handler** (`internal/server/session.go`): When serving `GET /api/sessions/{session_id}`, after resolving the task via `GetTaskBySessionID`, resolve the session file path as `filepath.Join(RuntimeTaskBuildmaxDir(task.WorkspaceID, task.TaskID), "sessions", sessionID+".json")`. If that file exists, read from it; otherwise fall back to the existing global `SessionsDir` path so that sessions created before the re-org (or outside the executor) still work.

## Acceptance criteria

- [ ] Under `<workspacesDir>/<workspaceID>/tasks/<taskID>/` the executor creates `buildmax/` and `ws/`; persist files are materialized into `ws/` only.
- [ ] When the executor runs `buildmax -p`, the process has `BUILDMAX_HOME` set to `<taskDir>/buildmax` and working directory `<taskDir>/ws`; sessions and logs for that run are stored under `buildmax/`.
- [ ] Result file `result-<taskID>.md` is written at task dir root (same as today), and artifact creation continues to work.
- [ ] `WorkspacePaths` includes the new buildmax and ws path methods; server and executor tests use them and pass.
- [ ] `GET /api/sessions/{session_id}` reads the session file from the task’s `<taskDir>/buildmax/sessions/<session_id>.json` when present, and falls back to global `SessionsDir` otherwise.
- [ ] `go build ./...` and `go test ./...` pass (with `BUILDMAX_HOME` set for tests as today where needed).
