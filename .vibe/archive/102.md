# Task 102: Gui common components

## Goal

Identify which UI components in portal (and desktop, where applicable) are good candidates to consolidate into `@buildmax/gui`, and implement **one concrete slice** — the base modal — so both apps can reuse it and the pattern for adding shared components is established.

## Context

- **Task 101** introduced `@buildmax/gui` with theme only (ThemeProvider, useTheme, ThemeToggle, theme.css). Portal and desktop both consume it.
- **Portal** has many presentational components: BaseModal (used by SettingsModal, NewChatFromAgentModal, ArtifactContentModal, CreateEntityModal), PromptArea, Sidebar, UserAvatar, Breadcrumbs, various modals and form pieces. Modal base styles live in `portal/src/css/modal.css` (overlay, .modal, .modal__header, .modal__title, .modal__close, .modal__body, plus portal-specific .modal--settings and form helpers).
- **Desktop** currently has a minimal UI (single App.jsx with inline chat); it will gain modals and other UI over time and can reuse the same base components.
- **Convention** (from 101): Share widgets, not app logic. Components in gui are presentational and accept props/callbacks; each app keeps its own state and API calls.

## In scope

1. **Consolidation analysis** — Document a short list of components that are good candidates to move into gui next (beyond the one implemented in this task), with brief rationale. Place this in the gui package README (e.g. "Consolidation candidates" section) so future work can pick from it.
2. **BaseModal in gui** — Move the base modal component and the minimal CSS it needs into `@buildmax/gui`:
   - **Component**: Same API as current portal `BaseModal`: `open`, `title`, `titleId`, `onClose`, optional `className`, optional `hideHeader`, `children`. Behavior: overlay click and Escape close, focus management, ARIA attributes.
   - **CSS**: Provide `modal.css` (or include in a single gui modal stylesheet) with: `.modal-overlay`, `.modal`, `.modal--large`, `.modal__header`, `.modal__title`, `.modal__close`, `.modal__body`, and any keyframes used by these. Use existing theme variables (e.g. `var(--color-bg-elevated)`, `var(--shadow-modal)`) so it fits both apps.
3. **Portal integration** — Portal imports `BaseModal` and base modal CSS from `@buildmax/gui`; remove local `BaseModal.tsx` and the base modal rules from `portal/src/css/modal.css`. Keep in portal all modal variants and form helpers (e.g. `.modal--settings`, `.settings-modal__*`, `.modal__input`, `.modal__btn--primary`) that are specific to portal screens.
4. **Desktop** — No change required for desktop in this task; desktop can adopt `BaseModal` from gui when it adds modals later.
5. **Docs** — Update gui README: document `BaseModal` and modal CSS export; add the "Consolidation candidates" section.

## Out of scope

- Moving other components in this task (PromptArea, chat bubbles, sidebar, UserAvatar, buttons, form inputs, etc.).
- Design system, tokens, or Storybook.
- Publishing the package to npm.

## Deliverables

1. **gui package**
   - New export: `BaseModal` (and type for props if applicable).
   - New style export: modal base CSS (e.g. `@buildmax/gui/modal.css` or equivalent) containing only the rules required by BaseModal; no portal-specific variants.
   - README: "Consolidation candidates" section listing recommended next components (e.g. PromptArea / composer, chat message bubble, primary/secondary button, icon set) with one-line rationale; plus documentation for BaseModal and modal CSS usage.
2. **Portal**
   - Uses `BaseModal` and modal base CSS from `@buildmax/gui`.
   - Local `BaseModal.tsx` removed; `portal/src/css/modal.css` only retains portal-specific rules (and imports gui modal CSS if needed).
   - All existing modals (SettingsModal, NewChatFromAgentModal, ArtifactContentModal, CreateEntityModal) continue to work.
3. **Build and run** — `cd gui && npm run build`, portal `npm run build` and `npm run dev` succeed.

## Acceptance

- [ ] gui exports `BaseModal` and a modal base CSS file; package build produces the new assets.
- [ ] gui README includes a "Consolidation candidates" section and documents BaseModal/modal CSS.
- [ ] Portal imports BaseModal and modal base styles from `@buildmax/gui`; local BaseModal and duplicated base modal CSS removed.
- [ ] Portal modals (Settings, NewChatFromAgent, ArtifactContent, CreateEntity) still open, close, and look correct.
- [ ] `./make build` (or equivalent: gui build + portal build) succeeds.
