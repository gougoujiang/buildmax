# Task 029: Use --model arg to specify model

## Goal

Allow users to select which configured LLM model to use via a `--model` CLI flag; the flag selects an entry from `settings.json` by model ID or display name, and applies to both prompt mode and TUI.

## Context

- **Current behaviour**: `config.EffectiveLLM("")` returns the first model from `settings.json` or falls back to env via `LoadLLM()`. `setupAgentAndSession(resumeID)` calls it with no override; both `runPrintMode` and `runTUI` use the same setup. Model is shown in TUI footer and prompt mode.
- **Where it fits**: Root command in `internal/cmd/root.go` defines flags; `setup.go` calls `EffectiveLLM`. Selection must be resolved in config (settings have `model` and `name` per entry); cmd passes the override into setup.
- **Conventions**: AGENTS.md §6.1 (snake_case for persisted data). Settings path: `config.SettingsPath()`; structure from task 028 (`models` array with `model`, `name`, `api_url`, `api_key`).

## In scope

- **`--model` flag**: Add a root flag `--model` (string, optional). When set, the app uses this value to choose one entry from `settings.json` instead of the first entry.
- **Matching rule**: Treat the flag value as a selector: match against each entry’s `model` (ID) first; if no match, match against `name` (display). Comparison is exact (no case folding or trimming beyond normal string comparison). First matching entry wins.
- **When no settings or empty models**: If the user passes `--model` but the settings file is missing, unreadable, or `models` is empty, exit with a clear error (e.g. "no models in settings; add settings or omit --model"). If settings exist and have models but no entry matches the selector, exit with a clear error (e.g. "model not found: <value>").
- **Prompt and TUI**: Same behaviour in both modes: `runPrintMode` and `runTUI` receive the selected model via the existing setup result (no separate code paths).
- **Display name**: Use the selected entry’s `name` if set, else `model`, for TUI footer and any prompt-mode display.

## Out of scope

- **Using a raw model ID not in settings**: If `--model` is set, it must refer to an entry in `settings.json`. No fallback to env or raw model ID for this task.
- **Env override when `--model` is set**: The chosen entry’s `api_key`, `api_url`, and `model` come only from that entry; no merging with env.
- **Creating or editing settings from the app**: Unchanged from task 028.
- **Model picker UI in TUI**: No in-app model switcher; CLI flag only.

## Deliverables

1. **`internal/config`**
   - Add a function that returns the effective LLM and display name with an optional model selector, e.g. `EffectiveLLMWithSelector(settingsPath, modelSelector string) (LLM, string, error)`. When `modelSelector` is empty, behaviour equals current `EffectiveLLM(path)` (first model or LoadLLM fallback; no error). When non-empty: load settings; if no models, return error; otherwise find an entry whose `model` or `name` equals `modelSelector`; if found, return that entry’s LLM and display name; if not found, return error. Keep `EffectiveLLM(path string) (LLM, string)` for callers that don’t need a selector (e.g. tests); it can delegate to `EffectiveLLMWithSelector(path, "")` and ignore error.
   - Document that the selector matches `model` first, then `name`; first match wins.

2. **`internal/cmd/root.go`**
   - Define `--model` / no short flag, string, default `""`. In `runRoot`, read the flag and pass the value to the code that performs setup (see below).

3. **`internal/cmd/setup.go`**
   - Change `setupAgentAndSession` to accept an optional model selector (e.g. `setupAgentAndSession(resumeID string, modelSelector string)`). Call `config.EffectiveLLMWithSelector("", modelSelector)`; on error, return the error (so runRoot/runPrintMode/runTUI can exit with message). Otherwise use the returned LLM and display name as today.

4. **`internal/cmd` call sites**
   - `runRoot`: Resolve `--model` and pass it to `runPrintMode` / `runTUI`, or pass it into a shared setup path. Both `runPrintMode(prompt, resumeID)` and `runTUI(resumeID)` currently call `setupAgentAndSession(resumeID)` with no second arg; extend the signature and pass the flag value from root (e.g. `runPrintMode(prompt, resumeID, modelOverride)`, `runTUI(resumeID, modelOverride)`, and have both call `setupAgentAndSession(resumeID, modelOverride)`).

5. **Tests**
   - Config: unit tests for `EffectiveLLMWithSelector` — empty selector uses first model or fallback; non-empty selector matches `model`; non-empty matches `name`; no match returns error; no settings + non-empty selector returns error.
   - Build and `go test ./...` pass.

## Acceptance

- [ ] Root command has a `--model` flag (string, optional). When omitted, behaviour is unchanged (first model from settings or env fallback).
- [ ] When `--model <value>` is set, the app selects the settings entry whose `model` or `name` equals `<value>`; first match wins. Both prompt mode and TUI use that model.
- [ ] If `--model` is set and settings have no models (missing file, empty, or invalid), the app exits with a clear error and does not start.
- [ ] If `--model` is set and no entry matches, the app exits with a clear error (e.g. "model not found: ...").
- [ ] Display name in TUI footer and prompt mode reflects the selected entry’s `name` or `model`.
- [ ] Config has unit tests for selector behaviour (empty, match by model, match by name, no match, no settings).
- [ ] `go build ./...` and `go test ./...` succeed.
