# Task 027: Add current git branch at bottom status line in interactive mode

## Goal

Show the current Git branch in the TUI footer when running in interactive mode, so the user can see which branch they are on without leaving the app.

## Context

- The TUI footer is built in `internal/tui/model.go` in `Model.View()`: it currently shows `model: <name> | @<workspace> | ctrl+c: quit | esc: clear/focus input` (and optionally `| error: ...`).
- `TUIOpts` is populated in `internal/cmd/tui.go` with `Workspace` set to `res.CWD` (current working directory). The same directory is the natural place to resolve the Git branch (e.g. run `git branch --show-current` from that dir).
- The project uses no Git library today; resolving branch via `exec` of `git` from the workspace dir keeps the change minimal and avoids new dependencies (AGENTS.md: implement in Go where possible; calling out to `git` is acceptable).

## In scope

- Resolving the current branch once when the TUI starts (from the workspace directory). No live refresh during the session.
- Displaying the branch in the footer (e.g. `branch: <name>`). If not a Git repo or `git` fails, show a neutral value (e.g. `branch: -` or omit the segment) so the UI does not show an error for a normal non-repo case.
- Only the interactive TUI is affected; prompt mode and other CLI paths are unchanged.

## Out of scope

- Refreshing the branch during the TUI session (e.g. on tick or after commands).
- Showing commit hash, status, or other Git info.
- Adding a dedicated config or flag to enable/disable the branch line.

## Deliverables

1. **Branch resolution**
   - A way to get the current branch name for a given directory (e.g. run `git branch --show-current` with that dir as working dir). Place under `internal/` (e.g. a small helper in `internal/tui` or a new `internal/git` package). Return the branch name (trimmed) or empty string on error / not a repo.

2. **TUIOpts**
   - Add a field to hold the branch string (e.g. `Branch string`). When empty, footer shows `branch: -` (or equivalent) so the layout is consistent.

3. **TUI wiring**
   - In `internal/cmd/tui.go`, when building `TUIOpts`, resolve the branch from the workspace dir and set the new field.

4. **Footer**
   - In `internal/tui/model.go`, extend the footer string to include the branch (e.g. `| branch: <name>`). Keep existing order and style (model, workspace, branch, shortcuts, error).

5. **Tests**
   - Unit test for the branch-resolver: when run from a directory that is a Git repo, return the current branch; when run from a non-repo or invalid dir, return empty (or covered by integration). No real Git required in tests: use a temp dir and optionally `git init` + `git checkout -b test-branch` in test, or mock by testing the helper with an empty dir and a dir created with `git init`).

## Acceptance

- [ ] TUI footer in interactive mode shows a branch segment (e.g. `branch: main` or `branch: -` when not in a repo).
- [ ] Branch is resolved from the workspace directory (same as `@<workspace>` in the footer).
- [ ] Non-Git directories do not show an error; they show a neutral placeholder (e.g. `branch: -`).
- [ ] Prompt mode and other commands are unchanged.
- [ ] `go build ./...` and `go test ./...` pass.
- [ ] No new external dependencies (use `os/exec` to run `git branch --show-current`).
