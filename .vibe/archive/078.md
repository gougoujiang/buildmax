# Task 078: Supports agents.md

## Goal

Make the BuildMax CLI agent's system prompt dynamic by appending project-specific instructions from an AGENTS.md file at the workspace root when present, following the [agents.md](https://agents.md/) convention.

## Context

- **agents.md convention**: A Markdown file (typically named AGENTS.md) at the root of a repository provides agent-focused instructions (build steps, tests, conventions). Plain Markdown; no required structure. We read it and append to the system prompt so the LLM gets project context.
- **Existing code**: `internal/agent`: `DefaultSystemPrompt` constant and `SystemPrompt(prompt string)` option for `NewAgent`; `processLoop` uses `a.systemPrompt` as the single system message. `internal/cmd/setup.go`: `setupAgentAndSession` gets `cwd` via `os.Getwd()`, builds tools and agent with `agent.NewAgent(client, tools)` (no custom prompt today).
- **Scope**: CLI only (`buildmax` / `cmd/buildmax`). No changes to `buildmax-server` or `buildmax-worker`; they do not use this system prompt.
- **Conventions**: All-Go; follow AGENTS.md layout (`internal/agent`, `internal/cmd`); no new runtime deps.

## Workspace root and AGENTS.md (this task)

For this task:

1. **Workspace root** = current working directory when the user runs `buildmax` (same as the `cwd` already used in `setupAgentAndSession` for tools and agent-def search paths).
2. **AGENTS.md** = a file named `AGENTS.md` at that directory. We do not create or write it; we only read it if present. If missing, behavior is unchanged (default system prompt only).
3. **Dynamic system prompt** = `DefaultSystemPrompt` + optional `"\n\n"` + raw contents of AGENTS.md (no parsing; the file is appended as-is so the project can use any Markdown structure).

We are **not** yet implementing:

- Nested or multiple AGENTS.md files (e.g. “closest file wins”).
- Support for an alternate filename (e.g. `agents.md`) in this task.
- Any change to worker, server, or Portal.

## Deliverables

1. **System prompt composition**
  - In `setupAgentAndSession` (or a small helper it calls), compute the effective system prompt: if `AGENTS.md` exists under workspace root, append its contents (trimmed) after `DefaultSystemPrompt` with a double newline; otherwise use `DefaultSystemPrompt` only.
  - Pass the result into `agent.NewAgent(..., agent.SystemPrompt(effectivePrompt))`.
2. **Reading AGENTS.md**
  - Add a function that, given the workspace root directory path, returns the contents of `AGENTS.md` if the file exists and is readable, or empty string if not (missing file or read error treated as “no extra content”; log read errors at debug or warn level). Place this in a package that fits the project layout—e.g. `internal/agent` (e.g. `ReadAgentsMd(dir string) (string, error)`) or `internal/config`—and use it from `internal/cmd/setup.go`.
  - File path: `filepath.Join(rootDir, "AGENTS.md")`. No symlink resolution beyond normal `os.ReadFile`.
3. **Tests**
  - Unit test(s) for the “read AGENTS.md” behavior: when file exists, content is returned; when file is missing or directory missing, empty string (or error as designed) and no panic. Prefer table-driven tests.
4. **Documentation**
  - Brief note in AGENTS.md (project design doc) that the CLI supports an optional `AGENTS.md` at workspace root and appends it to the system prompt (reference [https://agents.md/](https://agents.md/) as needed).

## Out of scope (for later)

- Supporting `agents.md` (lowercase) or other filenames.
- Nested / multiple AGENTS.md resolution.
- Worker, server, or Portal using AGENTS.md.
- Creating or scaffolding AGENTS.md from the CLI.

## Acceptance

- When `AGENTS.md` exists at the workspace root (cwd when running `buildmax`), the agent receives `DefaultSystemPrompt` + `"\n\n"` + file contents as the system message.
- When `AGENTS.md` is missing or unreadable, the agent uses only `DefaultSystemPrompt` (current behavior).
- No code paths in `buildmax-server` or `buildmax-worker` depend on AGENTS.md or this prompt composition.
- Unit test(s) cover “file present” and “file absent” (and optionally “read error”) for the read function.
- `go build ./...` and `go test ./...` pass.
- AGENTS.md (project doc) mentions CLI support for workspace-root AGENTS.md and links to agents.md where appropriate.
