# Task 038: Add project

Add project persistence and APIs so projects are owned by a workspace; users can list projects for a workspace and create a new project. Portal migrates from mock project data to the real backend API.

---

## Goal

**One sentence:** Add a project table (id, workspace_id, name, description, created_at), expose `GET /api/workspaces/{workspace_id}/projects` and `POST /api/workspaces/{workspace_id}/projects` with JWT and workspace-ownership checks, and have the portal load and create projects via the API instead of mock data.

---

## Context

- **Server:** `internal/server` — HTTP server with `/api/login`, `GET /api/workspaces` (JWT required). Workspace list is per authenticated user; workspace ids are UUIDs.
- **Store:** `internal/store` — MySQL via GORM; `User`, `Workspace` models; `WorkspaceStore` with `EnsureDefaultWorkspaceForUser`, `ListWorkspacesByOwner`. AutoMigrate runs for User and Workspace.
- **Design (001):** Project = executable work unit under a workspace; hierarchy is Workspace → Project → Tasks/Artifacts.
- **Portal:** Projects are mock-only in `portal/src/data/mockData.ts` (`MOCK_PROJECTS`, `listProjectsForWorkspace`, `getProjectById`). `App.tsx` calls `listProjectsForWorkspace(route.workspaceId)` and passes result to `WorkspaceHome` and project routes. `Project` type in `portal/src/lib/types.ts`: id, workspaceId, name, status, updatedAtLabel (status/updatedAtLabel are UI-only for now; backend will provide id, workspace_id, name, description, created_at).
- **Conventions:** AGENTS.md — persisted data uses snake_case in JSON; backend in Go; portal calls Go API.

---

## In scope

- **Project table (MySQL, same store)**
  - Columns: `id` (UUID, primary key), `workspace_id` (FK to workspaces), `name` (display name), `description` (text, optional), `created_at` (Unix timestamp or equivalent).
  - JSON/API: snake_case (`workspace_id`, `created_at`).
  - Table name: `projects`.

- **Backend API**
  - **`GET /api/workspaces/{workspace_id}/projects`** — requires valid JWT. Returns list of projects for the given workspace. Caller must own the workspace (authenticated user’s id = workspace’s owner_user_id); otherwise 403. Response: array of `{ "id", "workspace_id", "name", "description", "created_at" }`. 401 when no/invalid token.
  - **`POST /api/workspaces/{workspace_id}/projects`** — requires valid JWT. Body: `{ "name", "description" }` (name required). Creates a project under the given workspace. Caller must own the workspace; otherwise 403. Returns 201 and the created project object (same shape as list item). 400 if name missing or invalid. 401 when no/invalid token.

- **Store layer**
  - Add `Project` model and persistence (e.g. `ProjectStore` or methods on existing Store): list projects by workspace_id, create project. Enforce that workspace_id exists and is owned by the same user when creating (or delegate to handler). Use same DB and GORM; AutoMigrate for `Project`.

- **Portal**
  - When authenticated and in a workspace, load projects via `GET /api/workspaces/{workspaceId}/projects` (with `Authorization: Bearer <token>`). Use returned list for workspace home and for resolving project by id (replace mock `listProjectsForWorkspace` / `getProjectById` with API-backed data when available). Support creating a new project (e.g. from workspace home) via `POST /api/workspaces/{workspaceId}/projects` and then refresh list or navigate to the new project.
  - Map API project shape (id, workspace_id, name, description, created_at) to existing `Project` type where needed (e.g. derive or default status/updatedAtLabel from created_at for display).

- **OpenAPI**
  - Document `GET /api/workspaces/{workspace_id}/projects` and `POST /api/workspaces/{workspace_id}/projects` (auth: Bearer JWT; request/response schemas).

---

## Out of scope

- **Opening a project** to show its tasks/artifacts in detail — UI already exists with mock data; this task only switches project list and create to the real API. Task/artifact APIs and persistence are future work.
- **Update/delete project** — not in this task.
- **Project status or updated_at** in the backend — optional follow-up; portal can use placeholders from created_at for now.

---

## Technical notes

- **Project id:** UUID (same style as Workspace id).
- **Workspace ownership:** Before listing or creating projects for a workspace, resolve the workspace by id and ensure `workspace.OwnerUserID == userID` from JWT; otherwise return 403.
- **Path parameter:** Use Go 1.22+ ServeMux pattern like `GET /api/workspaces/{workspace_id}/projects` and parse workspace_id from the path; validate ownership in handler.
- **Portal create flow:** Add a way to create a project (e.g. “New project” on workspace home); call POST with name (and optional description), then either refetch list and show workspace home or navigate to the new project page.

---

## Deliverables

1. **internal/store**
   - `Project` struct: id (UUID), workspace_id, name, description, created_at; GORM and `json:"snake_case"` tags.
   - Interface or methods: list projects by workspace_id; create project (with workspace_id, name, description). AutoMigrate `Project`.

2. **internal/server**
   - Register `GET /api/workspaces/{workspace_id}/projects` and `POST /api/workspaces/{workspace_id}/projects`. Extract user id from JWT; resolve workspace and check ownership; list or create project; return JSON. Return 401/403/400/201 as specified.
   - Update OpenAPI spec with both endpoints.

3. **Portal**
   - API client: e.g. `getProjects(workspaceId, token)` and `createProject(workspaceId, body, token)` in `api.ts`, calling the new endpoints with Bearer token.
   - App/workspace home: when authenticated, fetch projects for the current workspace from the API; use that list instead of mock `listProjectsForWorkspace`. Add “New project” (or equivalent) that calls create API and refreshes or navigates.
   - Map API response to existing `Project` type for display (id, workspaceId, name; status/updatedAtLabel can be derived or defaulted from created_at).

4. **Tests**
   - Backend: test list projects (empty list when none; 403 when workspace not owned); test create project (201 and body; 403 when workspace not owned; 400 when name missing). No real external API in tests.

## Acceptance criteria

- [ ] Project table exists with columns id, workspace_id, name, description, created_at (snake_case in JSON); AutoMigrate adds it.
- [ ] `GET /api/workspaces/{workspace_id}/projects` without valid JWT returns 401.
- [ ] `GET /api/workspaces/{workspace_id}/projects` with valid JWT and workspace not owned by user returns 403.
- [ ] `GET /api/workspaces/{workspace_id}/projects` with valid JWT and owned workspace returns 200 and array of projects (possibly empty).
- [ ] `POST /api/workspaces/{workspace_id}/projects` with valid JWT, owned workspace, and body `{ "name": "My Project" }` returns 201 and the created project object.
- [ ] `POST /api/workspaces/{workspace_id}/projects` with missing or invalid name returns 400; with non-owned workspace returns 403.
- [ ] OpenAPI spec documents both project endpoints.
- [ ] Portal, when logged in and in a workspace, loads projects from the API and displays them on workspace home; user can create a new project and see it in the list or navigate to it.
- [ ] `go build ./...` and `go test ./...` pass.
