# Task 009: Cobra integration to support subcommands

## Goal

Replace the current `flag`-based CLI with Cobra so that the root command runs the TUI by default, keeps prompt-and-quit via `-p`/`--resume`, and adds a `version` subcommand, establishing a structure for future subcommands (e.g. chat, config).

## Context

- **Current CLI** (`cmd/buildmax/main.go`): Uses `flag` for `-h`, `-p`, `--resume`. No subcommands; `main()` branches on flags then either starts TUI or calls `runPromptMode()`.
- **Existing behavior to preserve**: `buildmax` → TUI; `buildmax -p PROMPT` → one-shot prompt, print reply, save session, exit; `buildmax --resume ID -p PROMPT` → resume session, send prompt, save, exit. Help text is in a `usage` constant.
- **Project**: All-Go CLI (AGENTS.md); single binary; `./make build` and `./make test` for build and test.
- **No version today**: There is no version constant or ldflags in the repo; the `version` subcommand will display a defined value (e.g. a constant or placeholder like `dev` until build tooling injects it later).

## “Root command” and “subcommand” (this task)

- **Root command** = the `buildmax` command. When run with no subcommand and no `-p`, it starts the TUI. When run with `-p` (and optionally `--resume`), it runs prompt-and-quit and exits. Help and version are available via flags or subcommands as below.
- **Subcommand** = a named child command (e.g. `buildmax version`). For this task we add only `version`. Other subcommands (e.g. `config`, `chat`) are out of scope.

We are **not** yet implementing:

- A separate `chat` or `run` subcommand; prompt-and-quit remains flags on the root.
- Config subcommand, Viper, or config-file binding.
- Shell completion (e.g. `buildmax completion bash`).

## Deliverables

1. **Dependency**
   - Add `github.com/spf13/cobra` to `go.mod` (e.g. `go get github.com/spf13/cobra`). No other CLI libs required for this task.

2. **Root command**
   - Define a Cobra root command whose default behavior (when no subcommand and no `-p`) is to start the TUI (same as today: `tea.NewProgram(app.NewModel(), ...)`).
   - Add persistent or local flags: `-p` / `--prompt` (string), `--resume` (string). Validation: if `--resume` is set, `-p` must be set; otherwise exit with a clear error (same as today).
   - When `-p` is provided, run the existing prompt-and-quit flow (current `runPromptMode` logic): load config, create agent/session, process prompt, save session, print reply, exit. Do not start the TUI.
   - Use Cobra’s help so that `buildmax -h` / `buildmax --help` shows usage and lists subcommands (e.g. `version`). Preserve the gist of the current usage text (TUI vs prompt mode, sessions, env vars) in the root’s `Long` or similar.

3. **Version subcommand**
   - Add a `version` subcommand. When the user runs `buildmax version`, print the application version (e.g. one line: `buildmax version 0.0.0` or `buildmax dev`). Version value can be a constant in code (e.g. `var version = "dev"`) for now; ldflags injection can be a follow-up.

4. **Main entry**
   - `main()`: init logging, then execute the root command (e.g. `root.Execute()`). Remove direct use of `flag`; all parsing is via Cobra.

5. **Tests and build**
   - No new test file is required for this task if the team prefers manual verification. Ensure `./make build` and `./make test` succeed after the change.

## Out of scope (for later)

- Additional subcommands (e.g. `config`, `chat`, `run` as a subcommand).
- Viper or config file binding to Cobra.
- Shell completion.
- Injecting version via ldflags in the build script (can be a later task).

## Acceptance

- [ ] `buildmax` with no args starts the TUI (same behavior as before).
- [ ] `buildmax -p "hello"` runs prompt-and-quit: prints the agent reply and exits; session is saved under the app data dir.
- [ ] `buildmax --resume <session-id> -p "hello"` resumes the given session, sends the prompt, saves, and exits.
- [ ] `buildmax --resume <id>` without `-p` exits with a clear error (e.g. “--resume requires -p”).
- [ ] `buildmax version` prints the application version (e.g. `buildmax version 0.0.0` or `buildmax dev`).
- [ ] `buildmax -h` / `buildmax --help` shows help for the root command and lists subcommands (including `version`).
- [ ] `./make build` succeeds.
- [ ] `./make test` passes.
