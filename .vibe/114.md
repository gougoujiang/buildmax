# Task 114: TUI /skills slash command

## Goal

Add **`/skills`** as a **builtin TUI slash command** that shows every **skill the agent can use** (same discovery rules as the `skill` tool) in a **dedicated on-screen panel**, without treating the command or its output as a chat turn.

## Context

- **Slash commands** (task 113): `internal/tui/slash.go` — `builtinSlashCommands`, `dispatchSlashCommand`, `syncSlashPopupFromInput`; `internal/tui/model.go` — on Enter, lines starting with `/` call `dispatchSlashCommand` and **must not** `session.Append` or run the agent.
- **Skill discovery** today: `internal/tools/skill.go` — `discoverSkills(searchPaths)` (unexported), `SkillEntry` (`Name`, `Description`, `Path`), `NewSkill`; rules: one level under each search path, subdirectory with `SKILL.md`, first path wins on name conflict, sorted by name; description from first non-empty non-heading line in `SKILL.md`.
- **Search paths**: `internal/config/config.go` — `SkillSearchPaths(workspace)` → `<workspace>/.buildmax/skills`, then `<DataDir>/skills`.
- **Agent wiring**: `internal/app/agentrun/runtime.go` registers `tools.NewSkill(skillPaths)` with those paths; the TUI holds `*agent.Agent` in `TUIOpts` but **does not** expose the `SkillTool` instance. The list should still match the tool by reusing the **same discovery code** as `NewSkill` (export a small listing API from `internal/tools` rather than duplicating scans in the TUI).
- **UI precedent**: `internal/tui/mcp_overlay.go` — bordered panel above the input (`mcpInlineBoxStyle`), not in the chat viewport; **Esc** closes via `closeMCPOverlay` in the key handler chain.

## In scope

1. **`/skills` dispatch**

   - Register `/skills` in `builtinSlashCommands` (keep the list sorted).
   - On `/skills`, open a **skills system panel** (new overlay state on `Model`, same general pattern as `/mcp`: panel above input, not chat history).
   - **No** `session.Append`, **no** LLM/agent call, **no** `PersistAfterReply` for this command; clear the input after handling (same as other slash commands).
   - While `busy`, Enter behavior unchanged (no slash handling for new submits — already the case).

2. **Panel content**

   - Resolve paths with `config.SkillSearchPaths(TUIOpts.Workspace)` and list skills using **shared** `internal/tools` discovery (e.g. export `DiscoverSkillEntries(paths []string) []SkillEntry` and use it from both `NewSkill` and the TUI, so behavior cannot drift).
   - **Empty**: explicit empty state (e.g. short copy + where skills live: `.buildmax/skills` under the workspace and global `DataDir()/skills`).
   - **Non-empty**: stable order (same as today: alphabetical by name); each row shows at least **skill name** and **description** (truncate long lines for width like the tool’s `extractDescription` cap). Showing filesystem **path** per skill is optional; if shown, keep it secondary (muted / second line) so the list stays readable.

3. **Interaction**

   - **Esc** closes the skills panel and returns to normal chat + input with **input focused**; the skills panel must be handled in the Esc chain **before** the generic “clear input” Esc path (mirror `/mcp` / `/session` precedence).
   - If the slash completion popup is open, existing behavior wins (Esc dismisses completion first).

4. **Tests**

   - Extend `internal/tui` tests: `/skills` does not append to session and does not start an agent run; overlay opens with expected content for a temp dir that contains a minimal skill tree; Esc closes overlay and restores input focus.
   - Add or extend `internal/tools` tests for the exported discovery/list helper if needed (table-driven, temp dirs only; **no** network).

5. **Discoverability**

   - Update the **unknown slash command** message in `dispatchSlashCommand` to mention `/skills` alongside existing builtins.
   - Optional: one-line footer hint where other slash hints already exist (match existing style; do not spam the footer).

## Out of scope

- **`-p` / prompt mode** slash commands.
- **Portal / desktop** UIs.
- **Invoking** a skill from the panel (read-only list).
- **Hot reload**: the list reflects a **fresh disk scan** when the user runs `/skills`; it does not change how or when the agent’s registered tools refresh (still a separate concern / session restart).
- **Cursor / VS Code “skills”** — only filesystem skills used by the `skill` tool.

## Acceptance criteria

- [ ] `/skills` is **never** a chat turn: no `session.Append` for the command line or for the listing; no LLM call.
- [ ] Non-slash messages and existing slash commands (`/mcp`, `/session`, …) behave as before.
- [ ] The listing uses **`SkillSearchPaths(workspace)`** and the **same discovery semantics** as `NewSkill` (single implementation in `internal/tools`).
- [ ] Empty and non-empty states are clear in the dedicated panel; chat viewport is not used for the list body.
- [ ] **Esc** closes the skills panel and leaves **input focused**.
- [ ] Slash completion includes `/skills`; unknown commands mention `/skills` in help text.
- [ ] `go test ./...` passes; tests use temp dirs only, no real API or network.
