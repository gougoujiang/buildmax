# Task 112: Variable interpolation in MCP config loading

## Goal

After parsing `mcp.json`, expand `$VAR` / `${VAR}` in MCP server string fields so URLs, commands, args, and child `env` values can use secrets and paths without duplicating them in the file.

## Implemented behavior

- **Load paths:** If `BUILDMAX_MCP_CONFIG` points at an existing file, only that file is loaded. Otherwise **merge** `DataDir()/mcp.json` with `<workspace>/.buildmax/mcp.json` (workspace entries override the same server id).
- **Expansion:** `os.Expand` with **`mcpExpandMapping`**: built-in **`EnvKeyBuildmaxWorkspaceRoot` (`BUILDMAX_WORKSPACE_ROOT`)** is the `workspaceDir` argument to `LoadMCPConfigForWorkspace` (not `os.Getenv` for that name); all other names use **`os.Getenv`**. Hook point for future plugin/tool-injected names is the mapping switch in `internal/config/mcp.go`.
- **Fields expanded:** `command`, each `args` element, each `env` value, `url` — after parse/merge, before validation.
- **Note:** Go’s `os.Expand` does **not** treat `$$` as a literal dollar (unlike POSIX shells).

## Acceptance criteria

- [x] Expansion runs on merged or single-file config before validation.
- [x] `BUILDMAX_WORKSPACE_ROOT` expands to the loader’s workspace directory.
- [x] Other variables use the process environment via `os.Getenv`.
- [x] `go test ./internal/config/...` passes (including merge + interpolation tests).
- [x] No new `go.mod` dependencies.
