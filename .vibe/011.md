# Task 011: TUI improvements

## Goal

Improve the Bubble Tea TUI with light sky blue styling, multi-line text wrapping for input and chat, immediate display of the user message on send, and an "assistant: . / .. / ..." carousel while waiting for the LLM.

## Context

- **Existing TUI**: `internal/tui` — Bubble Tea `Model` with viewport (banner + chat from `buildViewportContent`), `textarea` input, footer. `format.go` formats messages as "you: …" / "assistant: …"; `inputBoxStyle` uses gray border (240). Chat content is built from `session.Messages()`; long lines are not wrapped.
- **Session**: `session.Append(msg)` adds a message; `session.Messages()` returns a copy. Agent `Process(ctx, sess, userMessage)` appends the user message at the start, then runs the LLM loop and appends assistant/tool messages.
- **Current behavior**: On Enter, TUI clears input, sets `busy`, runs `runAgent(opts, text)` (blocking). Viewport is updated only when `agentDoneMsg` is received, so the user message does not appear until the agent finishes. While busy, the input box shows "... thinking ...".
- **Conventions**: All-Go stack, Bubble Tea for TUI; AGENTS.md and `tasks/` for layout and persistence (snake_case for persisted JSON).

## Styling and behavior (this task)

- **Light sky blue**: Use as the primary accent (e.g. `#87CEFA` or equivalent in lipgloss). Apply to: input box border; a vertical bar at the start of each user and assistant message line (not to the message text itself).
- **Text wrapping**: Input box wraps long text to multiple lines so the user can see earlier chat; chat history area wraps long message lines to the viewport width so nothing is cut off horizontally.
- **User message on send**: As soon as the user sends, the user message is appended to the session and shown in the chat area immediately, then the agent runs. The "thinking" placeholder in the input box is removed; the waiting state is shown by the assistant carousel in the chat area.
- **Assistant carousel**: While the agent is running, show a single line in the chat area: "assistant: ." then "assistant: .." then "assistant: ..." then back to "assistant: .", cycling on a timer until the real assistant reply replaces it.

## Deliverables

1. **internal/tui (styling)**
   - **Theme color**: Define a shared style or constant for light sky blue (e.g. `lipgloss.Color("#87CEFA")`).
   - **Input box**: Use the light sky blue color for the input box border (replace current `BorderForeground(lipgloss.Color("240"))` in `inputBoxStyle` or equivalent).
   - **Message styling**: In the chat output, add a vertical bar (e.g. `|`) at the beginning of each user and assistant message line, styled with light sky blue; keep the message text unstyled (default foreground).

2. **internal/tui (text wrapping)**
   - **Input**: Configure the textarea so long input wraps to multiple lines (e.g. set a max height such as 5 lines and allow the component to use multiple lines), so the viewport remains visible above. Resize logic must keep viewport height = total - input height - footer.
   - **Chat history**: When building viewport content, wrap each logical line to the viewport width (e.g. word-wrap or rune-wrap). Use the current viewport width (from `Model.width` or the viewport’s width) so long messages do not overflow horizontally.

3. **internal/tui (behavior: user message and carousel)**
   - **Immediate user message**: On submit (Enter with non-empty text): (1) append the user message to the session via `session.Append`; (2) rebuild viewport content from the session and set it on the viewport, then `GotoBottom()`; (3) set `busy = true`; (4) start the agent. The agent must not append the user message again (see agent deliverable).
   - **Assistant carousel**: Add state for the carousel (e.g. dot count 0, 1, 2 for ".", "..", "..."). When `busy` is true, append a line "assistant: ." / ".." / "..." to the viewport content and start a `tea.Tick` (e.g. ~400 ms) that sends a message to advance the dot count (0→1→2→0). When `agentDoneMsg` is received, stop the tick and replace the carousel line with the real assistant content.
   - **Remove input "thinking"**: When `busy` is true, do not show "... thinking ..." in the input box; show an empty input area (or a neutral placeholder like "Waiting for reply…"). The carousel in the chat area indicates that the agent is working.

4. **internal/agent**
   - **Entry point without appending user**: Add a way to run the agent loop when the user message is already in the session (so the TUI can append the user message, refresh the view, then call the agent). Options: (a) new method `ProcessAfterUserAppended(ctx, sess)` that assumes the last message in `sess` is the user message and runs the existing loop without calling `sess.Append` for that user message; or (b) `Process(ctx, sess, userMessage string, skipAppendUser bool)`. The TUI will call this after appending the user message and refreshing the viewport.

5. **Tests**
   - **internal/tui**: Extend or add tests as needed for: viewport content including carousel line when busy; wrapped chat lines (e.g. a long line is split to width); optional style assertions if feasible.
   - **internal/agent**: Test the new entry point (e.g. session with one user message; call `ProcessAfterUserAppended` or equivalent; assert session ends with an assistant message and no duplicate user message).

## Out of scope (for later)

- Session list/picker, config file, or new tools (see AGENTS.md planned items).
- Changing the banner art or footer layout beyond the described styling.
- Theming beyond light sky blue (e.g. dark/light theme switch).
- Accessibility or screen-reader-specific behavior.

- [ ] Long lines in the chat history wrap to the viewport width (no horizontal overflow).
- [ ] On send: user message appears in the chat area immediately; then the agent runs; no duplicate user message in history.
- [ ] While the agent is running, the chat area shows a cycling "assistant: ." / ".." / "..." line; when the reply arrives, that line is replaced by the real assistant message.
