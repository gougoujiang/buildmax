# Task 048: Use generated session id and save to task

## Goal

When the executor runs a task, generate a UUID session id **before** spawning the CLI, pass it to `buildmax --session-id <uuid>`, and persist it to the `task` table so every task execution is traceable back to its full agent conversation.

## Context

- The `buildmax` CLI already accepts `--session-id <uuid>` (`internal/cmd/root.go`). If the id doesn't match an existing session file, a new session is created with that id; if it does, the session is resumed.
- The executor (`internal/executor/executor.go`) currently spawns `buildmax -p "<input>"` with **no** `--session-id` flag, so the CLI generates a random session id that is never recorded on the task record.
- The `Task` model (`internal/store/store.go`) has **no** `session_id` column today.
- The API response (`TaskResponse` in `internal/server/tasks.go`) likewise has no `session_id` field.

## In scope

1. **Add `SessionID` field to `store.Task`** — nullable `varchar(36)`, column `session_id`. GORM AutoMigrate will add the column.
2. **Executor generates a UUID** before spawning the CLI and passes `--session-id <uuid>` alongside `-p`.
3. **Executor saves the session id to the task** by calling `UpdateTaskStatus` (or a new targeted update) to set `session_id` when marking the task as RUNNING.
4. **`UpdateTaskStatus` supports session_id** — accept an optional `sessionID *string` parameter (or add a separate `SetTaskSessionID` method).
5. **API response includes `session_id`** — add `session_id` (nullable, omitempty) to `TaskResponse` and `taskToResponse`.
6. **Update the `TaskStore` interface** if signatures change.

## Out of scope

- Fetching or displaying the session conversation in the portal (future task).
- Any new API endpoint to retrieve session contents.
- Changing how `--session-id` works in the CLI itself (it already works correctly).

## Acceptance criteria

- [ ] `store.Task` has a `SessionID *string` field with `gorm:"type:varchar(36)" json:"session_id,omitempty"`.
- [ ] GORM AutoMigrate adds the `session_id` column to the `task` table on startup.
- [ ] The executor generates a UUID session id and passes `--session-id <uuid>` when spawning `buildmax`.
- [ ] The executor persists the session id to the task record (visible in DB after task starts running).
- [ ] `GET /api/workspaces/{workspace_id}/tasks` returns `session_id` for tasks that have one.
- [ ] `POST /api/workspaces/{workspace_id}/tasks` response includes `session_id` (null for newly created PENDING tasks).
- [ ] `go build ./...` succeeds.
- [ ] `go test ./...` passes.
