# Task 101: Common GUI package for portal and desktop

## Goal

Introduce a shared GUI package at workspace root so portal and desktop can import common UI components and styles, reducing duplication and keeping visualization consistent — **implement once, use in both**.

## Sharing strategy

- **Desktop and portal are different apps** with different inner logic (data source, auth, routing, backend). We do **not** try to make them the same; we share **reusable presentational pieces** only.
- **Share widgets, not app logic.** The gui package should contain components that are purely or mostly about presentation and can accept data/callbacks from either app. Each app keeps its own state, API calls, and flow.
- **Good candidates for sharing** (this task does theme first; others are for later): **theme** (provider, toggle, CSS), **settings page** (or settings UI pieces), **chat history rendering** (message list / bubbles), **input box** (prompt/composer), and similar widgets. These can be designed with props/callbacks so portal and desktop plug in their own logic.

## Context

- **Portal** (`portal/`): React 19, Vite, TypeScript. Has `contexts/ThemeContext.tsx`, `components/ThemeToggle.tsx`, `css/theme.css` (and many other components).
- **Desktop** (`desktop/frontend/`): React 18 today; will be upgraded to React 19 in this task. Vite, JSX (no TypeScript). Has near-duplicate `ThemeContext.jsx`, `ThemeToggle.jsx`, `css/theme.css`.
- **Current state**: Theme logic and theme CSS are duplicated; both apps use the same `data-theme` and CSS variable names. No npm workspaces or shared package exists at repo root.
- **Convention**: Portal and desktop build independently; AGENTS.md describes portal as "React + Vite + TypeScript" and desktop as a Wails app with embedded React frontend.

## Common GUI package (this task)

For this task, "common GUI package" means:

1. A **new npm package** under the workspace root (e.g. `gui/`) that exports React components and optional CSS.
2. **First slice**: theme only — `ThemeProvider`, `useTheme`, `ThemeToggle`, and shared theme CSS (CSS variables for light/dark, same semantics as current portal/desktop).
3. **Consumers**: Portal and desktop add this package as a **local dependency** (e.g. `"@buildmax/gui": "file:../gui"`) and use the theme components and CSS from it; local copies of theme context, toggle, and theme CSS are removed.
4. Both apps will use **React 19**; the package targets React 19 only (`peerDependencies`: `react` and `react-dom` ^19.0.0). Desktop is upgraded from React 18 to 19 as part of this task (Wails does not require React 18).

We are **not** yet implementing:

- Migrating other shared-looking components (modals, sidebar, layout, icons).
- A full design system or component library.
- Storybook or visual regression tests.

## Deliverables

1. **Shared package `gui/` (or `packages/gui`)**
   - **package.json**: Name (e.g. `@buildmax/gui`), `main`/`module`/`types` exports, `peerDependencies` for `react` and `react-dom` ^19.0.0. Build script that produces a distributable (e.g. Vite library mode or `tsc` + bundler).
   - **Theme**: Export `ThemeProvider`, `useTheme`, `ThemeToggle` (and `Theme` type/constants if needed). Single implementation (TypeScript is fine; desktop can consume compiled JS).
   - **Theme CSS**: Export `theme.css` (or equivalent) with the same CSS variables and `[data-theme="light"]` / `[data-theme="dark"]` rules as today. Consumers import this file from the package.
   - **No TUI or Go code** in this package; frontend-only.

2. **Portal integration**
   - Add dependency on the new package (local path).
   - Replace `contexts/ThemeContext.tsx` and `components/ThemeToggle.tsx` with imports from `@buildmax/gui`; replace `css/theme.css` with import of the package’s theme CSS (or keep a thin wrapper if needed).
   - Portal continues to build and run (`npm run build`, `npm run dev`).

3. **Desktop integration**
   - Upgrade to React 19 (`react` and `react-dom` ^19.0.0).
   - Add dependency on the new package (local path).
   - Replace `ThemeContext.jsx` and `ThemeToggle.jsx` with imports from `@buildmax/gui`; replace local `css/theme.css` with package theme CSS.
   - Desktop frontend continues to build and run.

4. **Docs**
   - Short README in the package describing exports and how portal/desktop depend on it (local `file:` dependency).

## Out of scope (for later)

- Moving more shared widgets into the package: settings page (or settings UI), chat history rendering, input box / prompt area, modals, sidebar pieces, layout, icons.
- Design system, tokens, or Storybook.
- Publishing the package to npm.

## Acceptance

- [ ] Package `gui/` (or `packages/gui`) exists at repo root with valid package.json and build that produces consumable JS (and types where applicable) plus theme CSS.
- [ ] Package exports `ThemeProvider`, `useTheme`, `ThemeToggle` and a theme CSS file; no duplicated theme logic inside portal or desktop.
- [ ] Portal depends on the package, uses theme from it, and `portal` build + dev still work.
- [ ] Desktop frontend depends on the package, uses theme from it, and desktop frontend build + dev still work.
- [ ] Package README describes the package and local dependency setup.
- [ ] Desktop uses React 19 (same as portal).
