# Task 026 - Split internal/cmd/root.go by concern

## Goal

Split `internal/cmd/root.go` (309 lines, 12 imports) into four focused files so each file has a single responsibility, following the one-file-per-concern pattern already established with `version.go`.

## Context

- `internal/cmd/root.go` was recently extracted from `cmd/buildmax/root.go` (task 025). It contains command definition, flag handling, tool construction, agent-type wiring, session setup, and two run modes (TUI and prompt).
- `internal/cmd/version.go` already demonstrates the target pattern: one file per subcommand/run mode.
- All symbols being moved are unexported (same `cmd` package), so no API changes are needed.
- Smell proposals 1–5 in `.vibe/smell-20260214.md` detail each extraction.

## Splitting (this task)

For this task, "splitting" means:

1. Move setup infrastructure (`setupResult`, `buildBaseTools`, `buildAgentTypes`, `setupAgentAndSession`) into `setup.go`
2. Move `runPromptMode` into `prompt.go`
3. Move `runTUI` into `tui.go`
4. Introduce a `toolBuilder` helper in `setup.go` to reduce repetitive tool-creation boilerplate
5. Extract `resolveResumeID` helper in `root.go` to clean up `runRoot`

We are **not** implementing:

- Decomposing `setupAgentAndSession` further (it reads well as-is)
- Splitting `buildAgentTypes` built-in vs user-defined (tightly coupled)
- New tests (pure file moves; existing build+test coverage is sufficient)

## Deliverables

1. **`internal/cmd/setup.go`** (new file)
   - `setupResult` struct
   - `toolBuilder` type with `add` method (new helper)
   - `buildBaseTools` — refactored to use `toolBuilder`
   - `buildAgentTypes`
   - `setupAgentAndSession`

2. **`internal/cmd/prompt.go`** (new file)
   - `runPromptMode` function (moved from `root.go`)

3. **`internal/cmd/tui.go`** (new file)
   - `runTUI` function (moved from `root.go`)

4. **`internal/cmd/root.go`** (modified — shrinks to ~60 lines)
   - `Version` variable
   - `rootLong` constant
   - `NewRootCommand`
   - `resolveResumeID` (new helper extracted from `runRoot`)
   - `runRoot` (simplified to: resolve flags → dispatch)

5. **Build and test pass** — `go build ./cmd/buildmax` and `go test ./...` succeed.

## Out of scope (for later)

- Further decomposition of `setupAgentAndSession`
- Tests for individual setup functions
- Splitting `buildAgentTypes` into built-in + user-defined

## Acceptance

- [ ] `root.go` contains only command definition, flag routing, and `Version` (~60 lines)
- [ ] `setup.go` contains `setupResult`, `toolBuilder`, `buildBaseTools`, `buildAgentTypes`, `setupAgentAndSession`
- [ ] `prompt.go` contains `runPromptMode`
- [ ] `tui.go` contains `runTUI`
- [ ] `buildBaseTools` uses a `toolBuilder` helper — one `add` call per tool, single error check
- [ ] `runRoot` uses a `resolveResumeID` helper
- [ ] `go build ./cmd/buildmax` succeeds
- [ ] `go test ./...` succeeds
- [ ] No exported API changes (all moved symbols remain unexported)
