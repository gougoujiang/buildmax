# Task 070: Add agent concept

## Goal

Introduce a first-class **Agent** entity as a reusable persona/task template in the system, and add an **Agents** area in the Portal (sidebar + pages) so users can view executed tasks with pagination and manage agents (list, create).

## Context

- **Existing “agent” in codebase**: `internal/agent` is the runtime agent loop (LLM + tools); `internal/tools/agentdef.go` provides file-based agent definitions. Neither is a persisted workspace entity.
- **Existing entities**: Workspace → Project → Task (and TaskRun, Artifact). All use `internal/model`, GORM, and `internal/storage/entity` with interfaces in `interfaces.go`. API uses workspace-scoped routes (e.g. `GET/POST /api/workspaces/{id}/projects`).
- **Portal**: Sidebar in `LeftSidebar.tsx` (Projects, Explore, Activity); routes in `router.ts`; Activity page lists tasks (with project) and artifacts, no pagination. Tasks are listed via `GET /api/workspaces/{id}/tasks` (all, no limit/offset).

## Scope

### In scope

1. **Agent model and persistence**
   - New domain type `Agent` in `internal/model`: workspace-scoped; fields: `agent_id`, `workspace_id`, `name`, `description`, `instructions`, `created_at`. JSON and table names follow project conventions (snake_case, singular table name).
   - New `AgentStore` in `internal/storage/entity`: `ListAgentsByWorkspace`, `GetAgent`, `CreateAgent`. Implement in Store and wire in server startup (same pattern as Project/Task).
   - DB migration: new table `agent` with columns matching the model.

2. **Agent API**
   - Workspace-scoped: `GET /api/workspaces/{workspace_id}/agents` (list), `POST /api/workspaces/{workspace_id}/agents` (create; body: name, description, instructions), `GET /api/workspaces/{workspace_id}/agents/{agent_id}` (get one). Auth and workspace ownership same as existing workspace routes.

3. **Task list with pagination for “executed” tasks**
   - Backend: extend task listing to support optional `limit`, `offset`, and `executed_only` query params. “Executed” = task has been run (e.g. `last_run_id` not null or status not PENDING). Order: `created_at` DESC. Response can include a total count or “has more” indicator for the Portal to implement pagination.

4. **Portal – Agents area**
   - **Sidebar**: New nav item “Agents” (same style as Projects, Explore, Activity). New route names: `agents` (default Agents page), `agentList` (agent list + create).
   - **Agents page (default)**:
     - Route: `agents` (e.g. `#<workspaceId>/agents`).
     - Main content: list of **executed tasks** in this workspace (most recent first), using the new paginated task API. Support pagination (e.g. “Load more” or page controls).
     - Top-right: button “Agents” that navigates to the agent list page.
   - **Agent list page**:
     - Route: `agentList` (e.g. `#<workspaceId>/agents/list` or equivalent).
     - List all agents in the workspace (from `GET .../agents`).
     - Allow creating a new agent (form: name, description, instructions; POST to `.../agents`). No edit/delete required in this task.

### Out of scope

- **Skillset, Connectors, Triggers**: Not part of the Agent model or UI in this task; left for later.
- **Linking a task to an agent** when creating a task (e.g. “run with this agent”); future task.
- **Edit/delete Agent**: Optional for later; this task only requires list + create and get.
- **Using Agent instructions** in the executor or agent loop; only persist and expose via API/Portal.

## Deliverables

| Deliverable | Description |
|-------------|-------------|
| `model.Agent` | New type in `internal/model` with snake_case JSON and singular table name. |
| `AgentStore` + impl | Interface in `entity/interfaces.go`; implementation in `entity/agent.go`; migration for `agent` table. |
| Agent HTTP handlers | List, create, get under `/api/workspaces/{workspace_id}/agents`. |
| Task list pagination | Extended `GET .../tasks` with `limit`, `offset`, `executed_only`; order created_at DESC; response supports pagination (e.g. total or has_more). |
| Portal routes & sidebar | New routes `agents`, `agentList`; sidebar item “Agents”; hash/routing and types updated. |
| Agents page | Default view: executed tasks (paginated); top-right “Agents” button → agent list. |
| Agent list page | List agents; form to create agent (name, description, instructions). |

## Acceptance criteria

- [ ] `Agent` exists in `internal/model` with `agent_id`, `workspace_id`, `name`, `description`, `instructions`, `created_at`; table name `agent`; JSON snake_case.
- [ ] `AgentStore` is implemented and wired; `GET/POST /api/workspaces/{id}/agents` and `GET /api/workspaces/{id}/agents/{agent_id}` work with auth and workspace checks.
- [ ] `GET /api/workspaces/{id}/tasks` accepts `limit`, `offset`, `executed_only` and returns executed tasks (when filtered) ordered by `created_at` DESC; response allows the Portal to paginate.
- [ ] Portal sidebar has “Agents”; navigating to Agents shows the executed-tasks list (paginated) and a top-right “Agents” button that goes to the agent list page.
- [ ] Agent list page shows workspace agents and a create form (name, description, instructions); creating an agent succeeds and appears in the list.
