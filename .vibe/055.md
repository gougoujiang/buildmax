# Task 055: Alternative workspace persist: MinIO

## Goal

Add an alternative **object-storage (MinIO / S3-compatible)** backend for **persistent workspace files** and **artifact files**, selectable via environment variables, while keeping **task runtime workspace** on the local filesystem.

## Context

- **Current storage paths (filesystem-only)** (see `internal/config/config.go`):
  - **Persist**: `WorkspacesDir()/<workspace_id>/persist/` (user uploads; “Explore” reads this)
  - **Task runtime**: `WorkspacesDir()/<workspace_id>/tasks/<task_id>/` (executor runs `buildmax` here)
  - **Artifacts**: `WorkspacesDir()/<workspace_id>/artifacts/<task_id>/<artifact_id>/result.md`
- **Current executor behavior** (`internal/executor/executor.go`):
  - Prepares runtime dir by copying **persist → runtime** via `copyWorkspaceContents(persistDir, runtimeDir)` (filesystem walk/copy).
  - Creates an artifact by copying `result-<task_id>.md` to `.../artifacts/.../result.md` (filesystem copy) and inserting DB rows via `ArtifactStore`.
- **Current server behavior** (filesystem-only):
  - Upload writes into persist dir (`internal/server/upload.go`).
  - Explore file tree + content read from persist dir (`internal/server/files.go`).
  - Artifact content reads from artifact dir (`internal/server/artifacts.go`).
- **Local MinIO dev setup**: `setup/setup.sh` creates/ensures bucket `bmstore` and port-forwards MinIO:
  - API: `http://localhost:9000`, Console: `http://localhost:9001`
  - creds in script: access key `minio`, secret `minio123`, region `us-east-1`

## Workspace persistence providers (this task)

For this task, “alternative workspace persistence using MinIO” means:

1. **Persist provider** (workspace user files)
   - Upload/write files into the persistent workspace (used by Explore).
   - List files (tree) and read file content for Explore.
   - Provide a “download persist workspace into runtime dir” operation for the executor’s pre-run step.
2. **Artifact provider** (task run snapshots)
   - Write artifact file(s) for a task run (initially: only `result.md`).
   - Read artifact content for API response (same endpoints; storage backend changes only).
3. **Task runtime workspace stays local filesystem**
   - The executor still runs `buildmax` in a local `runtimeDir` and writes the raw `result-<task_id>.md` there.

### Provider types and configuration

Support two provider implementations for **persist** and **artifact**:

- **`local_fs`**: current behavior (filesystem under `WorkspacesDir()`).
- **`minio`**: S3-compatible object storage, using the local MinIO from `setup/setup.sh` by default.

Config via env vars (names are part of this task’s contract):

- **Provider selection**
  - `BUILDMAX_PERSIST_STORAGE=local_fs|minio` (default `local_fs`)
  - `BUILDMAX_ARTIFACT_STORAGE=local_fs|minio` (default `local_fs`)
- **MinIO connection**
  - `BUILDMAX_MINIO_ENDPOINT` (default `http://localhost:9000`)
  - `BUILDMAX_MINIO_ACCESS_KEY` (default `minio`)
  - `BUILDMAX_MINIO_SECRET_KEY` (default `minio123`)
  - `BUILDMAX_MINIO_REGION` (default `us-east-1`)
  - `BUILDMAX_MINIO_BUCKET` (default `bmstore`)
  - `BUILDMAX_MINIO_PREFIX` (default `workspaces`)

### Bucket layout

When using `minio`, object keys mirror the filesystem layout under `WorkspacesDir()` by using a prefix:

- **Prefix root**: `s3://<bucket>/<prefix>/`
- **Persist files**: `s3://<bucket>/<prefix>/<workspace_id>/persist/<relative_path>`
- **Artifact files**: `s3://<bucket>/<prefix>/<workspace_id>/artifacts/<task_id>/<artifact_id>/result.md`

We are **not** storing `tasks/<task_id>/` runtime state in object storage in this task.

## Deliverables

1. **Storage abstraction (new package)**
   - **New interfaces** for:
     - **Persist workspace storage**: write/upload, list, read, and “download workspace persist to a local directory”.
     - **Artifact file storage**: write `result.md` (and later multiple items), read `result.md`.
   - **Implementations**:
     - **Filesystem** implementation backed by the existing layout under `WorkspacesDir()`.
     - **MinIO** implementation using S3-compatible APIs.
   - **Design constraint**: keep these packages Go-only; no portal/React coupling.

2. **Config**
   - Parse the env vars above and construct the selected persist/artifact storage providers.
   - Bucket name configurable (default `bmstore`) and prefix configurable (default `workspaces`).

3. **Executor updates**
   - Persist pre-run: instead of filesystem copy-from-persist-dir only, use the configured **persist provider** to materialize the persist workspace into the local runtime directory.
   - Artifact creation: instead of copying to local artifact dir only, write `result.md` using the configured **artifact provider** (filesystem or MinIO), while keeping the DB artifact rows unchanged.

4. **Server updates (Explore + artifacts)**
   - Upload should write to the configured **persist provider**.
   - Explore tree/content should read from the configured **persist provider** (UI/endpoint behavior unchanged).
   - Artifact content should read from the configured **artifact provider** (endpoint behavior unchanged).

5. **Tests**
   - Unit tests for provider selection and key layout mapping.
   - Executor/server tests should use a fake/in-memory provider implementation (no real MinIO dependency in unit tests).

## Out of scope (for later)

- Migrating existing filesystem workspace data into MinIO (one-time import/export).
- Syncing **all** runtime changes back to persist (this task only requires persist → runtime before run; runtime → persist sync is not included unless explicitly needed by existing behavior).
- Storing task runtime directories in object storage.
- Multi-file artifact items (beyond the current `result.md`) and large streaming uploads/downloads optimization.
- Portal UI changes (Explore page stays the same).

## Acceptance

- [ ] When `BUILDMAX_PERSIST_STORAGE=minio`, uploads go to MinIO and Explore (tree + file content) reads from MinIO without API/UI changes.
- [ ] When `BUILDMAX_PERSIST_STORAGE=minio`, executor pre-run workspace preparation downloads from `s3://<bucket>/<prefix>/<workspace_id>/persist/` into the local runtime dir.
- [ ] When `BUILDMAX_ARTIFACT_STORAGE=minio`, executor artifact creation writes `result.md` to `s3://<bucket>/<prefix>/<workspace_id>/artifacts/<task_id>/<artifact_id>/result.md`.
- [ ] When providers are `local_fs`, behavior matches current filesystem implementation.
- [ ] Bucket name defaults to `bmstore`; prefix defaults to `workspaces`; both can be overridden via env vars.
- [ ] Unit tests cover provider selection + key layout mapping and validate server/executor behavior using a fake provider.
