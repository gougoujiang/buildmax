# Task 030: Add a portal

## Goal

Introduce a **portal** as a web-based entry point for BuildMax: create a `portal/` directory and a minimal React application so the project has a runnable frontend foundation. All feature work (API, chat, sessions) is left to later tasks.

## Context

- BuildMax is a Go-first AI Agent (CLI/TUI today). The portal is a separate web UI; the Go binary remains the single-binary core with no Node dependency for normal CLI use.
- User chose **React** as the portal tech stack and requested only the **basics** in this task.

## In scope

- **Directory**: Create `portal/` at the repository root for all portal (frontend) code.
- **Stack**: React, with a modern build tool (Vite), and TypeScript.
- **Deliverables**:
  - Scaffolded React app under `portal/` that builds and runs.
  - Single landing view (e.g. "BuildMax Portal" or equivalent) to confirm the app loads.
  - README in `portal/` describing how to install dependencies, build, and run the dev server.
- **Repositories**: No change to `go.mod` or Go build/test; portal is independent (its own `package.json` and tooling).

## Out of scope

- Backend or API (Go HTTP server, agent API, etc.).
- Chat UI, session list, or any agent features in the portal.
- Integration with the existing BuildMax CLI or TUI.
- Production build wiring (e.g. embedding static assets in the Go binary).
- Deployment or Docker.

## Acceptance criteria

- [ ] `portal/` exists at repo root and contains a React + Vite + TypeScript app.
- [ ] `npm install` and `npm run build` succeed in `portal/`.
- [ ] `npm run dev` starts a dev server and the app shows a clear "BuildMax Portal" (or equivalent) landing.
- [ ] `portal/README.md` documents install, build, and dev commands.
- [ ] Go build and tests unchanged: `go build ./...` and `go test ./...` still pass.
