# Task 041: Add --session-id flag for conversation

## Goal

Add a CLI flag `--session-id <uuid>` so the user can specify which session ID to use for the conversation. The value must be a valid UUID; invalid values produce a clear error. When set, that ID is used for the run: load the session if it exists on disk, otherwise create a new session with that ID.

## Context

- **Current behavior**: `-r/--resume <id>` resumes an existing session by ID (load from disk; fails if not found). With no `-r`, a new session is created with a random UUID via `session.NewSession("")`. Session IDs are UUIDs; persistence is under `DataDir()/sessions/<id>.json`.
- **Relevant code**: `internal/cmd/root.go` (flags, `resolveResumeID`, `runPrintMode`/`runTUI`); `internal/cmd/setup.go` (`setupAgentAndSession`: when `resumeID != ""` loads via `session.LoadFromDir`, else `session.NewSession("")`); `internal/session` uses `github.com/google/uuid` and has `NewSessionFromData(id, title, createdAt, messages)` to construct a session with a given ID.
- **Use case**: Scripting or reproducible runs where the user wants a fixed session ID; or “use this session” semantics (load if exists, else create) without separate “resume” vs “create” flows.

## In scope

1. **New flag**
   - Add `--session-id <uuid>` to the root command (long form only is fine; no short flag required).
   - Value must be a valid UUID (e.g. parse with `github.com/google/uuid`). If invalid, exit with a clear error message to stderr (e.g. "invalid session-id: not a valid UUID").

2. **Semantics**
   - When `--session-id` is set: use this ID for the conversation. In `setupAgentAndSession` (or equivalent flow): try to load the session from the sessions directory; if the file exists and is valid, use that session; if the file does not exist (or load fails for other reasons that imply “no such session”), create a new session with this ID (e.g. via `session.NewSessionFromData(id, "", time.Now(), nil)`).
   - When `--session-id` is not set: behavior unchanged — resolve session via `-r/--resume` and `-c/--continue` as today; empty means new session with random UUID.

3. **Precedence**
   - If both `--session-id` and `-r/--resume` are provided: `--session-id` wins (use that UUID; load or create as above). `-r` is ignored for that run. No need to error or require them to match.

4. **Help and docs**
   - Document the flag in the root command long description (e.g. under Sessions or a new line): "Use --session-id <uuid> to use a specific session ID (load if exists, else create); value must be a valid UUID."

5. **TUI and print mode**
   - Both code paths (TUI and `-p` print mode) already go through `setupAgentAndSession(resumeID, ...)`. The “effective session ID” (from `--session-id` when set, else from current resume resolution) is passed into that flow; no separate logic per mode.

## Out of scope

- Changing `-r/--resume` or `-c/--continue` behavior when `--session-id` is not set.
- Adding a short flag for `--session-id` (e.g. `-s`).
- Session list or TUI UX changes.
- Server/portal or other entry points (CLI only).

## Deliverables

- Root command: new `--session-id` flag; UUID validation before calling `runPrintMode`/`runTUI`; when set, pass this ID as the “session to use” and do not use `-r`/`-c` for session resolution.
- `setupAgentAndSession` (or the single place that loads/creates the session): when given a non-empty session ID, try load first; on “not found” (or equivalent), create a new session with that ID via existing session API (e.g. `NewSessionFromData`). Other load errors (e.g. corrupt file) can still surface as errors.
- Help text updated to describe `--session-id`.
- Tests: at least one test that invalid UUID for `--session-id` returns an error; optionally a test that a valid UUID creates or loads the session as specified.

## Acceptance

- [ ] `buildmax --session-id <valid-uuid>` uses that session (loads if `sessions/<uuid>.json` exists, otherwise creates a new session with that ID); works in both TUI and `-p` mode.
- [ ] `buildmax --session-id not-a-uuid` exits with a clear error (e.g. "invalid session-id: not a valid UUID") and non-zero exit code.
- [ ] When `--session-id` is set, `-r` and `-c` are ignored for session resolution (session ID comes from `--session-id`).
- [ ] When `--session-id` is not set, behavior is unchanged (resume via `-r`/`-c`, new session with random ID otherwise).
- [ ] Root command help documents `--session-id`.
- [ ] `go build ./...` and `go test ./...` pass.
