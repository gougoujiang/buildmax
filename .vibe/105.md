# Task 105: Desktop mandatory login check

## Goal

Enforce authentication at the Go binding level in the desktop app so that agent operations (`SendMessage`, `SendMessageStream`) cannot run without valid credentials, regardless of the frontend UI gate.

## Context

- **Frontend gate already exists**: `App.jsx` checks `GetAuthStatus()` on startup and shows `LoginPage` if `!authStatus.logged_in`. This is a UI-only gate — the Go bindings are still callable without auth (e.g. via devtools or if the frontend gate has a timing issue).
- **TUI/CLI gate added in task 104**: `requireLogin` in `internal/interface/cli/root.go` checks `auth.Load` + `IsValid()` before dispatching to TUI or print mode. The desktop app needs the same pattern at the Go binding layer.
- **Go bindings that need protection**: `SendMessage` and `SendMessageStream` in `internal/interface/desktop/app.go` go directly to `agentrun.Open` without checking credentials. These are the agent-running paths.
- **Go bindings that do NOT need protection**: `ListSessions`, `GetSession` are local disk reads (no server, no LLM). `GetAuthStatus`, `RequestOTP`, `DoLogin`, `Logout` are auth operations themselves. These should remain callable without auth.
- **Auth check is lightweight**: `auth.Load(config.AuthPath())` + `creds.IsValid()` — same as TUI. No network call.

## In scope

1. **Auth check in `SendMessage`** — Before calling `agentrun.Open`, load credentials and verify `IsValid()`. If not valid, return a clear error (e.g. `"not logged in"`).
2. **Auth check in `SendMessageStream`** — Same check before starting the agent runtime. If not valid, return an error (the frontend will receive it and can act on it).
3. **Helper method on App** — Extract a private `requireLogin() error` method on `App` that both `SendMessage` and `SendMessageStream` call. Keeps the check in one place.

## Out of scope

- Token validation against the server (checking expiry or calling a /me endpoint). Current contract is `IsValid()` = non-empty token.
- Changes to the frontend auth gate (it already works; this task hardens the backend).
- Auth checks on `ListSessions`, `GetSession` (local-only, no LLM calls).
- Changes to `internal/auth` package.
- Refresh tokens or re-auth prompts.

## Deliverables

1. **`internal/interface/desktop/app.go`** — Add a private `requireLogin() error` method on `App`. Call it at the top of `SendMessage` and `SendMessageStream`. Return `fmt.Errorf("not logged in")` if credentials are missing or invalid.

- [ ] `SendMessageStream` succeeds normally when valid credentials exist
