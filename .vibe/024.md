# Task 024 - Consolidate Agent Used Dirs

## Goal

Centralize the path resolution for skills and agent definitions into a single `internal/config` utility, so both tools load from a consistent two-level directory scheme (project → global) with project-level precedence, and remove ad-hoc path construction from `root.go`.

## Context

- **Skill tool** (`internal/tools/skill.go`): Already accepts `searchPaths []string` and scans each for subdirectories containing `SKILL.md`. Currently wired in `root.go` with three hard-coded paths: `<cwd>/.buildmax/skills`, `<cwd>/.cursor/skills`, `~/.buildmax/skills`.
- **Agent defs** (`internal/tools/agentdef.go`): `LoadAgentDefs(dir string)` takes a single directory. Currently wired in `root.go` as `<cwd>/.agents/agents/` — does **not** follow the `.buildmax/` convention and only supports one location (no global fallback).
- **Config** (`internal/config/config.go`): `DataDir()` returns the global data directory (`~/.buildmax` or `HOME_DIR` override). No workspace-level path helpers exist.
- **Existing convention**: Project-specific config lives under `<workspace>/.buildmax/`. Global config lives under `~/.buildmax/` (the `DataDir()`).

### Current wiring in `root.go`

```go
// Skills — 3 paths, mixed conventions
skillSearchPaths := []string{
    filepath.Join(cwd, ".buildmax", "skills"),
    filepath.Join(cwd, ".cursor", "skills"),
    filepath.Join(config.DataDir(), "skills"),
}

// Agent defs — 1 path, wrong convention (.agents instead of .buildmax)
agentDefsDir := filepath.Join(cwd, ".agents", "agents")
```

## Consolidated directory scheme (this task)

For this task, the **standard directory layout** is:

```
<workspace>/.buildmax/skills/    # project-level skills
<workspace>/.buildmax/agents/    # project-level agent definitions
~/.buildmax/skills/              # global-level skills
~/.buildmax/agents/              # global-level agent definitions
```

**Precedence rules:**
1. Project-level paths come first (higher priority).
2. Global-level paths come second (lower priority).
3. For skills: "first path wins" on name conflict (already implemented in `discoverSkills`).
4. For agent defs: project-level definitions override global-level definitions with the same name.

**Compatibility**: The `<workspace>/.cursor/skills` path is kept as an additional search path for skills (inserted between project-level and global-level) to maintain backward compatibility with existing Cursor skill layouts.

We are **not** yet implementing:

- Additional env var overrides for search paths (e.g. `BUILDMAX_SKILLS_PATH`)
- CLI subcommands to manage skills or agents directories
- Any changes to how `SkillTool` or `LoadAgentDefs` internally work (only changing what paths are passed in)
- Hot-reload or watch on these directories

## Deliverables

1. **`internal/config/config.go`** — New path helper functions
   - **`SkillSearchPaths(workspace string) []string`**: Returns the ordered list of skill search directories: `[<workspace>/.buildmax/skills, <workspace>/.cursor/skills, <global>/.buildmax/skills]`. The `<global>` portion uses the existing `DataDir()` logic. The `.cursor/skills` entry is for backward compatibility.
   - **`AgentDefsSearchPaths(workspace string) []string`**: Returns the ordered list of agent definition directories: `[<workspace>/.buildmax/agents, <global>/.buildmax/agents]`.
   - Both functions return absolute paths. Missing directories are **not** created — callers (the tools) already handle missing dirs gracefully.

2. **`internal/config/config_test.go`** — Unit tests for new helpers
   - Test `SkillSearchPaths` returns 3 paths in the correct order.
   - Test `AgentDefsSearchPaths` returns 2 paths in the correct order.
   - Test that paths use the workspace argument for project-level and `DataDir()` for global-level.
   - Test with `HOME_DIR` override to verify global path changes accordingly.

3. **`internal/tools/agentdef.go`** — Support multiple search directories
   - **Add `LoadAgentDefsFromPaths(dirs []string) ([]AgentDef, error)`**: Iterates over dirs in order, calls `LoadAgentDefs` for each, and merges results. First-dir-wins on name conflict (same precedence logic as skills). Returns the merged list sorted alphabetically by Name.
   - **Keep `LoadAgentDefs(dir string)`** unchanged — it remains the single-dir loader.

4. **`internal/tools/agentdef_test.go`** — Tests for the new multi-path loader
   - Test `LoadAgentDefsFromPaths` with project and global dirs where project overrides global on name conflict.
   - Test with missing directories (gracefully skipped).
   - Test with no valid dirs returns empty.

5. **`cmd/buildmax/root.go`** — Replace ad-hoc path construction
   - Replace the inline `skillSearchPaths` slice with a call to `config.SkillSearchPaths(cwd)`.
   - Replace the inline `agentDefsDir` with a call to `config.AgentDefsSearchPaths(cwd)` and use `LoadAgentDefsFromPaths` instead of `LoadAgentDefs`.
   - Remove the old `.agents/agents` path reference.

## Out of scope (for later)

- Env var overrides for custom search paths (e.g. `BUILDMAX_SKILLS_PATH`)
- CLI commands to list, create, or manage skills/agents directories
- Scaffold/init command that creates `.buildmax/skills/` and `.buildmax/agents/` directories
- Changes to the internal discovery logic of `SkillTool` or `AgentDef` parsing
- Config file (YAML/TOML) for path customization
