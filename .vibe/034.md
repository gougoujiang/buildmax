# Task 034: Portal layout details

Add the **primary left sidebar** menus (Home / Projects / Activity / Explore) and their routes/pages as discussed. Top Bar stays unchanged; Assistants are not handled in this task.

---

## Context: Product design discussion (summary)

Product direction from discussion:

- **Top Bar**: Left unchanged in this task (no Search/Settings/Assistants added here).
- **Left nav (primary)**: Home, Projects, Activity, Explore — core daily navigation; this task adds these sidebar menus only.
- **Assistants**: Not in scope for this task.

Three questions were raised and are resolved in this spec:

1. **What does Home show?** — User is already in a workspace; Home = workspace home (see § In scope).
2. **Activity in left nav vs in Project?** — Left nav "Activity" = workspace-level activity (all tasks/events across projects); Project page keeps project-level activity only.
3. **Is Explore “browse workspace content”?** — Yes; Explore = view to browse workspace content (artifacts, projects, etc.) — see § In scope.

---

## Goal

One sentence: **Add the primary left sidebar with Home / Projects / Activity / Explore and the new routes/views for Activity and Explore; leave Top Bar unchanged and do not handle Assistants.**

---

## In scope

- **Primary left sidebar (replacing or wrapping current projects-only sidebar)**
  - **Home** — navigates to workspace home (`#<workspaceId>`). Active when route is `workspace`.
  - **Projects** — current project list (existing list); active when route is `project`/`task`/`artifact`. No change to project list behavior.
  - **Activity** — navigates to workspace-level activity route (new). Active when route is `activity`.
  - **Explore** — navigates to workspace-level explore route (new). Active when route is `explore`.

- **Routes and pages**
  - **Workspace home** (existing): Keep current WorkspaceHome content: prompt area, project list, quick actions. Optionally add a “Recent activity” section for this workspace (mock data) so Home clearly represents “workspace landing.”
  - **Activity (workspace-level)** (new): New route `#<workspaceId>/activity`. Page shows a single feed of recent tasks/events across all projects in the workspace (mock list: task title, project name, time, status). Distinct from project-level activity on ProjectDashboard.
  - **Explore (workspace-level)** (new): New route `#<workspaceId>/explore`. Page lets users “browse workspace content”: e.g. list of all artifacts (or projects) in the workspace with links to open artifact/project (mock data). Purpose: browse workspace content without going project-by-project.

- **Routing**
  - Extend `Route` and hash router: add `{ name: "activity"; workspaceId: string }` and `{ name: "explore"; workspaceId: string }`.
  - Breadcrumbs: include Activity and Explore where applicable; “Home” crumb continues to point to workspace home.

---

## Out of scope

- **Top Bar**: Leave style and content unchanged (no Search, Settings, or other new controls).
- **Assistants**: Not handled in this task (no Assistants menu, page, or placeholder).
- Real search, real settings page, or user preferences.
- Backend or API; all data remains mock.
- Changes to project-level Activity on ProjectDashboard (only ensure naming/placement is consistent with “workspace Activity” in left nav).

---

## Deliverables

1. **Left sidebar**
   - Primary nav: Home, Projects, Activity, Explore.
   - “Projects” is the existing project list (possibly under a “Projects” heading).
   - Each nav item highlights when its route is active; clicking navigates to the correct hash.

2. **Router and types**
   - `Route`: add `activity` and `explore` variants with `workspaceId`.
   - `parseHash` / `buildHash` / `navigate`: support `#<workspaceId>/activity` and `#<workspaceId>/explore`.

3. **Pages**
   - **WorkspaceHome**: Unchanged or lightly refined; optional “Recent activity” block for workspace (mock).
   - **ActivityPage** (new): Workspace-level activity feed (mock tasks across projects).
   - **ExplorePage** (new): Workspace content browse (mock artifacts and/or projects with links).

4. **App and shell**
   - App resolves new routes and renders ActivityPage / ExplorePage.
   - AppShell passes route (and any needed callbacks) so the left nav can highlight and navigate to activity/explore.
   - Breadcrumbs: support activity and explore (e.g. Home > Activity, Home > Explore).

5. **Mock data**
   - Enough mock data to drive workspace-level activity (e.g. tasks with projectId) and explore (e.g. artifacts list by workspace) without new entity types if possible; reuse Task/Artifact and filter by workspace/projects.

---

## Acceptance criteria

- [ ] Top Bar is unchanged (no new controls or style changes).
- [ ] Left sidebar shows primary nav: Home, Projects, Activity, Explore; Projects list appears (current behavior); active item reflects current route.
- [ ] Clicking Home navigates to `#<workspaceId>`; WorkspaceHome (prompt + projects + quick actions, optionally recent activity) is shown.
- [ ] Clicking Activity navigates to `#<workspaceId>/activity`; ActivityPage shows workspace-level activity feed (mock).
- [ ] Clicking Explore navigates to `#<workspaceId>/explore`; ExplorePage shows workspace content browse (mock).
- [ ] Breadcrumbs work for workspace, project, task, artifact, activity, and explore; “Home” links to workspace home.
- [ ] After switching workspace, activity and explore routes use the new workspaceId (hash format and redirect behavior consistent with existing workspace handling).
- [ ] No new dependencies; build and existing behavior (workspace switch, project/task/artifact navigation) still work.
