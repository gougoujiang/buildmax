# Task 013 - Persist session list file for easy lookup

## Goal

Persist a session index file (`sessions.json`) under the sessions directory so sessions can be listed and the "last" session resolved without scanning the filesystem, and add a `--continue` flag to resume the most recent session by created_at.

## Context

- **`internal/session`**: `Session` has id, title, created_at, messages; `SaveToDir(s, dir)` writes `dir/<id>.json`; `LoadFromDir(dir, id)` loads one session. No session list today (task 008).
- **`cmd/buildmax`**: Prompt mode and TUI use `filepath.Join(config.DataDir(), "sessions")` as sessions dir. `--resume` / `-r` takes a session id; no `--continue` yet. Workspace is current working directory (cwd) at run time.
- **AGENTS.md**: Persisted data uses snake_case for JSON keys (e.g. `created_at`). Session package must not depend on `internal/agent` or `cmd/buildmax`.
- Sessions are saved after each run (prompt mode) and after each assistant reply (TUI). Title is often empty; first user message is a good default title when saving.

## Session list (this task)

For this task:

1. **List file** = `sessions/sessions.json` (same directory as `sessions/<id>.json`). One JSON array of list entries.
2. **List entry** = one object per session: `id`, `title`, `workspace`, `created_at`. All keys snake_case. Workspace is the absolute path of the working directory when the session is saved (e.g. `C:\my\ws` or `/home/user/ws`). Use **RFC3339** for `created_at` so the list format matches the per-session JSON and stays human-readable; Unix timestamp would be valid too but is out of scope for this task.
3. **One entry per session id**: When saving a **new** session, append its entry to the list. When saving a **resumed** session, update the existing entry for that id (title, workspace) so the list stays in sync; created_at is unchanged.
4. **"Last" session** = the list entry with the latest `created_at`. Used by `--continue` to choose which session to resume.
5. **Title from first user message**: When saving, if the session title is empty and the session has at least one user message, set the title to the content of the first user message, truncated to 100 characters (runes or bytes as appropriate). Apply before writing the session file and before upserting the list entry.

We are **not** yet implementing:

- A `list-sessions` CLI subcommand or TUI session picker.
- Deleting or pruning sessions from the list when a session file is removed.
- Storing workspace as a `file://` URL; plain path is enough for this task.

## Deliverables

1. **`internal/session`**
   - **List entry type**: Define a struct used only for the session list JSON (e.g. `ListEntry` or package-internal type) with fields: `ID`, `Title`, `Workspace`, `CreatedAt` and `json:"id"`, `json:"title"`, `json:"workspace"`, `json:"created_at"`.
   - **List file path**: List file lives at `dir/sessions.json` where `dir` is the same sessions directory used for `SaveToDir` (caller passes it).
   - **LoadList**: `LoadList(dir string) ([]ListEntry, error)`. Read `dir/sessions.json`; if missing, return empty slice and nil error (no file yet). If present but invalid JSON, return non-nil error.
   - **UpsertListEntry**: `UpsertListEntry(dir string, entry ListEntry) error`. Load list from `dir/sessions.json`, upsert by `id` (update title and workspace if exists, else append), write back. Create `dir` if needed. Caller is responsible for setting title (e.g. from first user message) and workspace before building the entry.
   - **LastByCreatedAt**: `LastByCreatedAt(entries []ListEntry) *ListEntry`. Return the entry with latest `created_at`; return nil if slice is empty. Used by CLI to resolve `--continue`.
   - **Title from first user message**: `EnsureTitleFromFirstUserMessage(s *Session, maxLen int)`. If `s.Title() == ""` and the session has at least one user message, set the session title to the content of the first user message, truncated to `maxLen` characters (use runes for safe truncation). No-op otherwise. Callers use `maxLen == 100`.
   - **Save flow**: Callers (cmd and TUI) must, before each save: call `EnsureTitleFromFirstUserMessage(s, 100)`; then `SaveToDir(s, sessionsDir)`; then build a list entry from `s.ID()`, `s.Title()`, `s.CreatedAt()` and the current workspace, and call `UpsertListEntry(sessionsDir, entry)`. Session package does not call SaveToDir from within list logic; callers orchestrate.

2. **`cmd/buildmax`**
   - **Flag `--continue`**: Add `--continue` (and short `-c` if desired) meaning "resume the last session (by created_at)". When `--continue` is set, resolve session id by loading the session list from `sessions/sessions.json`, then `LastByCreatedAt(list)`; if no entries or nil, print a clear message to stderr (e.g. "no sessions found; create one with -p PROMPT or start the TUI") and exit non-zero. Then behave as `--resume <that-id>` (prompt mode or TUI as today). Mutually exclusive with explicit `--resume <id>`: if both are given, prefer `--resume` and ignore `--continue`, or document that `--resume` takes precedence.
   - **Prompt mode**: Before `SaveToDir`, call `session.EnsureTitleFromFirstUserMessage(sess, 100)`. After `SaveToDir`, call `session.UpsertListEntry(sessionsDir, session.ListEntry{...})` with id, title, created_at, and workspace (cwd).
   - **TUI**: Same: before saving (wherever `SaveToDir` is called), ensure title from first user message; after save, upsert list entry with TUI workspace (already available in opts).
   - **Help**: Document `--continue` in the long description (resume most recent session).

3. **Tests**
   - **`internal/session`**: (1) `LoadList` with missing file returns empty slice and nil error; (2) `LoadList` with invalid JSON returns error; (3) `LoadList` after writing valid list returns same entries; (4) `UpsertListEntry` on empty dir creates `sessions.json` with one entry; (5) `UpsertListEntry` with existing id updates that entry's title and workspace, leaves created_at and order stable; (6) `LastByCreatedAt` returns nil for empty slice, and returns the entry with latest created_at for non-empty slice; (7) `EnsureTitleFromFirstUserMessage` sets title from first user message when title is empty and truncates to maxLen; (8) no-op when title already set or no user messages.

4. **Dependencies**
   - No new external Go modules. Use `encoding/json`, `os`, `path/filepath`, and existing session/time types.

## Out of scope (for later)

- CLI subcommand to list or delete sessions; TUI session picker.
- Pruning or repairing the list when session files are removed by hand.
- Storing workspace as `file://` URL; display or normalization can be a follow-up.

## Acceptance

- [ ] **LoadList**: Missing `sessions.json` returns `([]ListEntry, nil)`; invalid JSON returns non-nil error; valid file round-trips. Unit tests cover all three.
- [ ] **UpsertListEntry**: Creates `sessions.json` with one entry when list is empty; updates existing entry by id (title, workspace); creates dir if needed. Unit tests cover append and update.
- [ ] **LastByCreatedAt**: Returns nil for empty slice; returns entry with latest `created_at` for non-empty slice. Unit test with two entries.
- [ ] **EnsureTitleFromFirstUserMessage**: Sets title from first user message when empty, truncated to maxLen; no-op when title set or no user messages. Unit test.
- [ ] **Prompt mode**: Saving (new or resumed) updates session list and uses first user message as title when title was empty; `buildmax --continue -p PROMPT` resumes the session with latest created_at and runs one turn, then saves; when no sessions exist, `--continue` prints clear message and exits non-zero.
- [ ] **TUI**: Saving after assistant reply updates session list and title from first user message when applicable.
- [ ] **Help**: Long description documents `--continue` (resume most recent session).
- [ ] **Build and test**: `make build` and `make test` pass.
