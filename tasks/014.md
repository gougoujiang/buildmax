# Task 014: Large TUI refactor

## Goal

Refactor the TUI so the root Bubble Tea model uses a pointer receiver everywhere and the viewport vs input areas have a clearer structural separation, improving maintainability without changing behavior or layout.

## Context

- **Existing code**: `internal/tui/model.go` defines a single `Model` struct (viewport.Model, textarea.Model, opts, dimensions, focus state). `NewModel(opts TUIOpts) Model` returns a value. Methods are mixed: `Init`, `Update`, `View`, `FocusInput` use value receiver `(m Model)`; `syncInputHeight`, `scheduleScrollIdleReturn` use pointer receiver `(m *Model)`. Helpers like `handleKeyMsg`, `refreshViewportAndGotoBottom` take `Model` or `*Model`. `internal/app/app.go` returns `tui.NewModel(opts)` as `tea.Model`. Tests in `internal/tui/model_test.go` use `NewModel(opts)` and type-assert `Update` results to `Model`.
- **Where it fits**: TUI layer only (`internal/tui`, `internal/app`). Bubble Tea’s `tea.Model` interface is satisfied by either value or pointer; switching to pointer is an API convention change for this package and its callers.
- **Conventions**: AGENTS.md specifies Bubble Tea for TUI, Go-only implementation; `make.bat test` must pass. Persisted and JSON keys use snake_case (not needed for in-memory TUI model).

## “Sub-model” (this task)

For this task, **sub-model** means **Option A — grouped state structs**:

- Introduce types that group viewport-related state and input-related state (e.g. `ViewportBlock`, `InputBlock` or similar), with the root `Model` holding or embedding them.
- Viewport content building and input rendering stay in dedicated functions or methods on these types.
- Still a single `tea.Model` with one `Update`/`View` that delegate to these blocks where it helps readability.

We are **not** in this task:

- Adding new TUI features or changing layout/behavior.
- Refactoring session persist, agent, or `cmd/buildmax` beyond what is needed for the pointer receiver (app still returns `tea.Model`).
- Option B (nested Bubble Tea models: viewport/input each implementing `tea.Model`) — out of scope.

## Deliverables

1. **Pointer receiver for root TUI model**
   - Change `NewModel(opts TUIOpts)` to return `*Model` (allocate with `&Model{...}` or local variable then return `&m`).
   - Change every method on `Model` to use pointer receiver `(m *Model)`: `Init`, `Update`, `View`, `FocusInput`, `syncInputHeight`, `scheduleScrollIdleReturn`. Update any helper that currently takes `Model` by value to take `*Model` where it needs to mutate or pass to other helpers (e.g. `handleKeyMsg`, `handleWindowSize`, `handleAgentDone`, `handleCarouselTick`, `handleMouseMsg`, `handleScrollIdle`, `refreshViewportAndGotoBottom`).
   - Ensure `*Model` still satisfies `tea.Model` (Init, Update, View). No change to the logic inside these methods beyond receiver and argument types.
   - In `internal/app/app.go`: keep `NewModel(opts tui.TUIOpts) tea.Model`; it can return `tui.NewModel(opts)` which will now be `*Model` (interface satisfied by pointer).
   - In `internal/tui/model_test.go`: update tests that use `NewModel(opts)` and type-assert `Update`’s return value to use `*Model` (e.g. `m2.(*Model)` instead of `m2.(Model)`). Fix any code that relied on copying the model (e.g. chained `mod.Update` then `mod2.Update` still works with pointers).

2. **Sub-model structure (viewport vs input) — Option A: grouped state structs**
   - Add structs (e.g. in `model.go` or in `viewport_block.go` / `input_block.go`) that hold viewport-related data and input-related data (and optionally their helpers). Refactor root `Model` to hold these structs.
   - Move or group viewport content building and input rendering so that “viewport” and “input” are identifiable units (types or functions scoped to those structs).
   - Keep existing behavior and layout: same banner, chat, input box, footer, focus and scroll behavior.

3. **Tests and build**
   - All existing tests in `internal/tui` and the rest of the repo pass. No new tests are required unless you add small unit tests for new helper types.
   - `make.bat test` passes.

## Out of scope (for later)

- New TUI features (e.g. session picker, new key bindings).
- Refactoring session persist flow, agent processLoop, or root command setup (those are in refactor-proposal-20250201.md or other tasks).
- Changing logging, config, or CLI flags.

## Acceptance

- [ ] `NewModel(opts TUIOpts) *Model`; all methods on `Model` use pointer receiver `(m *Model)`; helpers that need to mutate the model take `*Model`.
- [ ] `internal/app.NewModel` still returns `tea.Model`; running `buildmax` (and `buildmax --resume <id>`) starts the TUI and behaves as before.
- [ ] `internal/tui/model_test.go` uses `*Model` in type assertions and any other places that assumed value semantics; all TUI tests pass.
- [ ] Viewport and input are separated into distinct grouped state structs (viewport block, input block); root `Model` holds them and delegates where appropriate; layout and behavior unchanged.
- [ ] `make.bat test` passes.
