# Task 021 - Grep tool

## Goal

Add a **Grep** tool so the agent can search file contents by regex pattern under the workspace root, with filtering, context lines, and multiple output modes — implemented in pure Go (no shelling out to `rg` or `grep`).

## Context

- **`internal/agent`** defines the `Tool` interface: `Name()`, `Description()`, `Parameters() any` (JSON schema), `Execute(ctx, args) (string, error)`. `NewAgent(caller, tools)` builds `toolDefs` and `toolsByName`; the agent dispatches tool calls by name and prefixes errors with `error: `.
- **`internal/tools`** already has ReadFile, WriteFile, EditFile, Glob, Bash, WebFetch, TodoWrite. All file-based tools share a pattern: `root string`, constructor `NewX(root)`, path resolution under root, and clear success/error messages for the LLM.
- **`cmd/buildmax/root.go`** — `setupAgentAndSession` creates tools with `cwd` and passes them to `NewAgent`. Grep will receive the same workspace root.
- **Glob tool** (`glob.go`) uses `doublestar` for `**` pattern matching and `os.DirFS` + `filepath.WalkDir`. Grep can reuse the same `doublestar` dependency for its `glob` file filter.
- **AGENTS.md**: All-Go implementation; snake_case JSON keys; tool output must be meaningful on success and failure.

## Grep (this task)

For this task, **Grep** means:

1. A tool that searches **file contents** under the tool's root (or a subdirectory) for lines matching a **Go regexp** pattern.
2. **`pattern`** (required): Regular expression (Go `regexp` syntax, which is close to ripgrep/RE2). The LLM provides patterns like `log.*Error`, `function\s+\w+`, etc.
3. **`path`** (optional): File or directory to search in, relative to root. If a file, search only that file. If a directory, search recursively. Defaults to root.
4. **`glob`** (optional): Glob pattern to filter which files are searched (e.g. `*.go`, `*.{ts,tsx}`). Uses `doublestar` matching against relative paths. Applied on top of `path`.
5. **`type`** (optional): Shorthand file-type filter (e.g. `go`, `js`, `py`). Maps to a set of extensions internally. Mutually usable with `glob` (both filters apply).
6. **`output_mode`** (optional, default `"files_with_matches"`): One of `"content"` (matching lines with optional context), `"files_with_matches"` (just file paths), `"count"` (match counts per file).
7. **Context flags** (`-A`, `-B`, `-C`): Number of lines after, before, or around each match. Only effective in `"content"` mode.
8. **`-n`** (optional, default `true`): Show line numbers in `"content"` mode.
9. **`-i`** (optional, default `false`): Case-insensitive matching (prepend `(?i)` to pattern).
10. **`multiline`** (optional, default `false`): Enable multiline/dotall mode (prepend `(?ms)` to pattern) so `.` matches `\n` and `^`/`$` match line boundaries.
11. **`head_limit`** (optional, default `0` = unlimited): In `"content"` mode, limit total match entries shown. In `"files_with_matches"` and `"count"` modes, limit number of files.
12. **`offset`** (optional, default `0`): Skip the first N entries before applying `head_limit` (pagination support).
13. **Result**: A string suitable for the LLM. Content mode outputs ripgrep-style grouped output (file header, then `LINE_NUM:matched line` or `LINE_NUM-context line`). files_with_matches outputs one path per line. count outputs `filepath: N` per line. "No matches found." when nothing matches.

We are **not** yet implementing:

- Replace-in-files / sed-like functionality (use Edit tool).
- Binary file detection or skipping (treat all files as text; skip files that fail UTF-8 read).
- Respect for `.gitignore` or custom ignore rules (search all files under root).
- Streaming/incremental output.

## Deliverables

### 1. `internal/tools/grep.go`

- **`Grep` struct**: Fields `root string` (absolute path). Implements `agent.Tool`.
- **`NewGrep(root string) (*Grep, error)`**: If root is empty, use `os.Getwd()`. Normalize and absolutize root. Return error if root cannot be resolved. Same pattern as NewGlob / NewReadFile.
- **`Name() string`**: Return `"Grep"`.
- **`Description() string`**: A concise description for the LLM: searches file contents by regex pattern; supports glob/type file filters; three output modes (content, files_with_matches, count); context lines; case-insensitive and multiline flags; use for finding code by pattern.
- **`Parameters() any`**: OpenAI-style JSON schema with these properties:

  | Parameter | Type | Required | Default | Description |
  |-----------|------|----------|---------|-------------|
  | `pattern` | string | yes | — | Regex pattern to search for |
  | `path` | string | no | root | File or directory to search in |
  | `glob` | string | no | — | Glob pattern to filter files (e.g. `*.go`) |
  | `type` | string | no | — | File type shorthand (e.g. `go`, `js`, `py`) |
  | `output_mode` | string | no | `"files_with_matches"` | `"content"`, `"files_with_matches"`, or `"count"` |
  | `before_context` | number | no | 0 | Lines before each match (content mode only) |
  | `after_context` | number | no | 0 | Lines after each match (content mode only) |
  | `context` | number | no | 0 | Lines before and after (content mode only; overrides before/after if set) |
  | `line_numbers` | boolean | no | true | Show line numbers (content mode only) |
  | `case_insensitive` | boolean | no | false | Case-insensitive search |
  | `multiline` | boolean | no | false | Multiline/dotall mode |
  | `head_limit` | number | no | 0 | Limit output entries (0 = unlimited) |
  | `offset` | number | no | 0 | Skip first N entries |

  Note: use snake_case parameter names in the JSON schema (not `-A`/`-B`/`-C`/`-n`/`-i` from the reference). The LLM description for each parameter should mention the ripgrep equivalent flag for familiarity (e.g. "equivalent to rg -A").

- **`Execute(ctx context.Context, args map[string]any) (string, error)`**:
  1. **Parse and validate `pattern`** — required, non-empty string. Compile with `regexp.Compile`. If `case_insensitive`, prepend `(?i)`. If `multiline`, prepend `(?ms)`. Return clear error on invalid regex.
  2. **Resolve `path`** — if provided, resolve under root (same path safety as other tools). Stat: if file, search only that file; if directory, search recursively. If omitted, use root. Reject paths outside root.
  3. **Collect candidate files** — Walk the search directory (or use the single file). For each file:
     - Apply `glob` filter: match the file's path (relative to search dir) against the glob pattern using `doublestar.Match`.
     - Apply `type` filter: check the file extension against a built-in type→extensions map.
     - Skip directories, skip files that fail to read (log and continue).
  4. **Search each file** — Read file contents. Split into lines. Find all lines matching the compiled regex. Record matches with line numbers.
  5. **Build output** based on `output_mode`:
     - **`"files_with_matches"`**: Collect unique file paths that have at least one match. Apply `offset` and `head_limit`. Return one absolute path per line, or "No matches found."
     - **`"count"`**: For each file with matches, output `filepath: N`. Apply `offset` and `head_limit` (on file count). Return "No matches found." if none.
     - **`"content"`**: For each match, include context lines (before_context / after_context / context). Format: file path header, then `LINE_NUM:matched line` or `LINE_NUM-context line` (ripgrep style). Apply `offset` and `head_limit` (on match entries across all files). If `line_numbers` is false, omit the `LINE_NUM:` prefix. Return "No matches found." if none.
  6. **Return** the formatted string.

- **Type map** (internal constant or var): Map type shorthand to extensions. At minimum support: `go` → `.go`, `js` → `.js`, `ts` → `.ts`, `tsx` → `.tsx`, `py` → `.py`, `java` → `.java`, `rust` → `.rs`, `c` → `.c`, `cpp` → `.cpp .cc .cxx`, `h` → `.h`, `css` → `.css`, `html` → `.html .htm`, `json` → `.json`, `yaml` → `.yaml .yml`, `md` → `.md`, `sh` → `.sh`, `sql` → `.sql`, `xml` → `.xml`, `toml` → `.toml`, `rb` → `.rb`. Can be extended later.

### 2. `internal/tools/grep_test.go`

Unit tests using `t.TempDir()` as root:

- **NewGrep**: empty root uses `os.Getwd()`; valid root; invalid root returns error.
- **Execute — pattern validation**: missing pattern returns error; empty pattern returns error; invalid regex returns error.
- **Execute — path validation**: path outside root rejected; path to non-existent file/dir returns error; path to a file searches only that file; path to a directory searches recursively; omitted path searches root.
- **Execute — output modes**:
  - `files_with_matches`: returns file paths with matches, one per line.
  - `count`: returns `filepath: N` per file.
  - `content`: returns matched lines with line numbers and file headers.
- **Execute — filters**: `glob` filter restricts to matching files; `type` filter restricts to matching extensions; both combined.
- **Execute — context lines**: `before_context`, `after_context`, `context` produce correct surrounding lines in content mode; context lines don't duplicate or overlap between adjacent matches.
- **Execute — flags**: `case_insensitive` matches regardless of case; `line_numbers=false` omits line numbers; `multiline` allows patterns spanning lines.
- **Execute — pagination**: `head_limit` limits output entries; `offset` skips entries; combined offset+limit.
- **Execute — no matches**: returns "No matches found." for all output modes.
