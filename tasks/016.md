# Task 016 - Web fetch tool

## Goal

Implement an agent tool **WebFetch** that fetches content from a URL, converts HTML to markdown, optionally processes it with the configured LLM using a user prompt, and returns the result; with a short-lived in-memory cache and clear handling of cross-host redirects so the LLM can re-call with the redirect URL.

## Context

- **internal/tools**: Existing tools (ReadFile, WriteFile) implement `agent.Tool`: `Name()`, `Description()`, `Parameters() any`, `Execute(ctx, args) (string, error)`. Snake_case for parameter keys; return meaningful success/error strings so the LLM can act on them (AGENTS.md §6.2).
- **internal/agent**: Agent builds `toolDefs` and `toolsByName` from the tool list; `processOneToolCall` runs `tool.Execute(ctx, args)` and appends the result (or `error: …`) as a tool-role message. No change to the agent package for this task.
- **cmd/buildmax/root.go**: `setupAgentAndSession` creates LLM client, then ReadFile and WriteFile with CWD as root, then `NewAgent(client, tools)`. WebFetch will need the LLM client in its constructor so it can optionally call the model on fetched content.
- **Config**: `config.LoadLLM()` provides APIKey, BaseURL, Model. Use the same LLM config for WebFetch’s optional “process with prompt” step (no separate “small model” env in this task).
- **Conventions**: All-Go implementation; persisted and tool-output data use snake_case where applicable. Tools are built for the LLM: output must be clear on both success and failure.

## WebFetch (this task)

For this task, **WebFetch** means:

1. **Input**: `url` (required) and `prompt` (optional). If the URL scheme is `http`, upgrade to `https` and fetch.
2. **Redirects**: Follow redirects only when the final host equals the original request host. If a redirect goes to a **different host**, do not follow it; return a single, consistent message that includes the redirect URL so the LLM can call WebFetch again with that URL (e.g. `"Redirected to a different host. Fetch this URL instead: <redirect_url>"`).
3. **Fetch & convert**: Fetch the response body (respecting same-host redirects). If the response looks like HTML (e.g. Content-Type contains `html` or body starts with `<!`), convert it to markdown using a Go HTML-to-markdown library; otherwise treat as plain text. Apply a maximum content size (e.g. 200_000 runes); if exceeded, truncate and append a note like `(content truncated; total N characters)`.
4. **Optional LLM step**: If `prompt` is non-empty, call the configured LLM with the (possibly truncated) content and the prompt (e.g. one system/user message pair: “Answer based only on the following content.” + content, then user message with the prompt), and return the model’s reply. If `prompt` is empty or omitted, return the fetched (and converted) content as-is.
5. **Cache**: In-memory cache keyed by the **final fetched URL** (after same-host redirects), TTL 15 minutes. On cache hit, return cached result (no refetch). Do not cache cross-host redirect responses. Eviction: on access, if entry is expired, remove it and refetch.

We are **not** implementing in this task:

- Disk-persisted cache
- Separate env var for a “small/fast” model (use same BUILDMAX_MODEL)
- Custom headers, cookies, or auth for the HTTP client
- JavaScript rendering or headless browsers
- TUI or config-file changes

## Deliverables

1. **internal/tools/webfetch.go**
   - **WebFetch** struct: holds an LLM caller (`agent.LLMCaller` or `*llm.Client`), an in-memory cache (e.g. `map[string]cacheEntry` with mutex, or `sync.Map`), and cache TTL (e.g. `time.Duration`). Implement `agent.Tool`: `Name() string` → `"WebFetch"`, `Description()` → short text for the LLM (fetch URL, HTML→markdown, optional prompt to process content; prefer MCP web fetch if available; read-only; may summarize if large; cross-host redirect returns redirect URL for a new request; 15-minute cache).
   - **NewWebFetch**(caller LLMCaller, cacheTTL time.Duration) (*WebFetch, error): construct WebFetch with the given caller and TTL; no external config needed beyond caller.
   - **Parameters() any**: JSON schema with `url` (string, required), `prompt` (string, optional). Required: `["url"]`.
   - **Execute(ctx, args) (string, error)**: Parse `url` (required); if scheme is `http`, replace with `https`. Check cache by URL (after resolving same-host redirects). If cache hit and not expired, return cached string. Else: create HTTP client with custom `CheckRedirect` that returns an error when redirect host != original host (so we get the redirect URL); fetch; if cross-host redirect, return the fixed message including redirect URL. On success: read body, detect HTML vs plain text, convert HTML to markdown (use a Go library, e.g. `github.com/jaytaylor/html2text` or equivalent), apply max size and truncation. If `prompt` is non-empty, call LLM with content + prompt and return model reply; else return content. Store result in cache keyed by final URL. Return meaningful errors (e.g. invalid URL, fetch failed, timeout).

2. **internal/tools/webfetch_test.go**
   - Unit tests: (1) invalid or missing `url` returns error; (2) HTTP URL is upgraded to HTTPS in request; (3) same-host redirect is followed and content returned; (4) cross-host redirect returns the specified message format including redirect URL (no body fetch); (5) cache hit within TTL returns cached result without refetch; (6) cache miss or expired entry triggers fetch; (7) HTML response is converted to markdown (mock or small fixture); (8) non-empty `prompt` triggers LLM call and returns model reply (mock LLM); (9) empty `prompt` returns raw (converted) content; (10) oversized content is truncated with note. Use `net/http/httptest` for local servers and a mock `LLMCaller` where needed.

3. **cmd/buildmax/root.go**
   - In `setupAgentAndSession`: build the LLM client first (unchanged). Then create `webFetchTool` with `tools.NewWebFetch(client, 15*time.Minute)` (or equivalent). Pass `[]agent.Tool{readFileTool, writeFileTool, webFetchTool}` to `NewAgent`. Add any needed import (`time`, etc.).

4. **Dependencies**
   - Add a Go HTML-to-markdown library (e.g. `github.com/jaytaylor/html2text`) to `go.mod` and use it in `webfetch.go`. Prefer a pure-Go, maintained package with a simple API (HTML string → markdown string).

## Out of scope (for later)

- Config option or env var for a dedicated “web fetch” model
- Persisting the cache to disk
- Authentication, cookies, or custom headers for fetch
- JavaScript execution or headless browser
- TUI session picker or config subcommand

## Acceptance

- [ ] **WebFetch** implements `agent.Tool` and is registered in `setupAgentAndSession`; the agent can invoke it by name `"WebFetch"` with `url` and optional `prompt`.
- [ ] HTTP URLs are upgraded to HTTPS before fetch; cross-host redirects are not followed and the tool returns a single, consistent message that includes the redirect URL so the LLM can re-call with it.
- [ ] Same-host redirects are followed; response body is fetched; HTML is converted to markdown; non-HTML text is returned as-is; content over the chosen max size is truncated with an explicit note.
- [ ] When `prompt` is non-empty, the tool calls the configured LLM with the fetched (and possibly truncated) content and the prompt and returns the model’s reply; when `prompt` is empty or omitted, the tool returns the fetched/converted content.
- [ ] An in-memory cache keyed by final URL with 15-minute TTL is used; cache hit returns stored result without refetch; expired entries are refetched.
- [ ] Unit tests cover invalid/missing URL, HTTP→HTTPS upgrade, same-host redirect, cross-host redirect message, cache hit/miss/expiry, HTML→markdown, prompt vs no prompt, and truncation; tests use httptest and a mock LLM where appropriate.
- [ ] `make test` (or `go test ./...` with `HOME_DIR=./testing-sandbox`) passes.
