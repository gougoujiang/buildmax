# Task 020 - Edit file tool

## Goal

Add an agent tool **Edit** that performs exact string replacements in files under a configurable root, enabling the LLM to modify existing files by replacing content, inserting text, or making targeted edits without overwriting entire files.

## Context

- **`internal/agent`** defines the **`Tool`** interface: `Name()`, `Description()`, `Parameters() any` (JSON schema), `Execute(ctx context.Context, args map[string]any) (string, error)`. The agent wires tools via `NewAgent(caller, tools []Tool)` and passes their definitions to the LLM; tool results are sent back as tool-role messages.
- **`internal/tools`** already has **`ReadFile`** (Task 005) and **`WriteFile`** (Task 015) tools. Both follow the same pattern: constructor `NewX(root string)`, path resolution under root, and `agent.Tool` implementation.
- **`cmd/buildmax/root.go`** constructs tools in `setupAgentAndSession`: gets `cwd`, creates tools with `tools.NewReadFile(cwd)`, `tools.NewWriteFile(cwd)`, etc., and passes them to `agent.NewAgent`.
- Path safety: All tools resolve paths under a root directory (typically CWD) using `filepath.Join`, `filepath.Abs`, `filepath.Clean`, and `filepath.Rel` to reject path traversal and paths outside the allowed root.
- AGENTS.md section 6.2: Tools output meaningful results on both success and failure so the LLM can understand what happened and decide on next steps.

## Edit file tool (this task)

For this task, "edit file" means:

1. **Single tool**: One tool named **`Edit`** that the LLM can call with a file path, old string, new string, and optional `replace_all` flag to perform exact string replacements.
2. **Parameters**: Required `file_path` (string), `old_string` (string), `new_string` (string); optional `replace_all` (boolean, default false). JSON schema follows the same style as existing tools.
3. **Behavior**: Read the file at the given path, perform string replacement(s), write the modified content back. On error (file not found, path outside root, old_string not found, old_string not unique when `replace_all=false`, etc.), return a clear error message.
4. **Uniqueness check**: When `replace_all=false`, the tool must verify that `old_string` appears exactly once in the file. If it appears zero times, return error "old_string not found". If it appears multiple times, return error "old_string is not unique; use replace_all=true to replace all occurrences or provide more context to make old_string unique".
5. **Path safety**: Same path resolution and under-root check as ReadFile/WriteFile: resolve path against root, ensure it's under root, reject path traversal.
6. **File validation**: Path must exist and be a file (not a directory). Read file, perform replacement, write back atomically if possible (or write directly).

We are **not** yet implementing:

- Line-based editing (insert line at position, delete line N)
- Regex-based replacements
- Multi-file edits in a single tool call
- Undo/redo or edit history
- Conflict detection or merge logic

## Deliverables

1. **`internal/tools/editfile.go`**
   - **`EditFile` struct**: Holds `root string` (absolute path; all resolved paths must be under this). Implements `agent.Tool` interface.
   - **`NewEditFile(root string) (*EditFile, error)`**: Constructor. If root is empty, use `os.Getwd()`. Normalize and absolutize root; return `&EditFile{root: ...}` or error. Same pattern as `NewReadFile` and `NewWriteFile`.
   - **`Name() string`**: Return `"Edit"`.
   - **`Description() string`**: One or two sentences describing the tool: performs exact string replacements in files; must read file first; preserves indentation; fails if old_string is not unique (unless replace_all=true).
   - **`Parameters() any`**: JSON schema: `type: "object"`, `properties`: `file_path` (string, required), `old_string` (string, required), `new_string` (string, required), `replace_all` (boolean, optional, default false). `required`: `["file_path", "old_string", "new_string"]`. Snake_case keys.
   - **`Execute(ctx context.Context, args map[string]any) (string, error)`**: Extract and validate `file_path`, `old_string`, `new_string` (all required, non-empty strings); extract `replace_all` (boolean, default false). Resolve path: `filepath.Join(e.root, filePath)` → `filepath.Abs(filepath.Clean(...))`; ensure under root with `filepath.Rel(e.root, resolved)` and reject `..` prefix. Verify file exists and is not a directory. Read file content. Count occurrences of `old_string`. If `replace_all=false` and count != 1, return appropriate error (0 occurrences: "old_string not found"; >1: "old_string is not unique; use replace_all=true or provide more context"). Perform replacement (single or all). Write modified content back. Return success message (e.g. "File edited successfully. Replaced 1 occurrence." or "File edited successfully. Replaced N occurrences.") or error.

2. **`internal/tools/editfile_test.go`**
   - Unit tests using `t.TempDir()` as root:
     - Edit existing file: replace single occurrence (replace_all=false) succeeds
     - Edit existing file: replace all occurrences (replace_all=true) succeeds
     - File not found returns error
     - Path outside root rejected
     - Path traversal (`../outside`) rejected
     - Missing or empty `file_path`/`old_string`/`new_string` returns error
     - `old_string` not found (0 occurrences) returns error when replace_all=false
     - `old_string` not unique (multiple occurrences) returns error when replace_all=false
     - `old_string` not unique succeeds when replace_all=true
     - Target is directory returns error
     - Path resolution under root works correctly

3. **`cmd/buildmax/root.go`**
   - **Modify `setupAgentAndSession`**: After creating `writeFileTool`, add `editFileTool, err := tools.NewEditFile(cwd)`. On error, log and return. Pass `editFileTool` to `agent.NewAgent` in the tools slice: `[]agent.Tool{readFileTool, writeFileTool, webFetchTool, todoWriteTool, bashTool, globTool, editFileTool}`.

## Out of scope (for later)

- Line-number-aware editing (insert/delete at specific line numbers)
- Regex pattern matching for replacements
- Multi-file batch edits
- Edit history or undo functionality
- Atomic file writes with backup/rollback
- Encoding detection/conversion (assume UTF-8 like other tools)
- Large file handling optimizations (streaming, etc.)
