# Task 015 - Write new file

## Goal

Add an agent tool **Write** that writes content to a local file under a configurable root so the LLM can create or overwrite files (e.g. source code, config, or text) within the allowed workspace.

## Context

- **`internal/agent`** defines **`Tool`**: `Name()`, `Description()`, `Parameters() any`, `Execute(ctx, args) (string, error)`. Tools are registered via `NewAgent(caller, tools []Tool)`; tool results are sent back as tool-role messages.
- **`internal/tools`** already has **ReadFile**: root-based path resolution, path traversal rejected, `file_path` (and optional `offset`/`limit`). Implemented in `readfile.go`, tests in `readfile_test.go`.
- **`cmd/buildmax/root.go`** builds the agent with `tools.NewReadFile(cwd)` and `agent.NewAgent(client, []agent.Tool{readFileTool})`. The same **root** (current working directory at startup) is used as the allowed workspace.
- AGENTS.md: persistence and JSON use **snake_case** for keys; tools use snake_case in parameters (e.g. `file_path`).
- Build/test: `make.bat test` (or `make test`); `HOME_DIR=./testing-sandbox` for tests.

## Write tool (this task)

For this task, "Write" means:

1. **Single tool**: One tool named **`Write`** that the LLM can call with `file_path` and `content` to write text to a file.
2. **Parameters**: Required **`file_path`** (string) and **`content`** (string). JSON schema in the same style as ReadFile (`type`, `properties`, `required`).
3. **Path rules**: Resolve the given path against a **root** (same concept as ReadFile). Only allow writing under that root; reject path traversal and paths outside root with a clear error.
4. **Behavior**: Write `content` to the resolved path. If the file exists, **overwrite** it. If the parent directory does not exist, **create parent directories** with sensible permissions (e.g. `0755`) so that "write new file" works for new paths. Return a short success message (e.g. "Written N bytes to <path>") or an error string.
5. **Encoding**: Write content as UTF-8. No binary or encoding options in this task.
6. **Safety**: Do not allow writing to paths outside the root (e.g. reject `..` or absolute paths that escape root). Reject if the resolved path is a directory (target must be a file).

We are **not** in this task:

- Enforcing "read before overwrite" in code (that is LLM/user guidance only).
- Append mode, partial write, or binary content.
- TUI or CLI changes beyond wiring the new tool.
- Configurable tool list or enabling/disabling the Write tool via config.

## Deliverables

1. **`internal/tools` package**
   - **WriteFile tool**: A type (e.g. `WriteFile`) that implements **`agent.Tool`**:
     - **Name()**: returns `"Write"`.
     - **Description()**: short description so the LLM knows when to use it (e.g. write or overwrite a local file with the given content; path must be under the allowed workspace).
     - **Parameters()**: JSON schema with required `file_path` (string) and `content` (string). Use snake_case keys.
     - **Execute(ctx, args)**: read `args["file_path"]` and `args["content"]`; resolve path against the tool’s root; ensure path is under root and not a directory; create parent dirs if needed; write content as UTF-8; overwrite if file exists; return success message or error.
   - **Root**: Same pattern as ReadFile—constructor takes a root string (e.g. `NewWriteFile(root string) (*WriteFile, error)`). Root is normalized and absolutized; paths are resolved and checked to be under root.
   - **New file**: `internal/tools/writefile.go` (or `write_file.go` per project convention). No TUI or LLM imports.

2. **Wiring**
   - In **`cmd/buildmax/root.go`**: Construct the Write tool with the same root used for ReadFile (e.g. `cwd`). Add it to the slice passed to `NewAgent` so the agent can call both Read and Write (e.g. `[]agent.Tool{readFileTool, writeFileTool}`). Handle constructor errors like ReadFile.

3. **Tests**
   - **`internal/tools/writefile_test.go`**: Unit tests covering: create new file under root; overwrite existing file; path outside root rejected; path traversal (e.g. `../outside`) rejected; empty `file_path` or missing args error; parent directory created when missing; target is directory returns error. Use a temp dir as root; run tests in a way that does not depend on global cwd (e.g. `t.TempDir()`).

## Out of scope (for later)

- Append mode or line-range writes.
- Binary content or encoding options.
- Optional "read before overwrite" check in tool code.
- CLI/TUI changes for listing or confirming writes.

## Acceptance

- [ ] **WriteFile** implements `agent.Tool` with name `"Write"`, description, and parameters schema (`file_path`, `content`).
- [ ] Paths are resolved under the configured root; path traversal and paths outside root return a clear error.
- [ ] New files can be created; parent directories are created when missing; existing files are overwritten.
- [ ] Unit tests in `writefile_test.go` cover success (new file, overwrite), path safety (outside root, traversal), and invalid args; tests use a temp dir and do not touch global cwd.
- [ ] `make.bat test` (or `make test`) passes with the new tool and wiring.
- [ ] Agent can call the Write tool from prompt or TUI (manual smoke check acceptable).
