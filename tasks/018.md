# Task 018: New tool: bash

## Goal

Add a Bash tool so the agent can run shell commands in the workspace (e.g. git, npm, docker) with a configurable timeout and safe output truncation, returning meaningful results to the LLM on both success and failure.

## Context

- **internal/tools**: Existing tools (Read, Write, WebFetch, TodoWrite) implement `agent.Tool`: `Name()`, `Description()`, `Parameters()`, `Execute(ctx, args) (string, error)`. Parameters use OpenAI-style JSON schema; args use snake_case (e.g. `file_path`). Tools return clear success text or error messages so the LLM can decide next steps (AGENTS.md §6.2).
- **internal/agent**: `NewAgent(caller, tools)` builds toolDefs and toolsByName; each tool call is dispatched by name and `Execute` is called with parsed args. Agent prefixes tool errors with `error: ` when sending to the LLM.
- **cmd/buildmax/root.go**: `setupAgentAndSession` gets cwd, creates tools (e.g. `NewReadFile(cwd)`, `NewWriteFile(cwd)`), and passes them to `NewAgent`. Bash will receive the same workspace root (cwd) so commands run in a predictable directory.
- **Conventions**: All-Go; no TUI in tools; tool output must be meaningful for the LLM; `make.bat test` uses `HOME_DIR=./testing-sandbox` for tests.

## Bash tool (this task)

For this task, the Bash tool:

1. **Runs one command per call** in a new process (no persistent shell session). Working directory is the tool’s configured root (workspace).
2. **Shell**: On Unix use `bash -c "<command>"` if bash is available, else `sh -c "<command>"`. On Windows use `cmd /c "<command>"` (or equivalent so a single string runs as one command).
3. **Parameters**: `command` (required string). Optional `timeout` (number, milliseconds; default 120_000, max 600_000).
4. **Execution**: Start process with Dir set to tool root; cancel/kill on context deadline or timeout. Capture combined stdout and stderr.
5. **Output**: Return combined stdout+stderr. If length exceeds 30_000 runes, truncate and append a note (e.g. "(output truncated; total N characters)").
6. **Success**: Exit code 0 → return captured output (possibly truncated).
7. **Failure**: Non-zero exit or execution error → return a clear message (e.g. exit code and truncated output, or error description) so the LLM can retry or inform the user. Do not rely on the agent’s "error: " prefix as the only signal; the tool’s returned string should be self-explanatory.

We are **not** implementing in this task:

- Persistent shell session (stateful shell across calls).
- `run_in_background` or async execution with later result retrieval.
- `dangerouslyDisableSandbox` or any sandbox bypass (commands always run in the configured root as working directory).
- Interactive or PTY-based execution.

## Deliverables

1. **internal/tools/bash.go**
   - **Bash** struct: holds `root string` (absolute path, working directory for commands).
   - **NewBash(root string) (*Bash, error)**: If root is empty, use `os.Getwd()`. Normalize and absolutize root (same pattern as ReadFile/WriteFile). Return error if root cannot be resolved.
   - **Name() string**: return `"Bash"`.
   - **Description() string**: Short description for the LLM: run a shell command in the workspace; optional timeout (default 2 min, max 10 min); output truncated if over 30k characters; for terminal operations (git, npm, etc.), not for file read/write/search (prefer Read/Write/Glob/Grep).
   - **Parameters() any**: JSON schema with `command` (string, required), `timeout` (number, optional, milliseconds; document default 120000, max 600000).
   - **Execute(ctx context.Context, args map[string]any) (string, error)**:
     - Parse `command` (required); trim and reject empty.
     - Parse optional `timeout` (default 120_000 ms, max 600_000 ms; invalid/negative → use default).
     - Build command line for the OS (bash/sh on Unix, cmd on Windows); set process Dir to `b.root`.
     - Run with a context that respects both `ctx` and the chosen timeout (whichever cancels first). Kill process on cancel.
     - Capture combined stdout+stderr. On success (exit 0), return output, truncating at 30_000 runes with a truncation note. On non-zero exit or run error, return a clear message (e.g. "exit code N" plus truncated output, or run error text).
   - Use `os/exec` and standard library only; no external deps. Prefer `exec.CommandContext` and proper handling of context cancellation.

2. **internal/tools/bash_test.go**
   - Tests: NewBash with empty root (use Getwd), with valid root; Execute success (e.g. echo hello); Execute non-zero exit; Execute timeout (command that sleeps longer than a short timeout); Execute output truncation (command that prints many chars); missing or empty `command` returns error; invalid timeout is clamped or ignored to default.

3. **cmd/buildmax/root.go**
   - In `setupAgentAndSession`: after existing tools, `bashTool, err := tools.NewBash(cwd)`; on error log and return. Pass `bashTool` in the slice to `NewAgent` (order: readFileTool, writeFileTool, webFetchTool, todoWriteTool, bashTool).

## Out of scope (for later)

- Persistent shell session (reuse one shell process for multiple commands).
- Background execution and TaskOutput-style result retrieval.
- Sandbox disable or running outside workspace root.
- Optional `description` parameter (LLM-side hint); no change to tool schema required for that.

## Acceptance

- [ ] **NewBash**: Empty root uses current working directory; non-empty root is normalized and absolutized; invalid root returns error.
- [ ] **Bash** implements `agent.Tool`: Name "Bash", Description and Parameters match spec (command required, timeout optional with default/max).
- [ ] **Execute**: Command runs in tool root as working directory; combined stdout+stderr returned; output over 30k runes truncated with note.
- [ ] **Execute**: Exit code 0 returns output; non-zero exit returns clear message including exit code and (truncated) output.
- [ ] **Execute**: Timeout is enforced (e.g. sleep 10 with 100ms timeout returns error or timeout message); context cancellation stops the process.
- [ ] **Execute**: Missing or empty `command` returns a clear error string.
- [ ] **Tests**: Unit tests cover success, non-zero exit, timeout, truncation, and invalid args; tests run with `make.bat test` (or `go test ./internal/tools/...`).
- [ ] **Wiring**: `setupAgentAndSession` creates Bash with cwd and includes it in the tool list passed to `NewAgent`; agent can invoke Bash from TUI or prompt mode.
