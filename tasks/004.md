# Task 004 - Log Framework (slog)

## Goal

Adopt Go's standard library **`log/slog`** as the application's logging framework, with level filtering, env-based level control, and a **persisted log file** under the application data dir with **rotation**, so the rest of the app can log at Debug, Info, Warn, and Error to both stderr and a rotating file.

## Context

- There is no logging in the codebase yet; errors and messages are printed via `fmt` to stderr (e.g. in `cmd/buildmax/main.go`).
- AGENTS.md calls out "Infrastructure such as config, logging, and persistence" and requires all-Go implementation.
- The project uses **Go 1.21+** (e.g. 1.25.x); **`log/slog`** is built-in and is the Go team's recommended structured logging API.
- **slog does not support log rotation**; it only writes to an `io.Writer`. Rotation is done by the writer. The usual choice in Go is **Lumberjack** (e.g. `gopkg.in/natefinch/lumberjack.v2`): it implements `io.Writer`, rotates by size, keeps N backups, and optionally compresses. We add Lumberjack as the single extra dependency for file rotation.
- Application data dir is given by **`config.DataDir()`** (default `~/.buildmax`, or **`HOME_DIR`** when set). We persist logs under **`DataDir()/logs`**.
- `internal/config` uses env vars with a `BUILDMAX_` prefix for app-specific settings; log level will follow the same convention.
- New infrastructure lives under `internal/`; we add a thin **`internal/log`** package that configures slog's default logger.

## Log framework (this task)

For this task, "log framework" means:

1. **slog as the logger**: The application uses **`log/slog`** for all logging. Code calls `slog.Debug`, `slog.Info`, `slog.Warn`, `slog.Error` (and format variants) directly; no custom log API in this task.
2. **Configuration**: **`internal/log`** configures **`slog.Default()`** at startup: minimum level from **`BUILDMAX_LOG_LEVEL`** (case-insensitive: `debug`, `info`, `warn`, `error`, `off`), and output to **both**:
   - **stderr** (for interactive use), and
   - a **persisted log file** under **`config.DataDir()/logs`** (e.g. `buildmax.log`), using **Lumberjack** so the file rotates by size and keeps a limited number of backups.
3. **Log file path**: **`{DataDir()}/logs/buildmax.log`**. Create the **`logs`** directory under `config.DataDir()` if it does not exist when `Init()` runs.
4. **Level filtering**: Only messages at or above the configured minimum level are written. Default minimum level is **Info** when `BUILDMAX_LOG_LEVEL` is unset or invalid.
5. **Testability**: `internal/log` must provide a way for tests to redirect output (e.g. **`SetOutput(w io.Writer)`** or equivalent) so tests can assert on log content without writing to stderr or the real log file.

We are **not** in this task:

- Adding any third-party logging *API*; we use only **`log/slog`** (Lumberjack is only a writer for rotation).
- Integrating the logger into TUI or agent code (callers will use `slog` in a follow-up); only configuration and tests are in scope.
- Replacing every existing `fmt` usage in `main` with slog.

## Deliverables

1. **`internal/log` package**
   - **Configure default logger**: **`Init()`** sets `slog.Default()` to a logger that uses:
     - **Level**: Parsed from **`BUILDMAX_LOG_LEVEL`** (values: `debug`, `info`, `warn`, `error`, `off`). Invalid or empty → default to **`slog.LevelInfo`**.
     - **Output**: **`io.MultiWriter(os.Stderr, fileWriter)`** where `fileWriter` is a **Lumberjack** writer writing to **`filepath.Join(config.DataDir(), "logs", "buildmax.log")`**. Create the **`logs`** directory under `config.DataDir()` if it does not exist (e.g. `os.MkdirAll(..., 0750)`).
     - **Handler**: `slog.NewTextHandler(multiWriter, &slog.HandlerOptions{Level: level})`.
   - **Lumberjack settings**: Use sensible defaults for the log file: e.g. MaxSize (e.g. 10 MB), MaxBackups (e.g. 3), MaxAge (e.g. 7 days), Compress (optional, e.g. true for rotated files). Exact values left to implementer; document them in code or a comment.
   - **SetOutput for tests**: Expose **`SetOutput(w io.Writer)`** (or equivalent) that replaces the default logger's handler so it writes only to `w`. Tests use this to capture output in a `bytes.Buffer` without touching stderr or the real log file. No TUI or Bubble Tea imports in this package.
   - **Init()**: Explicit **`Init()`** called from `main` so `main` controls when configuration runs and tests can run without creating the real logs dir.

2. **Wire-up in main**
   - In **`cmd/buildmax/main.go`**, call the log package's init at startup (e.g. **`buildmaxlog.Init()`**) so the default slog logger is configured before any code logs. Use an import alias to avoid shadowing the standard `log` package (e.g. `buildmaxlog "buildmax/internal/log"`). No need to replace existing `fmt` usage in this task.

3. **Tests**
   - **Level filtering**: Unit test that when minimum level is Info, `slog.Debug` does not produce output to the configured writer, and `slog.Info` does.
   - **Env default**: Unit test that with `BUILDMAX_LOG_LEVEL` set (e.g. via `t.Setenv`) to `debug`, the configured level allows Debug messages; use a fresh output buffer and restore env after test.
   - **Output**: Test that messages at or above the minimum level are written to the writer set by `SetOutput` and contain the expected level and message text (slog TextHandler format is sufficient).
   - **Log file (optional)**: Optionally test that `Init()` creates `DataDir()/logs` and that the Lumberjack file is created when logging (e.g. with `HOME_DIR` set to a temp dir). Not required if it complicates tests; at least document that production writes to both stderr and file.

4. **Dependencies**
   - **`log/slog`**: standard library.
   - **Lumberjack**: add **`gopkg.in/natefinch/lumberjack.v2`** (or v3 if preferred) to **`go.mod`** for log file rotation. No other new dependencies.

## Out of scope (for later)

- Replacing existing `fmt`/stderr usage in `main` or other packages (follow-up task).
- TUI or agent code that calls `slog` (they will use it in a follow-up).
- Multiple named loggers or per-package levels; a single default logger with one minimum level is enough for this task.
- JSON output (slog's JSONHandler); TextHandler is sufficient for this task.
- Configurable Lumberjack options via env or config file; sensible defaults in code are enough for this task.

## Acceptance

- [ ] **slog**: `internal/log` configures `slog.Default()` with minimum level from **`BUILDMAX_LOG_LEVEL`** (debug, info, warn, error, off). Invalid or empty env → level Info.
- [ ] **Dual output**: Default handler writes to **both** `os.Stderr` and a **persisted log file** at **`config.DataDir()/logs/buildmax.log`**. Create **`logs`** under `config.DataDir()` if it does not exist.
- [ ] **Rotation**: The log file uses **Lumberjack** so it rotates by size and keeps a limited number of backups (and optionally compresses). Lumberjack is the only new dependency in `go.mod`.
- [ ] `internal/log` exposes **`SetOutput(w io.Writer)`** (or equivalent) so tests can capture log output without writing to stderr or the real file.
- [ ] **`cmd/buildmax/main.go`** calls the log package's init (e.g. `buildmaxlog.Init()`) at startup so the default logger is configured before any logging.
- [ ] Unit tests: (1) level filtering (Debug not written when level is Info; Info is written); (2) env-based level (`BUILDMAX_LOG_LEVEL=debug` allows Debug); (3) output content (level and message visible in captured buffer).
- [ ] Code follows project layout and AGENTS.md (Go only, `internal/log`).
