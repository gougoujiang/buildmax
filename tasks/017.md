# Task 017 - Todo write tool

## Goal

Implement an agent tool **TodoWrite** that lets the agent create and update a structured task list during a session (pending, in progress, completed), so the user and agent can track multi-step progress. The list is session-scoped: each chat session has its own todo list.

## Context

- **internal/tools**: Existing tools (ReadFile, WriteFile, WebFetch) implement `agent.Tool`: `Name()`, `Description()`, `Parameters() any`, `Execute(ctx, args) (string, error)`. Snake_case for parameter keys; return meaningful success/error strings for the LLM (AGENTS.md §6.2).
- **internal/agent**: Agent runs `processLoop(ctx, sess)` and calls `tool.Execute(ctx, args)` for each tool call. Context is passed but does not currently carry session identity. Session is available in the agent but not passed to tools.
- **internal/session**: Session has `ID() string` (UUID). No context helpers today; adding `CtxWithSessionID` and `SessionIDFromContext` will let tools get the current session ID from `ctx` so they can scope state per session.
- **Conventions**: All-Go; snake_case for JSON and persisted data (AGENTS.md §6.1). Tools must return clear success/error messages.

## TodoWrite (this task)

For this task, **TodoWrite** means:

1. **Session-scoped list**: The todo list is keyed by session ID. The agent must set the session ID in `context.Context` before invoking tools so TodoWrite can read it (e.g. via `session.SessionIDFromContext(ctx)`). Each session has its own list; switching sessions gives a different list.
2. **Replace semantics**: Each tool call receives a full list of todos and **replaces** the current list for that session. The LLM maintains the list in its reasoning and sends the full desired state each time (add/update/complete by including all items with updated status).
3. **Todo item shape**: Each item has `content` (string, short description), `status` (string: `pending`, `in_progress`, or `completed`), and `active_form` (string, optional; e.g. present-tense description like "Running tests"). Snake_case in the JSON schema and tool arguments.
4. **In-memory only**: Store is in-memory (e.g. `map[sessionID][]TodoItem`). No persistence to disk in this task; lists are lost when the process exits.

We are **not** implementing in this task:

- Persisting todo lists to disk or session files
- TUI display of the todo list (only the tool and agent use it; the LLM can summarize in replies)
- Partial updates (e.g. "add one item" or "mark item 3 completed") — the tool takes the full list and replaces

## Deliverables

1. **internal/session**
   - Add a private context key type and package-level key variable.
   - **CtxWithSessionID**(ctx context.Context, id string) context.Context — returns a context that carries the given session ID.
   - **SessionIDFromContext**(ctx context.Context) (string, bool) — returns the session ID from ctx, or ("", false) if not set.
   - Used by the agent to inject session ID and by TodoWrite to read it.

2. **internal/agent**
   - In **processLoop**: at the start of each iteration (or once at the top of the loop), set `ctx = session.CtxWithSessionID(ctx, sess.ID())` so that when `processOneToolCall(ctx, a, sess, tc)` runs, `ctx` carries the session ID. Pass this `ctx` into all LLM calls and tool executions in that loop.

3. **internal/tools/todowrite.go**
   - **TodoWrite** struct: holds an in-memory store (e.g. `map[string][]todoItem` keyed by session ID), protected by a mutex. Implements `agent.Tool`: Name → `"TodoWrite"`, Description (short text for the LLM: create/update a structured task list for the current session; items have content, status, active_form; use to track multi-step progress), Parameters (JSON schema: `todos` — array of objects with `content` (string), `status` (string: pending | in_progress | completed), `active_form` (string, optional); required `["todos"]`).
   - **NewTodoWrite**() (*TodoWrite, error): returns a TodoWrite with an empty store (no constructor args needed).
   - **Execute**(ctx, args) (string, error): Read session ID from ctx via `session.SessionIDFromContext(ctx)`. If missing, return a clear error (e.g. "session ID not in context"). Parse `todos` from args (required; must be array of objects with content, status, active_form). Validate each item (content non-empty, status one of the three). Replace store[sessionID] with the parsed list. Return a short confirmation (e.g. "Updated N todos." or list summary) so the LLM knows the update succeeded.

4. **internal/tools/todowrite_test.go**
   - Unit tests: (1) missing session ID in context returns error; (2) session ID in context: valid todos replace store and return success; (3) missing or invalid `todos` (not array, wrong item shape) returns error; (4) invalid status value returns error; (5) two different session IDs get separate lists (store isolation); (6) Name/Description/Parameters and that TodoWrite implements agent.Tool. Use a context created with `session.CtxWithSessionID(context.Background(), "test-session-id")` for success cases.

5. **cmd/buildmax/root.go**
   - In `setupAgentAndSession`: create `todoWriteTool, err := tools.NewTodoWrite()`; on error log and return. Pass `readFileTool`, `writeFileTool`, `webFetchTool`, `todoWriteTool` to `NewAgent`.

## Out of scope (for later)

- Persisting todo lists to disk or embedding them in session JSON
- TUI panel or view that displays the todo list
- Partial update API (e.g. add one, remove one); this task uses full-list replace only
- Todo item IDs or ordering guarantees beyond array order

## Acceptance

- [ ] **session** package exposes `CtxWithSessionID` and `SessionIDFromContext`; agent sets session ID in context at the start of processLoop and passes that ctx to tool execution.
- [ ] **TodoWrite** implements `agent.Tool` and is registered in `setupAgentAndSession`; the agent can invoke it by name `"TodoWrite"` with `todos` (array of {content, status, active_form}).
- [ ] Todo list is keyed by session ID from context; when session ID is missing, Execute returns a clear error; when present, the list for that session is replaced and a short success message is returned.
- [ ] Unit tests cover missing session ID, valid replace, invalid/missing todos, invalid status, and per-session store isolation; tests use `session.CtxWithSessionID` for context.
- [ ] `go build ./...` and `go test ./...` (with `HOME_DIR=./testing-sandbox`) pass.
