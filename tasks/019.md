# Task 019 - New tool: Glob

## Goal

Enable the agent to find files by name or extension under a configurable root via a new Glob tool: one required parameter (pattern), optional search directory, results sorted by modification time, with clear success/error messages for the LLM.

## Context

- **internal/tools**: Existing tools (ReadFile, WriteFile, WebFetch, TodoWrite, Bash) implement `agent.Tool`; each has a constructor (e.g. `NewReadFile(root)`), `Name`, `Description`, `Parameters`, and `Execute`. ReadFile and Bash use a single `root` (absolute path) and resolve user-provided paths under that root.
- **internal/agent**: `NewAgent(caller, tools)` builds `toolDefs` and `toolsByName`; tool calls are dispatched by name and `Execute` is called with parsed args. Agent prefixes tool errors with `error: ` when sending to the LLM.
- **cmd/buildmax/root.go**: `setupAgentAndSession` gets `cwd`, creates tools with that root, and passes them to `NewAgent`. Glob will receive the same workspace root (cwd).
- **AGENTS.md**: Tool output must be meaningful on success and failure so the LLM can decide next steps; use snake_case for JSON keys in persisted/schema data where applicable; prefer all-Go implementation.

## Glob (this task)

For this task, **Glob** means:

1. A tool that lists files under a **search root** (the tool’s configured root, or a subdirectory of it when the optional `path` argument is provided).
2. **Pattern**: Required. Glob pattern (e.g. `*.go`, `**/*.js`, `src/**/*.ts`). Must support at least `*` (any non-separator sequence) and `**` (any directory depth); implementation may use `filepath.WalkDir` + custom match or a small pure-Go library (e.g. doublestar) for `**`.
3. **path**: Optional. Directory to search in, relative to the tool’s root. If omitted, search the tool’s root. Must not be `"undefined"` or `"null"`; omit the field for default. If provided, must resolve to a directory under the tool’s root.
4. **Result**: Matching file paths (relative to search root or absolute, as long as consistent and clear for the LLM), sorted by modification time (e.g. newest first). Return a clear message on success (e.g. list of paths or “no matches”) and on failure (e.g. path outside root, not a directory, permission denied).

We are **not** yet implementing:

- Grep/search-in-content (separate tool).
- Configurable sort order (newest-first is sufficient for this task).
- Symlink following policy (follow or not is an implementation detail; document behaviour).

## Deliverables

1. **internal/tools/glob.go**
   - **Glob** struct with field `root string` (absolute path; all resolved paths must be under this).
   - **NewGlob(root string) (*Glob, error)**: If root is empty, use `os.Getwd()`. Normalize and absolutize root (same pattern as ReadFile/Bash). Return error if root cannot be resolved.
   - **Name() string**: Return `"Glob"`.
   - **Description() string**: Short description for the LLM: fast file pattern matching; supports patterns like `**/*.js` or `src/**/*.ts`; returns matching paths sorted by modification time; use to find files by name/extension; prefer multiple parallel tool calls when useful; for open-ended search consider other strategies (e.g. Agent tool). Align with the description in the task detail.
   - **Parameters() any**: OpenAI-style JSON schema: `pattern` (string, required), `path` (string, optional). Description for `path`: directory to search in; if omitted, the tool’s default root is used; do not pass "undefined" or "null"—omit the field; must be a valid path under the workspace if provided.
   - **Execute(ctx context.Context, args map[string]any) (string, error)**:
     - Parse `pattern` (required, non-empty after trim). Return error if missing or empty.
     - Parse optional `path`; if present, resolve against `root` and ensure it is under `root` and is a directory; otherwise use `root` as search directory.
     - List files under the search directory that match the pattern (files only, not directories). Support `**` for recursive matching (e.g. via `filepath.WalkDir` and a matcher, or doublestar).
     - Sort matches by modification time (newest first).
     - Return a single string suitable for the LLM: e.g. one path per line, or "No files matched the pattern.", or a clear error message. On validation or system errors (path outside root, not a directory, permission denied), return a descriptive error so the agent can send `error: ...` to the LLM.

2. **internal/tools/glob_test.go**
   - Tests for **NewGlob**: empty root (uses Getwd), valid root, invalid root returns error.
   - Tests for **Execute**: success with simple pattern (e.g. `*.go` or `*.*`); success with recursive pattern (e.g. `**/*.txt`) if supported; no matches returns a clear message; optional `path` restricts search to that subdirectory; path outside root returns error; path to non-directory returns error; missing or empty `pattern` returns error.

3. **cmd/buildmax/root.go**
   - In `setupAgentAndSession`, after `bashTool`: create `globTool, err := tools.NewGlob(cwd)`; on error log and return. Pass `globTool` in the slice to `NewAgent`: `[]agent.Tool{..., bashTool, globTool}`.

## Out of scope (for later)

- Grep tool (search file contents).
- Configurable result limit or sort order.
- Following vs not following symlinks (implementation choice; document in code).

## Acceptance

- [ ] **NewGlob**: Empty root uses current working directory; non-empty root is normalized and absolutized; invalid root returns error.
- [ ] **Glob** implements `agent.Tool`: Name `"Glob"`, Description and Parameters match the spec; Execute returns a string (path list or message) or error.
- [ ] **Execute**: Required `pattern`; optional `path` resolves under tool root; path outside root or to a non-directory returns a clear error; matches are files only, sorted by modification time (newest first); success and “no matches” both return a clear, LLM-friendly message.
- [ ] **Tests**: NewGlob and Execute cases above are covered; tests run with `make.bat test` (or equivalent) and pass.
- [ ] **Wiring**: `setupAgentAndSession` creates Glob with cwd and includes it in the tool list passed to `NewAgent`; agent can invoke Glob by name and receive results.
