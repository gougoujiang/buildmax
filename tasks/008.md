# Task 008 - Persist sessions to file system

## Goal

Save chat sessions to disk under the application data directory so they can be loaded and resumed across runs via a `--resume <session-id>` flag.

## Context

- **`internal/session`**: `Session` holds id (UUID), title, created_at, and `[]llm.Message`; has `NewSession(title)`, `Append`, `Messages`, `ID`, `Title`, `CreatedAt`, `SetTitle`. All fields are unexported (task 007).
- **`internal/config`**: `DataDir()` returns the application data folder (env `HOME_DIR` if set, else `~/.buildmax`). Does not create the directory (task 003).
- **`cmd/buildmax`**: Prompt mode runs `buildmax -p PROMPT`: creates one `session.NewSession("")`, calls `agent.Process(ctx, sess, prompt)`, prints reply. No persistence today.
- **`internal/llm`**: `Message` has exported fields (`Role`, `Content`, `ToolCallID`, `ToolCalls`) so it is JSON-serializable.
- AGENTS.md: "Conversation and history: … optional persistence." Build/test: `./make build`, `./make test`.

## Session persistence (this task)

For this task:

1. **Sessions directory** = `filepath.Join(config.DataDir(), "sessions")`. Create it on first save if it does not exist.
2. **One file per session** = `<session-id>.json` (session id is UUID; safe as filename).
3. **File content** = JSON with: session id, title, created_at (RFC3339 or Unix), and messages (array of `llm.Message`). No system message in history.
4. **Save** = after each successful prompt-mode run (new or resumed), write the session to `sessions/<id>.json`, overwriting if present.
5. **Resume** = `buildmax --resume <session-id> -p PROMPT`: load session from `sessions/<session-id>.json`; if file missing or invalid, print error to stderr and exit non-zero. Then run agent with that session and the given prompt, then save.

We are **not** yet implementing:

- Listing or deleting sessions from the CLI.
- TUI integration (session list, picker, or resume from TUI).
- Migration or versioning of session file format.
- Auto-save during TUI or multi-turn in a single process.

## Deliverables

1. **`internal/session`**
   - **Persistence type**: Define an exported (or package-internal) struct used only for JSON: session id, title, created_at, messages. Use it for encoding/decoding; do not expose `Session`’s internal fields.
   - **Save**: `SaveToDir(s *Session, dir string) error`. Serialize the session to JSON and write to `dir/<s.ID()>.json`. Create `dir` (and parents) if it does not exist. Use standard `encoding/json`; created_at as RFC3339 string is fine.
   - **Load**: `LoadFromDir(dir string, sessionID string) (*Session, error)`. Read `dir/<sessionID>.json`; if file missing or invalid JSON, return a clear error. Construct and return a `*Session` with the same id, title, created_at, and messages (so the session can be used for further turns).
   - **Constructor for loaded data**: Add a way to build a `Session` from loaded id/title/created_at/messages (e.g. `NewSessionFromData(id, title string, createdAt time.Time, messages []llm.Message) *Session` or equivalent) so `LoadFromDir` can return a valid session without exporting session fields.
   - Session package must not depend on `internal/agent` or `cmd/buildmax`; it may use `internal/llm` and `internal/config` only for types and `config.DataDir()` if needed for a helper, or callers pass the dir.

2. **`cmd/buildmax`**
   - **Sessions directory**: Use `filepath.Join(config.DataDir(), "sessions")` as the sessions root. Create it when saving (session package can create it in `SaveToDir`).
   - **Flag `--resume`**: Add `-resume` (or `--resume`) taking a single argument (session id). Usage: `buildmax --resume <session-id> -p PROMPT` to load that session, run one turn with PROMPT, then save. If `--resume` is given without `-p`, show usage/error (resume requires a prompt for this task). If session file is missing or unreadable: print a clear error to stderr (e.g. "session not found: <id>") and exit with non-zero.
   - **New session (no resume)**: Keep current behavior: `buildmax -p PROMPT` creates a new session, runs one turn, then **saves** the session to disk (so it can be resumed later).
   - **Help**: Update usage string to document `--resume <session-id>` and that prompt mode saves sessions under the app data directory.

3. **Tests**
   - **`internal/session`**: (1) `SaveToDir(s, dir)` creates `dir/<s.ID()>.json` and the file contains valid JSON with id, title, created_at, messages; (2) `LoadFromDir(dir, id)` after save returns a session with same ID, Title, CreatedAt, and message count/order; (3) `LoadFromDir` with missing file or invalid JSON returns non-nil error; (4) round-trip: NewSession → Append messages → SaveToDir → LoadFromDir → assert Messages() equal.

4. **Dependencies**
   - No new external Go modules required; use `encoding/json`, `os`, `path/filepath`.

## Out of scope (for later)

- Listing sessions (e.g. `buildmax list-sessions`) or deleting a session from disk.
- TUI: session list, session picker, or resuming a session from the TUI.
- Versioning or migration of session file format.
- Running multiple turns in one process without exiting (e.g. REPL); this task is one prompt per run, save after that run.

## Acceptance

- [ ] **SaveToDir**: `session.SaveToDir(s, dir)` creates `dir` if needed and writes `dir/<s.ID()>.json` with JSON containing id, title, created_at, messages; unit test confirms file exists and content is valid.
- [ ] **LoadFromDir**: `session.LoadFromDir(dir, id)` returns a session matching the saved data; unit test round-trips Save → Load and compares ID, Title, CreatedAt, Messages.
- [ ] **Load errors**: `LoadFromDir` with missing file or invalid JSON returns a non-nil error; test(s) cover both cases.
- [ ] **Prompt mode (new session)**: `buildmax -p PROMPT` creates a new session, runs agent, then saves session to `config.DataDir()/sessions/<id>.json`.
- [ ] **Resume**: `buildmax --resume <session-id> -p PROMPT` loads that session, runs one turn with PROMPT, then saves; if session file is missing or invalid, error is printed to stderr and process exits non-zero.
- [ ] **Usage**: Help documents `--resume <session-id>` and that sessions are saved under the app data directory.
- [ ] **Build and test**: `./make build` and `./make test` pass.
