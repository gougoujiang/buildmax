# 探索式测试记录

> **翻译说明：** 本文是[英文原文](../../../contribute/exploratory-runs/README.md)的简体中文派生翻译。若中英文存在语义冲突，以英文原文为准。
> **受众：** 贡献者与测试 Agent · **状态：** 当前有效

[探索式测试](../exploratory-testing.md)会话的、带日期的记录。每个文件是一次会话的报告，按该指南的简短报告结构撰写并提交，使一项发现及其得出过程在会话工作目录消失后仍然留存。

## 哪些应当归档于此

当一次会话产生了值得留存的结果时提交报告：已确认或疑似缺陷、可用性障碍、可复用的探索任务章程，或其他贡献者会需要的证据。没有产生持久价值的会话留在被 git 忽略的 `.artifacts/` 工作目录即可，无需提交——不要制造覆盖率记录。

报告按[exploratory-testing.md](../exploratory-testing.md)中的结构撰写，并内联最短复现步骤与关键观察。`.artifacts/` 下的原始记录是临时的；提交的报告必须在它们消失后仍能自洽。提交前隐去凭据、登录码和无关隐私数据。

## 这是记录，不是工作队列

可执行的发现仍需成为一个修复 PR、一个 backlog 任务或一个 GitHub issue，遵循 [AGENTS.md](../../../../AGENTS.md)——一项一处。报告作为证据与历史链接到那个工作项，而不追踪其状态，因此报告绝不会成为工作项存在的第二处。

报告是绑定到它所标注提交的时间点记录。不要为跟随后续行为而修改它——改为链接工作项。当发现已解决且不再具有示范价值时删除该报告；本项目不保留任何必须长期留存的内容。

## 约定

- 文件名：`YYYY-MM-DD-<surface>-<slug>.md`，例如 `2026-09-13-cli-first-use-continuity.md`。`<surface>` 为 `portal`、`desktop`、`cli`、`worker` 等。
- 报告使用英文撰写，即仓库产物语言。本索引有中文镜像；单份报告不翻译。
- 提交报告时在下表新增一行；删除报告时移除该行。
