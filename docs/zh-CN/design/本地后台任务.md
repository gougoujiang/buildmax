## 问题

BuildMax 可以执行耗时较长的本地工作，但无法把这些工作暂时放到后台并保持对话可响应：

- `Bash.Execute` 会阻塞在 `cmd.Run` 上，默认超时 120 秒，最长 10 分钟。
- `Task.Execute` 会阻塞，直到子 Agent 返回最终回复。
- 并行工具执行只会重叠相邻的只读调用；`Bash` 和 `Task` 都是写入屏障。
- TUI 和 Desktop 中，每个会话或项目一次只能有一个顶层运行。其他消息会在其后排队（见[排队消息](排队消息.md)），不会创建独立工作。

缺失的能力远不止一个 `run_in_background` 布尔值。启动工具调用一旦返回，进程中就没有任何对象拥有这项操作：没有身份、状态、有界输出、取消、完成通知或追踪关联。Monitor 还增加了一项要求——它必须在存活期间发出事件，并允许 Agent 对这些事件作出响应。

### 根据轴的替代方案

在产品级别选择下，实施空间分解成四个独立的轴。

| 轴 | 选中的 | 最强的替代方案 | 判决 |
|---|---|---|---|
| 管理者拓 | 经理:`AgentApp` | 在一个单元插座背后的本地妖怪 (docker / tmux服务器形状)，这可以免费提供跨UI工作生存 | 推迟，不被拒绝 是监督者一个过程中生存的工作需要，这是[没有计划](#长久性不是计划的)。 |
| 活动交付 | 会议收件箱，有序式唤醒，层次叠加可查询的工作工具 | 运行循环，从来没有出门，在事件频道上阻塞 (演员模型) | 拒绝：它重写了`RunLoop`合同，运行量度的痕迹，以及收件箱已经购买的优雅的紧缩时间。 Hook |
| 过程适配器 | 具有过程组/工作目标的`exec` | 基于PTY托管 (ConPTY在Windows上)，因此线性缓冲程序在实时中发出输出 | 作为第一个版本的明确限制推迟；当一个真实情况强迫它时，添加一个PTY适配器 |
| 监视表格 | 一个通用命令，其的动态线是事件 | 类型的原生观察员 (档案观察,HTTP调查)，建筑界限 | 后期糖，不是竞争对手：如果大多数监视器看一个文件，将一个打字类型添加到同一工作和事件管道上。 |

另外，在拓轴上考虑并拒绝了：使用 pidfiles的孤儿进程 (PID重用，没有现场事件流尽管其磁盘格式是出口卷轴所需的)，并委托给tmux或OS服务管理人员 (对单双规则的外部依赖，以及三个含义性的三个平台)。

术语：本设计使用**job**用于本地运行时间对象，因此不会与Portal的`Task`实体或`Task`子工具发生冲突。

| 时间 | 意思 |
|---|---|
| 背景工作 | 一个`AgentApp`，工作空间和本地会议的所有权的过程扩展装置 |
| 司令部工作 | 发射器:Runs一个命令并发布终端结果 |
| 职位 | 克达相关标识符一个孤立的子文本，并发表了最后的答案 Runs |
| 监督工作 | Runs一个命令，其停留线成为到出门，停留时间，停止或关闭的事件 |
| 工作活动 | 具有明确来源的限定的生命周期，输出，完成或监控记录 |
| 起的起 Agent | 由于排队工作事件，导致新的串联顶级转变，从来没有同时写到会议历史 |

工作是**过程范围但会话所有**：当用户在同一过程中切换会话时，一个工作可能会继续进行，但其事件和结果属于启动的会话.关闭拥有`AgentApp`或应用程序会停止它。

## 子代理 Runtime

### 管理者和所有权

`AgentApp`拥有一个工作管理员，其工作空间的工作管理员  Desktop已经缓存一个项目，而 TUI拥有一个过程 给管理员一个生命周期，超过了任何工具调用，没有新的全球进程.管理员的操作是启动，列表，获取，基于线索输出读取，停止，每次会议订阅，和关闭。

订阅是流量，目前的限制是无价的，并且不需要重新写`internal/tool`或任何表面。

包装所有权遵循现有的边界:`internal/agentapp`协调工作和会议；过程创建和过程树终止是平台代码在`internal/infra`;LLM面向论证验证和工具输出停留在`internal/tool`;`internal/core/agent`进口没有任何。

每个工作都在开始时捕获不可变的来源：工作身份和类型；工作空间和会议身份；工具启动时母脚跟身份和母工具调用身份；模特和子字符类型的子字符类型；已解决的沙箱和许可证事实；时间邮票；终端状态和有限的错误总结.沙箱边界在启动时被捕获，因此设置重新加载不能默默地改变运行工作的边界。

### 国家机器

```text
starting → running → succeeded
                   → failed
                   → canceled
```

`canceled`意味着BuildMax接受了停止请求，操作结束，并携带一个相关标识符 (`user_stop`,`shutdown`，或`timeout`)。 停止的持久监视器是`canceled`，其原因不是第四个终端状态：状态机保持最小，动机生活在场上.从发射工具调用中返回是成功的脱离，而不是取消。 `stop_reason`

## 司令部工作

面向LLM的形状是现有的相关标识符工具上的可选相关标识符字段.`Bash`仍然是参数验证，风险分类，许可，沙盒包装和环境清洗的唯一权威；背景处理不得构建第二个更弱的道.许可门在脱离之前同步运行；一旦允许，工具返回身份和初始状态，而不是输出命令。 `run_in_background`

进程适配器必须在不阻孩子的情况下捕获stdout和stderr，在线索背后保留有限的近期输出，区分出口代码，时间限，停止请求和产卵失败，终止**进程树**，运行在已批准的呼叫的沙盒和清除环境下，并在管理器关闭时停止所有所有儿童。

过程树终止是新的工作，而不是重复使用：今天`exec.CommandContext`只向直接的孩子发出信号，因此在其产生的服务器存活期间杀死`bash`是当前的行为.Unix过程组和Windows等等同需要明确的测试；一个停止让孙子运行是一个失败的停止，即使登记器说[Problem](#问题)。 `canceled`

首个版本通过管道而不是 PTY 运行子进程。许多开发服务器在输出目标不是 TTY 时会改用块缓冲，导致输出延迟甚至只在退出时出现；Monitor 示例使用 `--line-buffered` 也是同一原因。这是明确记录的限制，真实用例证明有需要时，已知修复方案是增加 PTY 适配器（Windows 上使用 ConPTY）。

## 位工作

现有`Task`工具上的相同选项字段.一个背景子集接收了一个新背景，并立即带来一个职位身份.现有回归限制 (在子集中没有`Task`) 保留。

批准不需要新的机制：子部件已经没有批准处理器运行，循环将`Ask`在零处理器下作为否定解决.背景子部件继承了正确的结果，即一个要求的操作被拒绝，用户可以在重新尝试前景之前检查.新的是仅仅框架：拒绝作为前景工具结果而不是工作结果。

背景子组分类是像现在的前景子组分类一样，分享工作空间.这是一种正确性风险，而不是细节：两个作者可以竞赛，而父母的视角可能会变得陈旧.第一版本**在工具输出和UI中声明共享工作空间的边界，并建议而不是需要隔离**；要求工作树隔离将使其在基础设施上提供无法进行大部分阅读的委托的功能.工作树隔离的作家将会使其成为一个保证；他们是[没有计划](#长久性不是计划的)。

## 监督工作

监视器是一个专业的命令工作，而不是第二个调度器.它的命令预计将保持沉默，直到值得交付的东西发生；每个站点线都变成一个有限的`monitor_event`，过程出口成为正常的生命周期事件，而stderr是诊断工作输出，从来没有唤醒Agent.监视器通过相同的风险检查，许可政策，沙箱和环境规则，如`Bash`.一个`persistent`监视器意味着应用程序-会议寿命，而不是过去的出口过程生存。

在任何东西达到模型之前，应施加压力：每行字节盖子， UTF-8安全的缩小，每工作排队，事件率限制，当消费者落后时与落后事件总结合，并且在持久的追踪字节之前编辑.没有这些，繁忙的日志上的`tail -F`是文本耗尽工具。

** 发射时，每个显示器按反应政策决定.**默认情况下是`notify`：事件到达UI和会议收件箱，但不调用模型.发射时Agent可能声明`react`，在这种情况下，随队的事件会根据下列序列化规则唤醒所有者会议.隐藏的自动模型调用是成本和副作用，因此它永远不是默认；一个永远不会引起推理的显示器仍然是有用的作为手表。

## 活动的举报和唤醒

交付是层次的，首先拉.工作列表/获取/输出工具是整个阶段 1交付的结果。 模型在关心时会读取结果。 它们永久保持在反弹和调试道。 下面的收件箱唤醒是阶段 3 增长，从来没有取代。

### 类型来源，而不是排列用户输入

采用`RunLoopOpts.PendingInput`的方法，它是用户自主输入的：它运行`UserPromptSubmit`，添加用户消息，并发出`EventUserInput`。 工作事件不得通过它。

```text
user_prompt | command_result | subagent_result | monitor_event
```

模型提供商没有可移植的历史中期事件角色，因此一个事件可以在线上作为用户角色信息表示，但持续的消息和跟踪记录带有输入的非用户来源，包裹将有效载荷作为不值得信赖的观察而不是指示，**紧缩必须保留来源**，或者一个紧缩将监视线转换为用户所说的东西。

### 一个会议编辑，强制执行

工作事件永远不能同时与同一会话进行轮回.今天，这种保证只是一个表面公约:`Session.Append`和会话管理员没有锁定，并且序列化存在，因为每个表面允许一次运行.一个工作管理员乘以生产者，所以第一版本添加了一个 **会话轮回协调员**，使单笔记者规则成为拒绝或排队的呼叫而不是数据比赛。

1. 记录事件，并立即通知用户界面。
2. 如果一个顶级运行是活跃的，排队或合并事件。
3. 支持时，在有效的代界限提供排列事件，或
启动新内部转向，在活动运行结束后。
4. 如果此次会议是空的，可选择立即开始一个内部转换。
5. 通过现有会议管理器路径将结果历史保存。

### 完成时，模型会醒来。

每个生命周期事件都达到UI； 并非每一个事件都唤醒模型。 **完成只会在启动调用请求结果交付时唤醒所有者会话.** 显示器根据其声明的模式唤醒。 进步输出只会更新活动UI。 关闭期间停止的工作会记录并显示在下一个过程中视图上，而没有任何唤醒。

## 产量，保留和痕迹

工作输出不属于对话历史.每个工作保持一个有限的近期输出环，基于线索的增量读数.环仅是内存，并且没有任何工作输出存活的过程.这是[已结算，未定](#长久性不是计划的)。

发行电话回报后，父母运行跟踪不能保持开放，因此背景工作通过拥有会议ID，父母跟踪ID，父母工具调用ID和工作 ID 和类型来连接自己的工作事件流.它记录最小启动，边界，停止请求，出口，错误，输出缩小，丢弃的监视事件和任何引起的唤醒。 位工作保持其现有的儿童运行跟踪.跟踪故障保持失败开放，输出被限制和编辑，在持久之前，根据[耐用痕迹设计](持久化运行轨迹.md)。

工具调用链接是先决条件，而不是现有的接：目前的子管痕迹具有母号**运行**ID，但发射工具调用ID既不达到追踪运行环境，也没有达到工具的`Execute`。

## 生命周期和限制

管理者拥有独立于任何启动调用的根语境.它不会在请求语境中使用`context.WithoutCancel` ，它将任意值拖入，掩盖身份；启动复制明确来源到管理者拥有的语境中。

关闭是有限的：停止接受工作，要求在任何地方取消，等待短暂的宽限期，终止剩余的工艺树，记录哪些工作没有清洁地退出.经理强制执行保守的限制最大的同时指挥工作，副职位和监控，并开始有界限的队列明确拒绝而不是默默超过它们，直到种族和资源证据支持更大的默认。

## 长久性不是计划的

在此，第四个阶段被称为耐用性跟踪：输出卷和工作转录，如果工作必须存活 UI 退出，一个地方监督员,Desktop系统通知，工作树隔离的编写者，并根据相同的收件箱和工作模型进行排序。

子是看起来独立有用的部分，在论点上，持久输出和元数据在崩盘后是否有监督者随之而来帮助.他们不反对这种设计.`Manager.Close`取消了每一个运行的工作，并等待宽限期，因此退出过程是*工作结束，而子只会让某人读取不再存在的工作的输出.大部分后尸体已经存在:`<traces>/jobs/<id>.jsonl`记录了每个工作的开始，边界，退出代码，停止原因，以及监视器的线条.一个东西是命令工作的体，如果想要，比例的答案是相关标识符 `job_end`

剩下的阶段都在监督者身上，监督者则在要求下站着，没有人展示过。 过程存活的执行是它自己的产品和安全界限。 从[根据轴的替代方案](#根据轴的替代方案)的推迟本地-大emon拓，并将其承担为用户界面退出，升级和崩的职位。 持久的工作元数据也促进了工作进入实体，这带来了[实体身份.md](实体身份.md)中的规则；今天的`jb_`标识符是从一个工作中确实存在一个过程。

根据[扩张前的证据](#扩张前的证据)的最后一项：人们实际上在工作中做前景工作，而不是使用活动视图作为第二个终端.这种证据是证明监督者，监督者是将给卷轴提供它被论述的目的.命令不会逆转一个首先建造的卷轴是没有附加的存储能力。
