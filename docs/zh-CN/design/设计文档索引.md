# 设计记录

> **翻译说明：** 本文是[英文原文](../../design/README.md)的简体中文派生翻译。若中英文存在语义冲突，以英文原文为准。

> **受众：** 贡献者 · **状态：** 当前

本文说明 BuildMax 为什么会长成现在这个样子。这些文档是**设计理由，而不是用户文档**——当某项设计发布了可配置的能力时，面向用户的那一半会放在[手册](../../../manual)或 [../reference/](../../reference/) 中，设计记录本身只保留权衡取舍和尚未解决的问题。

文档采用稳定的语义化文件名。索引给出的是它们的生命周期和阅读顺序；文件名本身不编码时间顺序或路线图优先级。

## 新增一份设计记录

1. 选一个简短的语义化文件名，例如 `execution-policy.md`。
2. 写清楚问题、考虑过的方案、最终选择的做法、当前状态和实施阶段。
3. 把它加入到上面恰好一个分类表格中。
4. 如果它发布了用户需要配置的能力，请把面向用户的部分写在 `guide/` 或 `reference/` 中，并从表格中链接过去。

当一份记录不再描述当前方向时，**删除它**并移除对应的表格行。Git 历史会保留它；参见 [contribute/documentation.md](../contribute/documentation.md)。
