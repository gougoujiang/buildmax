BuildMax 是这样构建的理由。这些是**原理，而不是用户文档**——当一个设计发布了可配置的某些东西时，面向用户的部分存在于 [../manual/](../../../manual/) 或 [../reference/](../../reference/) 中，而设计记录则保留了权衡和开放的差距。

文档使用稳定、语义化的文件名。索引提供了它们的生命周期和阅读顺序；文件名不编码时间顺序或路线图优先级。

## 添加一个

1. 选择一个简短的语义文件名，例如 `execution-policy.md`。
2. 说明问题、考虑的选项、选择的方法、状态和阶段。
3. 将其添加到上述恰好一个部分。
4. 如果它发布了用户配置的某些内容，请在 `guide/` 或 `reference/` 中编写面向用户的部分，并从表格中链接到它。

当它停止描述当前方向时，**删除它**并移除其行。Git 历史会保留它；请参阅 [contribute/documentation.md](../../contribute/documentation.md)。
