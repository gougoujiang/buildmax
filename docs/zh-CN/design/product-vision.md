## 产品承诺

采用一个共享的Go Agent核心的BuildMax是一个可用于私人部署的企业Agent平台。

同样的运行时间服务于三个操作配置：

- 通过CLI/TUI和Desktop进行直接本地执行；
- 通过服务器和Portal进行空间协作和治理；以及
- 通过WorkerTaskRuns进行持久的背景执行。

服务器是可选的，用于本地使用.连接本地客户端将身份，管理模型,Space工作和发布添加到私人部署中；它不会将本地执行转化为仅远程产品。

## 产品模型

### 一个Agent核心，多个界面

重要的是,Agent功能首先属于共享运行时间.CLI,Desktop,Portal对话，员工可以以不同的方式展示和授权该功能，但他们不得发展单独的工具调用循环或不兼容的执行语义。

详细部门由[界面定位](surface-positioning.md)拥有：

- CLI/TUI是最快的地方Agent界面；
- Desktop是本地个人Agent工作台；
- 企业运营层是Portal；以及
- Worker在没有直接与用户交谈的情况下执行持久的背景运行。

### 拥有共同资源的Space

Space是Portal资源的所有权和授权界限.角色，配额，工作流程，问题，对话，任务，Artifact，插件，审计和使用都被解释在该界限内.部署范围内的管理是单独的赠款，并不意味着访问另一个Space的内容。

Issue是面向用户的主要工作对象.它声明了工作，将其讨论和执行联系起来，并且使得结果很容易找到，而不需要用户了解计划器内部。

### 预先的互动和持续的执行保持着不同

Conversation是一个独立的前景聊天和可选的管弦仪.它可以直接回答或创建一个支持Agent的相应标识符，当工作需要持久的执行时.它不是该Task的强制家长。

Task 加上 TaskRun 是持久的执行平面。可以通过它直接调用 Agent，并且 Task 在后续的 TaskRuns 中保留了 Agent 的会话。Conversation、Issue、Workflow、API 请求或 Webhook 可能是来源，但 Space 仍然是所有者，并且没有来源成为执行或授权的父级。完整的边界和延续模型在 [代理执行和任务线程.md](agent-execution-and-task-threads.md) 中。

### 结果是优秀的

用户要求结果，而不是内部任务图.因此,BuildMax处理结果总结,Artifact，以及来源作为产品对象而不是日志碎片.Task，运行，步骤，跟踪和模型调用页面是结果背后的解释和钻探界面。

Artifacts是明确的持久出版物。 Worker输出目录或本地文件不仅仅是因为它存在而成为Artifact；一个授权生产商故意发布文件。

## Runtime 原则

### 地方和管理方式是诚实的

局部客户端要么调用本地配置的提供商，要么登录后，调用其BuildMax部署提供的模型.这两种模式不会将目录或凭证合并.直动本地模式仍然是没有服务器的有用；管理模式将提供商凭证保留在服务器侧。

### 相信人有什么限制

工具权限，子，沙盒，痕迹，工作人员凭证和插件针必须描述实际应用的边界.记录下降的评级比未运行的暗示沙盒好，但安全敏感的政策仍然可能会选择不关闭。 BuildMax不得声称封锁，退出限制，批准或恢复行为它不执行。

每次运行都会默认地产生有限的，编辑的痕迹证据。

### 耐用性是目标，不是魔法

每个持久的对象都会命名自己的持久和恢复合同：

- 局部会议使用原子束和链接的历史；
- TaskRuns及其结果交付是服务器记录；
- Artifacts 具有稳定的身份和明确的保留行为；并且
- 审计和模特调用记录解释共享运营。

BuildMax没有通用版本的工作空间服务，隐藏的Git状态引擎，活动时间线恢复，或承诺每一个文件更改都是可逆的。 会议反转只改变对话历史记录；它不会撤销工具或恢复工作空间文件。

[工作场所检查站 Task](task-workspace-checkpoints.md) 是执行平面上的被接受的狭窄例外：一个计划中的 TaskRun 可以恢复一个不可变的 `workspace/` 检查点并发布下一个，这样 Task 的延续就不会将缺失的文件与被记住的 Agent 历史配对。那是执行恢复，而不是用户可见的工作区历史。变更集、任意回滚、跨设备重建以及将 Task 状态应用于共享的 Space 文件仍然需要单独接受的设计、所有权模型和路线图优先级。

### 配置和执行仍然可携带

Go核心和CLI/TUI仍然可以作为单个二进制器，而没有节点.Portal和Desktop可能使用其React前端，但运行时间必须适合支持的平台和模型提供商的本地和私人部署。

## 现有概念

| 概念 | 产品作用 | 管理局 |
|---|---|---|
| 地方工作空间 | 读取和更改本地Agent目录 | 局部用户和操作系统 |
| 地方会议 | 可与一个本地Agent的重复相互作用 | 地方会议包 |
| Desktop Project | 工作空间周围的本地UI状态 | 仅为Desktop；不属于服务器实体 |
| Space | 拥有权和授权的边界 | 服务器 |
| Issue | 主要共享工作对象 | Space |
| Workflow | 可重复使用的持久执行计划；目前是线性的，针对的是修改嵌的适应图 | Space |
| Conversation | 独立的前景聊天和可选的管弦乐器 | Space |
| Task / TaskRun | 耐用Agent线程及其执行转或尝试 | Space和时间表 |
| Artifact | 显而易见的持久产量，具有稳定的身份 | Space |
| 插件环境 | 增强Space/Agent激活式加上Task扩展式自动增长式；扩展的运行目录是预测 | 在TaskRun上记录的不可变包装和环境修改 |

## 新产品投注的指南

开放的提案是选择，而不是该愿景已经承诺的延长。

- 接收和返回来自当地客户的Issue工作；
- 协调选定的本地会议检查站；
- 会议树和结构化儿童报告；
- 企业身份整合；
- 客户会议和机器认证的边界；以及
- 经过测试的秘密交付和工作负载身份。

接受意味着更新路线图，将持久的理由转换为设计记录，并删除提案。

## 决策测试

拟议的功能适用于BuildMax，如果它不削弱共享运行时间或Space边界，并且可以清楚解释其权威，耐用性，故障行为和证据，则至少加强一个运行配置。

偏好那些使Agent的结果更容易获得、值得信赖和重复使用的更改。拒绝那些创建了仅限于Portal的Agent的捷径，让本地客户端成为第二个管理界面，让Conversation成为强制的执行父级，让后台运行的进程冒充用户的消息，或将未实现的恢复或安全边界作为产品行为。
