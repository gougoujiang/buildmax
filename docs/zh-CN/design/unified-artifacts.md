## 1. 决策

一个Artifact是一级BuildMax对象，而不是任务运行的副产品.系统提供了一个Artifact功能，任何生成文件的用户都应该保留一个代理，一个背景运行，一个直接上传使用该功能.一个想要保存其输出的任务运行就像其他生产者一样称其输出服务.因此，一个运行保持其可复制的输出目录，而它生成的文件可以在不知道其任务或运行身份的情况下找到，引用和共享。

这就是将模型与迁移 `artifact`/`artifact_item`表区分开的.这些是任务运行的子结构：没有运行，没有Artifact，唯一的方法是命名的运行.这里描述的对象拥有其身份和寿命，并记录其生产者作为来源而不是作为父母。 `0001_artifact_tables_to_task_run_artifact`

Artifact的身份是其不透明的公众身份证.该身份证是服务所返回的信息，工具所报告的信息，用户所引用的信息.URL是某个表面的身份证，而不是身份证本身。

它们生活在一个Space名字空间中，这是现有的授权界限；一个单独工作的用户由自己的个人Space表示，不需要在UI中看到Space概念.CLI和Desktop通过登录到BuildMax服务器来访问Artifact.该产品为私人部署案例而构建.一个针对提供商模型的本地会议，没有服务器，根本没有任何功能，并且没有Artifact工具显示在其Artifact列表中。 Artifacts

共享的Agent运行时间只会在该功能存在的情况下暴露`UploadArtifact`工具.它接受一个明确命名的本地文件，通过Artifact服务流传输，记录一个Artifact，并返回Artifact的ID和定位URL。

物体存储仍然是一个实现细节.一个BuildMaxArtifactURL不是一个桶键，也不是一个物体存储预签的URL。

## 2.产品目标

代理，用户或背景运行应能够使一个有用的文件可用于空间，并给收件人一个持久的引用.收件人应能够：

- 在有空间访问时预览或下载；
- 连接到问题，对话或结果，而不复制存储密钥；
- 保存该参考文献或信息并使其继续解决；以及
- 随着外部访问，故意创建可撤销的外部共享链接
需要空间。

产品语言是**artifact**，而不是桶，对象，结果目录或工人输出路径。

## 5. 域名模式

### 5.1 Artifact

采用Artifact模型，每件Artifact均具有一个不可变的内容对象.因为Space是授权名字空间，因此需要`SpaceID`，包括一个单独在个人Space工作的用户：

```go
type Artifact struct {
	ID              uint   `json:"-"`
	ArtifactID      string `json:"artifact_id"`
	SpaceID          string `json:"space_id"`
	Filename        string `json:"filename"`
	MediaType       string `json:"media_type"`
	SizeBytes       int64  `json:"size_bytes"`
	SHA256          string `json:"sha256"`
	StorageKey      string `json:"-"`
	CreatedByType   string `json:"created_by_type"`
	CreatedByID     string `json:"created_by_id"`
	SourceType      string `json:"source_type"`
	SourceID        string `json:"source_id,omitempty"`
	Title           string `json:"title,omitempty"`
	DeletedAt       *int64 `json:"deleted_at,omitempty"`
	ExpiresAt       *int64 `json:"expires_at,omitempty"`
	CreatedAt       int64  `json:"created_at"`
}
```

有一个Artifact商店.一个登录的CLI或Desktop会通过Space使用的相同服务创建相同的Artifact名字空间.表面只在表现结果方面不同.如果只添加本地商店，它必须从一开始发出公开身份证，以便参考工具返回每个表面的意思。 Portal

`StorageKey`是私有的，由存储适配器生成的.没有API，工具输出，跟踪或UI暴露它.`SHA256`是在播放上传时计算的，证明了存储的内容；它不是跨空间减倍密钥。

首发源类型是：

| 源类型 | 来源身份 | 意思 |
|---|---|---|
| `agent` | 提供时，代理运行或会议身份证 | 一个代理人呼唤了`UploadArtifact`。 |
| `task_run` | 任务运行身份 | 工人把文件作为运行输出。 |
| `user_upload` | 选择性请求/审计相关性ID | 一个成员直接上传了一个文件。 |
| `system` | 选择性操作身份证 | 没有代理的电话,BuildMax生成了文件。 |

采用`created_by_type`来区分用户，代理，工人或系统参与者；它不发明用于自动化工作的用户ID。 这遵循现有审计模型的参与者规则。

一个Artifact不包含一个自由形式的元数据 JSON列.上面的字段是故意可查询和限制的.只需要产品行为时添加一个具体的字段；任意的JSON是内容，提示和凭证的容易泄漏到持久的元数据的地方。

### 5.2 工作链接

编程中,Artifact可以与任务运行，问题，对话或结果卡连接.在第一片中,`source_type`和`source_id`捕捉到生产操作，并将相关任务/问题/对话从该来源中提取.一个单独的多到多的附件表被推迟到一个Artifact必须附加到独立的工作对象。

运行是生成文件的操作，并且是区分一个尝试与另一个尝试的原因；任务，问题和对话都可从中获得.读者走向另一边 问题问其工作产生了什么 必须收集每个任务的每次运行，而不是每个任务的最后一个，或者一次重试任务隐藏了其之前的尝试发表的内容。 `source_id`

这样就避免将上传的文件依赖于执行任务，仅仅因为第一位生产者是工人。

### 5.3 Task-Run输出不是Artifacts

`task_run_artifact(task_run_id, relative_path)`保持了其输出目录中的运行指数，而没有什么会自动成为 Artifact。

这反转了本节的早期草案，每个上传的文件都在终端运行处理上创建了一个Artifact.两件事是错误的.复制是真实的：兼容路径读取运行输出键空间，因此在Artifact键空间中存储每次输出。 收获是第一个节 11拒绝的代理的输出目录是`.env`文件，缓存和中间工作最终最终的位置，扫描是不是安全的服务器完成。

运行的输出目录是运行所产生的可复制记录；Artifact是某人应该保存的文件.一个代理通过选择一次，使用`UploadArtifact`将第一转换为第二个。

没有什么改变一个旧的任务运行路径成为一个ArtifactID，旧输出不会被反填充.任务运行路径保留其当前的响应。

## 6. 访问和URL

### 6.1 身份和路线

经典引用是Artifact的公开手柄.它本身是独一无二的  96 位的加密随机数据 所以找到Artifact不需要别的东西。 Space是记录的授权事实，不是地址的一部分。

由于分断，有两个路线形状：

```text
GET /api/artifacts/{artifact_id}          # detail
GET /api/artifacts/{artifact_id}/content  # content
GET /api/spaces/{space_id}/artifacts        # the space's listing
```

通过ID地址的路线，可以解决该Artifact，读取其`SpaceID`，并要求调用者成为该空间的成员.这是一个新的授权路径.它不能重复使用`access.Guard.UserAndPathSpace`，它从请求路径中取出空间，因此需要自己的防护方法和空间授权矩阵测试中的自己的输入。

没有成员国的通话者得到`404`，从来没有得到`403`.不透明的`artifact_id`是标识符，而不是凭证，没有任何响应可以将其转化为存在的口语，这就是第13节的不编号标准实际上所指的。

空间路线是列表和空间视图表面。 这不是一个Artifact的第二个地址。

Portal除了API路线外，还提供了一个面向人类的详细路线:`#/artifact/{artifact_id}`，通过相同的ID地址Artifact解决相同的Artifact，因此在相同的授权下.由于本节所提供的原因，它在地址中没有空间，并报告拒绝在相关标识符的404许可证没有找到的单词中，不管它是否存在.列表是生成的相关标识符，而不是相关标识符 `#/artifacts`

### 6.2 外部股票链接

外部共享是一个独立的功能，而不是在常规URL上的旗.创建链接生成一个高性，不可猜测的共享代币和URL，如：

```text
/shared/artifacts/{share_token}
```

股票链接标识一个Artifact，至少包含：

- 创造者和创造时间；
- 任择到期，具有限制性部署默认；
- 取消时间；
- 对于审计和未来限制的可选下载数量。

MVP政策是**仅获得身份验证的空间访问**.现在在[艺术品-公众分享和预览.md](./artifact-public-sharing-and-preview.md)中指定和重新开放了公共共享：可撤销的存储的股票代币，匿名的`/api/shared/...`路线和服务器转换的公共链接.该记录回答了授权矩阵，撤销模型和本段留下的审计事件.不要将永久的S3预署的URL作为快捷径实现：它们绕过BuildMax授权，不能中央撤销，并将保存的链接进行对象商店配置。

### 6.3 内容提供

所有内容请求都在获取对象之前授权或验证共享代币.服务器可以自动流媒体内容或授权后转向短暂的对象存储URL.后者是优化，而不是公共合同。

内容标题使用存储的，服务器验证的元数据；永远不要单独信任上传的文件名或被调用者提供的MIME类型.下载使用安全的内容配置和文件名.在线预览是允许列表，而不是浏览器猜测：平文，通过现有的净化器进行印，安全的图像/PDF类型可以故意添加.HTML,SVG，可执行内容和未知的类型可以作为附件下载在第一片中。

## 7. Agent 工具合同

### 7.1 可用性

`UploadArtifact`是一个共享运行时间工具，在 `internal/agentapp` 和其他默认工具一起组装.它只注册在表面有一个认证的Artifact服务：服务器部署的自己的运行时间，或一个 CLI或 Desktop 登录到一个 BuildMax 服务器。 `internal/interface/auth`已经回答了本地表面的这个问题。 `IsLoggedIn` `CanAuthenticate(serverURL)`

在没有这样的服务的情况下，工具在工具列表中**缺席**.它并非在每个通话都失败的状态下注册.只存在于"不可用"的工具只需要回车，并不会教模型任何东西，而没有的工具则是模型可以立即采取行动的事实。

工具从来没有通过返回源文件路径来模拟。 一台机器上的路径不是可共享的对象，而没有服务器的会议则保留其正常的本地输出行为。

### 7.2 召唤

代理提供：

| 论证 | 要求 | 规则 |
|---|---|---|
| `path` | 没有 | 在有效工作空间或允许运行时间输出目录中可读的常规文件。 |
| `title` | 没有 | 简短的用户面向标签；文件名仍然是内容名称。 |
| `purpose` | 没有 | 结果卡的限制性可读的注释，而不是任意的文件元数据。 |

工具必须拒绝目录，设备文件，逃离允许的根，超过活动配额的文件和无法安全打开的路径的符号链接.它将文件流，仅在存储成功后创建Artifact，并返回Artifact ID，文件名，大小和法规URL.存储故障返回一个有意义的工具错误，并没有成功的Artifact记录。

工具不会自动上传代理写的每一个文件.模型必须选择它打算呈现的最终文件.这使得输出可以理解，避免意外发布`.env`文件或缓存，并保持存储成本有限。

### 7.3 促成和结果

运行时间提示告诉代理人使用`UploadArtifact`来传递，保留或共享文件，并在最后的答案中引用返回的Artifact参考.一个Artifact结果卡应该包括标题，文件名，生成运行或代理，创建时间，预览/下载操作和正规链接。

面向LLM的名称是`internal/tool/names.go`的后续名称；当实现添加常数时,`docs/guide/tools.md`成为其参数和可用性的面向用户的真相来源。

## 8. 授权，治理，限制

Artifacts是空间资源。 Space会员是基线阅读界限，用户的个人 Space是私人单用户案例.一个Artifact从来没有从单独运行URL中获得授权.详细的矩阵是实施的一部分，但拟议的第一片政策是：

| 行动 | 成员 | 管理员 | 业主 | 空间外 |
|---|---:|---:|---:|---:|
| 阅读/下载空间Artifact | 没有 | 没有 | 没有 | 没有 |
| 通过授权代理/用户流程上传 | 没有 | 没有 | 没有 | 没有 |
| 删除自己的直接Artifact | 没有 | 没有 | 没有 | 没有 |
| 删除任何太空Artifact | 没有 | 没有 | 没有 | 没有 |
| 创建/撤销外部分享链接 | 起初没有 | 未来 | 未来 | 没有 |

删除是一个墓石：它立即隐藏了元数据，阻止了内容访问，记录了一个审计事件，然后在保留政策下安排了物理对象的删除.它不会重写任务运行历史.一个运行页面可以说其以前的输出已经被删除，而没有泄漏存储密钥。

`ArtifactRetainer` 在 `internal/server/scheduler` 中是保留政策，也是除了上传回放路外的Artifact内容的唯一东西.它每小时在两个阶段扫描：过期墓石Artifact，其 `ExpiresAt`，然后清除恢复了在 `storage.artifact_purge_after_days`之前被埋藏的Artifact.该 grace 默认的 **0** 删除已经在授权边界发生，因此保留字节后的影响和暴露而不是安全性.设定日为一个使用工具提供无删除的使用费用； 相关标识符提供无删除。 BuildMax

Artifact的`StorageKey`是记录其字节是否仍然保留.每一个Artifact在创建时都得到一个字节，因此一个墓石行上的空键意味着对象已经消失了.扫描清除了添加一个`purged_at`列："没有键"和"没有存储"是相同的事实，最后必须同意的两个列将有一天不会。

倒置将允许在之间出现崩，声称字节已经消失，而桶仍然为它们收费；这样，崩会导致一个行说对象存在，下一次扫描将删除已经缺失的内容。

服务在接受文件之前执行每文件大小和空间存储配额，并计算最后存储的字节.每文件的限额为`storage.max_artifact_mb`；空间允许是配额级的`max_storage_bytes`，通过`artifact.StorageAdmitter`查看第12问题2 查看为什么它是一个难以录取的类别.允许的MIME检查和病毒扫描集成操作员政策决定;Artifact服务暴露了所需的决策点，但不会在它们存在之前发明配置领域。

审计这些仅仅有元数据的操作：创建的Artifact，删除的Artifact，过期的Artifact，修复的Artifact，创建的分享和撤销的分享。 过期记录每件Artifact，因为它是没有成员要求的一个墓石，一个寻找为什么文件走的读者必须找到它的名字。 扫除记录每次扫描，一个数和字节总数，因为授权的墓石已经在轨道上，这只说字节已经消失了.审计记录不应包含文件内容，签署的URL，分享代币，或未经限制和审查的用户提供的描述。

## 9. 存储和失败的语义

存储密钥是私有的，由适配器生成，并与任何URL无关.服务器部署的代表形状是`spaces/{space_id}/artifacts/{artifact_id}/content`，它使对象所有权清晰，同时让桶布局在适配器背后演变.它与API路线的相似性是命名巧合而不是合约：在适配器之外的任何东西都不能分析，构建或依赖于密钥。

现有任务运行输出由创建用户而不是空间键.`objectstore.RunOutputFileKey`生成`<prefix>/<created_by>/artifacts/<conversation>/<task>/<run>/<path>`.新运行通过Artifact服务写入其关键空间而不是那个.此设计之前写的对象保留了旧键，只通过兼容路径才能访问，并且不会被复制。

接口`internal/infra/objectstore`被称为`ArtifactStorage` 已经在运行输出存储。 采用`RunRef`和`RunObjectRef`的方法，现在是`RunOutputStorage`，与`cfg.RunOutputs`和`db/run_output.go`相匹配.共享一个名称的两个接口将是后来更改安静地反转这个设计存在的依赖命名方向的最简单的方式。

产品产品的合同后来转向了消费者，称为`internal/service/artifact.ContentStore`，并以`internal/core/artifact`为参考类型。 该节目的方向与此相反，该节目的方向相同：服务表示需要的内容，而不是该服务必须采用的接口的存储包，而是一个适配器满足了这一需求。

接下来写一次：

1. 授权和验证源流；
2. 保留ArtifactID和生成的存储密钥；
3. 在测量尺寸时，向临时或最终物体流；
4. 只有对象是持久的后才能承诺不可变的Artifact元数据；
5. 由于不良的操作，可使用机去除未经承担的物体
存储和数据库工作之间。

没有内容更新终点.一个更改的文件创建了一个新的Artifact，如果产品要求版本谱系，则可能后来与其前身链接。

存储界面仍然可移植，在服务器的本地文件系统后端和S3/MinIO上.这是一个选择，即部署的对象存储存储存储所在地；它没有说任何关于CLI或Desktop会话是否本地，该节目7.1根据自己的条款来解决.服务器侧行为，而不是存储提供商URL行为，定义了产品合同。
