## 1. 这段记录决定了什么

工作空间根变成了会议状态而不是构建状态，一个代理可以创建一个Git工作树，将会议移动到它中，在那里工作，离开，并清理，而用户没有手动做任何事情。

根是每个工具的会议状态，一个`Worktree`工具创建，输入，离开，列表并删除它们，根决定的配置遵循一个动作，三个节事件宣布发生了什么，并可以给代表一个自己的工作树。 这一记录存在，因此实现不必重新推出根的依赖者与它一起移动，哪些不，因为这个问题，而不是工作树命令，是这个功能很容易得不错的地方。

## 2. 为什么

### 2.1 会议中就决定

开始一个工作树中的会议已经工作:`buildmax --workspace ../repo-refactor`给文件工具,Bash，子，技能，以及`/diff`作为他们的目录根，没有什么缺失。

需要这个记录答案是相反的情况，它是常见的：几次转向对话，限制和变化的形状确定后，就会清楚的工作应该在单独的树上进行.在新会议中重新开始恢复工作树，并失去使它必要的文本.要求用户运行Git命令，打开终端，并重新启动代理恢复了两者，并耗费了代理应该删除的中断。

### 2.2 今天它是什么阻碍的

| 阻塞器 | 在哪里 |
|---|---|
| 根是固定的，当运行时间组装，没有什么改变它之后 | 子代理 `internal/agentapp/app.go` `--workspace` `internal/interface/cli/root.go` |
| 阅读，写，编辑,Glob和Grep拒绝任何路径 | 通过`ResolvePath`在`internal/util/workspace.go`中进行`internal/tool/base.go` |
| 每次Bash电话前景和背景工作从根开始，所以`cd`永远不会生存 | `internal/tool/bash.go` |
| 没有界面可转换;TUI没有命令 | `internal/interface/cli/chat.go` |
| 子和背景工作都通过建设分享父母的根源 | `internal/tool/task.go`， `internal/agentapp/job` |
| 沙盒将工作空间绑定，只有工作空间，可编写 | `internal/infra/sandbox/manager.go` |

由于Bash 已被编写为 `git`,Bash 已经在 `internal/tool/safety.go` 中进行了操作,Bash 已经可以创建一个工作树，并将其作为一个外国目录地址：每一个用 `cd` 或 `git -C` 重新编写的命令，每一次通过 `cat` 阅读而不是阅读，每一次通过 `grep` 搜索而不是 Grep.一个忘记预写的模型一旦写到错误的树，系统中没有任何通知.这种失败模式是导致这种功能而不是提示命令。

## 3. 范围

** 在范围.** 一个会议，一个根一次，根据用户的指示或代理人的主动移动：创建，输入，工作，离开，删除.每个工具都遵循当前的根，没有新的语法.用户总是可以看到该会议的根是什么。

**不适用.** 曲会话或分支其背景，即[会议树提案](../../proposals/session-tree-and-agent-mailbox.md)，它将工作树作为一个先决条件，可以建立在此记录上。 还包括：在一个监督下进行多次同时会议，自动合并或重新基础一个工作树的变更，在Portal或工作树的路径 (该提案的第9.2条排除这一情况)，以及已取消的非Git工作空间的版本快照，其设计记录已被撤销，并未在待审。

给一个子树或背景工作，它自己的工作树在范围内，从来没有强制性的见D7.它回答了与本记录的其他部分不同的请求，将工作委托给另一个树，而不是在一个树上工作，但它重复使用相同的机制:`Task`取一个可选的`worktree`名称，树被创建并保持不移动父母的根，并且该代理类型的工具被重建对抗它。

## 5. 决策

### 工作树在`<repo>/.buildmax/worktrees/<name>`现场

已注册在`.git/info/exclude`而不是存储库的`.gitignore`.`.buildmax/`是使用它的存储库中被跟踪的目录。 `README.md` `agents/` `mcp.json` `skills/` Git

拒绝:`<BUILDMAX_HOME>`中部位置，可轻松在中心清理，但使树远离存储库，无法被用户编辑到达；以及一个兄弟的`../<repo>-<name>`，它不需要忽视，但污染了母目录，并发生了存储库之间的冲突。

### D2。 按开关重新读取`AGENTS.md`提示层

切换根变化层3，只有两个诚实的选择：重新阅读并无效预写，或者结并接受加载的指示描述与写入的不同目录。

会议的时间表是为期数不多的，因此成本是有限的，并且在使用统计中可见；冷层故障不会产生错误，并且会轻松产生错误的变化.其他三个层运行时提示,`<BUILDMAX_HOME>/AGENTS.md`，并且运行的额外系统提示不会改变，并且压缩总结是通过`RunLoop`添加到层后，因此不受影响。

### D3。 根只能移到当前存储库的工作树

现在，拒绝离开根源是安全性属性，而移动根将固定边界变成移动的；这种限制使得可达到的根集合保持闭合和数不清，而不是"任何目录模型名称".在根内，路径的含量是不变的。 `git worktree list` `ResolvePath`

一个会话可以进入一个没有创建的工作树，但只有没有现场会议在它.一个空置的树被一个早期的会话留下，或创建于这个一个简历可能被输入之前.一个树另一个现场会议目前持有，因为它的根被拒绝，拒绝的名称持有者。

拒绝是很少的：第二个会议可以创建自己的工作树，这是一个工具调用.禁止直接进入会花费更多恢复的会议无法回到自己的工作，一个废弃的分支永远无法再接收。

占用量是D10定义的.这里没有什么会引发哪个会议创建了工作树：在这个记录中没有任何决定需要，所以没有什么记录它。

### D4。 允许创建和输入；删除请求

按照[工具权限](tool-permissions.md)，层次是故意不对称的：

| 行动 | 级别 |
|---|---|
| 创建一个工作树，输入它 | 让我们 |
| 删除一个工作树 | 问问 |
| 删除包含未承诺的变更或未合并的承诺的工作树 | 拒绝，除非用户明确表示要丢弃它们 |

在新分支上创建空目录并不破坏性，也不应该打断用户的自主性是该功能的重点.删除可能包含唯一副本的树是一个不同的风险，它保持其提示。

### 工作树永远不会自动移除

如果在工作树内，该会议结束时，用户被要求保留或删除它，默认的位置是保存.这是代理的自主权可以破坏用户的工作的地方，所以默认的位置是非破坏性的。

同样的答案涵盖了一个被毁的会议遗留的工作树：没有收获器，没有基于年龄的扫描，并在下一次发射时没有清理.一个死去的过程不是树上的工作完成的证据，这正是树唯一的副本.清理是用户的，而且BuildMax欠他们的价格是可见性而不是自动化。

### 报告出了污染的开端树，未解决

工作树是从当前的`HEAD`创建的，而未提交的文件则被明确列出.沉默是不可接受的：对话可能描述了新树无法看到的代码。

工作树不是由自动存储库组成的.一个存储库的工作树共享一个存储库，因此自动存储库对该存储库中的每一个工作会议都构成危险.拒绝创建工作树也被拒绝了：常见的情况是一个干净或无关紧要的脏树，拒绝将迫使用户完全走向手动Git偏向。

### D7。 代表继承当前根，除非模型给他们自己的根

由于工作中已经开始的转换，已经开始使用了当前的根.已经运行的人保留了他们启动的根，并且在输出中表示，工作已经记录了工作空间.拒绝在运行时转换会在测试运行期间阻止转换，这是最需要的时间；默默地修复运行过程不是一个选择。

代表可以得到自己的工作树.这是在提供，从来没有被强加的：没有什么强迫每一个工作树，每一个代表决定隔离是否值得.一个树中的两个作家是一个真正的危险。 [地方背景工作](local-background-jobs.md)

### 8 相应标识符 和 TUI 得到全部功能； Desktop 仅显示根 CLI

命令是D5的可见性面向用户的一面：它列出每个工作树，哪个会议将其保留，以及它将其保留什么，它允许用户从同一视图中删除一个.从看到树后唯一的行动是没有其他收获.删除执行D4：当前树和另一个会议被拒绝，一个清洁树在确认时被删除，并且一个有工作的树只在确认后被删除，该问题将会被丢弃.这是用户的清洁，而不是D5拒绝的解释.相应标识符 `/worktree` `Project` TUI Desktop Project

### D9.模型名称工作树及其分支

模型的名称是从作品中，模型的创建时中得出的.一个固定的方案会产生`worktree-1`,`worktree-2`，该方案告诉用户列出什么树，并不是明确的覆盖。

碰撞是通过失败来处理的，而不是通过沉默的后音：创建一个已经存在的名称或分支的工作树会返回一个工具结果，该结果表示哪个是碰撞的，模型选择另一个.一个沉默的`-2`后音将使一个原本要返回现有树的模型创建第二个。

### D10。 占用是工作树的 Git管理目录中的一个建议锁

链接的工作树的`.git`是一个指向`<repo>/.git/worktrees/<name>/`的文件，其中Git保存了该工作树的 `HEAD`,`index`和相应标识符.该目录是占用量标记的正确所在地：它位于工作树之外，因此从未出现在用户的相应标识符，以及相应标识符和相应标识符 `locked` `git status` `git worktree remove` `git worktree prune` `CLAUDE_BASE`

标记是一个由会议过程保持开放的辅导文件锁，只要它在树里，而不是记录的过程ID.操作系统在进程出门时释放它，包括崩，因此"空"不需要停滞的论，也不需要对PID重复使用的防御.这使得D3的拒绝安全执行,D5的"用户声称它"更是真实的，而不是一个被一个死于会议永远锁定的树.标记 *包含*  会议ID，开始时间  存在以命名持有人在拒绝消息，而不是决定寿命。

没有`git worktree lock`：这是防剪，设计上持久，与哪个工艺在哪里工作无关.重复使用将会混两个含义，使树木被锁定，在每个人都离开后很长时间。

费用是每操作系统代码的 `flock`与`LockFileEx` 相比,`internal/infra/sandbox`已经为同样的原因承担。

## 6. 用户所看到的

草图，而不是文本的规范：

```text
user  > 这个重构不小，开个 worktree 并行做

agent > Created .buildmax/worktrees/refactor-tool-roots on branch
        worktree/refactor-tool-roots, from HEAD (a1b2c3d).
        Two uncommitted files stayed behind in the original tree:
        internal/tool/bash.go, docs/ROADMAP.md.
        This session is now working in the worktree.

        … ordinary work: Read, Edit, Grep, Bash, /diff all in the new tree …

user  > 提交了，回主目录吧

agent > Left the worktree; it and its branch are kept at
        .buildmax/worktrees/refactor-tool-roots.
```

## 8. 按阶段交付

** 阶段 1 根成为会话状态。 实现.** `util.Workspace`是合同， `agentapp.MovableRoot`是状态，文件工具,Bash， `Monitor`， `Task`，沙盒的可写结， TUI脚本，和 `/diff`都每次电话读取。 相应标识符服务于每一个移动的界面和测试。 没有工作树能力，而 相应标识符的行为都无法完全恢复，所以它在现有的阶段上运输之前，它完全无法恢复。 `util.FixedRoot` `--workspace`

**阶段2 工作树生命周期。 实施.** `internal/agentapp/worktree`拥有它， `internal/infra/git` Git 机械，和 `internal/infra/flock` 占用锁。 `Worktree` 工具和 TUI 的 相应标识符 面板是两个界面。 D3 的封闭， D4 的检查层， D5 的拒绝自行删除任何东西， D6 的脏报告， D9 的命名，和 D10 的锁都在生效。 `/worktree`

**阶段3 衍生配置。 实现.** 移动根和重新解决它决定的东西是一个操作，在`sessionRoot.Set`：任何移动根的东西都会让会话运行一个树的和技能与另一个树的文件，从外面看来没有什么看起来错误.Hooks重组，技能和子定义重组解决，缓存工具注册表下降，并调整MCP。 `AGENTS.md`

阶段2发布了一个版本之前的阶段3，这仅仅是因为同一仓库的工作树通常具有相同的工作空间配置，所以过时的快照通常是相同的快照.该参数不存活放松的D3，而且不再需要：阶段3已经降落。

**4 阶段  其他界面。 实施.** `WorktreeCreate`， `WorktreeRemove`，和 `CwdChanged`从生命周期中火，所有建议：工具调用已经通过`PreToolUse`，所以第二门只能留下一个工作树半创建，一个失败的子永远不会撤销发生的移动。 Desktop没有代码。 [导航/工具.md](../../guide/tools.md) [导航/子.md](../../guide/hooks.md)

**第5阶段 代表工作树。 实施.** `Task`取了一个可选的`worktree`名称。 树被创建并保持其占用锁，只要代表运行，前景或背景，而父母的根不会移动：委托到树中不是转换到树上。 委托的工具是重建的，因为父母的实例保持父母的根，交给这些将打败孤立。 答案命名树，这在这里比其他任何地方都重要  没有什么会把它移除，所以代表的变化会在父母从未学习的地方。
